# SC40 AI 网关开关与空安全

## 1. 场景背景与目的

`EnableAiGateway` 开关自 2026-07-01 引入：开启时 BFE 走 `ServeHTTPForAI`（AI 路由、鉴权、计费、AI 日志），关闭时走普通反向代理。2026-07-17 修复了「关闭 AI 网关但产品为 AI」时 `mod_ai_token_auth` 的空指针 panic（`74f2841c`）。

已有场景全部以 `EnableAiGateway=true` 启动，关闭态没有任何回归网。本场景验证：

- 关闭态下 AI 形态请求按普通反向代理转发：不鉴权、不计费、不写 AI 日志字段，后端收到原始 Host 与 body；
- 关闭态下已加载的 AI 模块（`mod_ai_route`、`mod_ai_token_auth`、`mod_body_process`、`mod_access_pb3`）全部空安全跳过，不 panic；
- 开启态基线：无 Key 401 `NO_API_KEY`，有 Key 200 且日志含 `ai_mode`/`ai_target_model`；
- SSE 识别（`IsSse`）在开关之外：关闭态 SSE 请求仍按长连接处理并计入 `proxy_state` 指标。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程；
- AI 后端为进程内 `httptest` mock，Redis 为进程内 miniredis；
- 每个用例只启动一个 BFE，`EnableAiGateway` 在 `bfe.conf` 生成后、启动前改写。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | `EnableAiGateway` 按用例改写为 `true`/`false`；模块列表固定加载全部 AI 模块 |
| `mod_ai_route/ai_route.data` | `ak_auth` 命中 `cluster_auth` |
| `mod_ai_token_auth/token_rule.data` | 运行时生成：不限量 Token |
| `mod_body_process/body_process.data` | 默认规则 |
| `mod_access_pb3/mod_access_pb3.conf` | 请求级 pb 日志，用于 AI 字段存在性断言 |
| `cluster_conf/gslb.data` | `cluster_auth` 单子集群 |
| `cluster_conf/cluster_table.data` / `cluster_conf.data` | 运行时生成 |

## 4. 测试 Cluster 与配置

- `cluster_auth.AIConf`：单 provider key（`sk-sc40-1`）；
- mock 后端默认返回非流式 usage；TC-05 切换为 `SSEEvents` 模式返回 `text/event-stream`。
