# TC-08 原始凭证掩码兜底

## 目的

验证红线 bfenetworks/bfe#1357 覆盖新增白名单字段：白名单采集的头值中含原始 API Key 时，日志中该值被替换为 `key_id`；独立字段 49 `authorization` 仍恒空。白名单内容本身不做敏感头限制（`Authorization`/`Cookie` 可配、照采，由运行时兜底保证凭证不落地）。

## 前置条件

- `mod_access_pb.data`：`req_headers` 含 `x-echo` 与 `authorization`（刻意把敏感头配进白名单，验证数据面不限制但兜底生效）；
- 客户端 token：`ak_hdr_a`（原始 Key 记为 `RAWKEY-A`，内部 `key_id` 为 `kid-hdr-a`）。

## 请求构造

- 请求头：
  - `Authorization: RAWKEY-A`（同 token 值，模拟凭证外传形态）；
  - `X-Echo: prefix-RAWKEY-A-suffix`（白名单头值中嵌入原始 Key）；
- 发送请求 → 200。

## 执行步骤

1. 发送请求 → 200；
2. 解码 b2log 取 `RequestLog`；
3. 对整条 `RequestLog` 做序列化字节级扫描（沿用 SC05 公共断言），不得包含 `RAWKEY-A`。

## 预期结果

- 独立字段 `authorization`（49）缺席（#1357 恒空语义不变）；
- 白名单 `req_headers` 中：`X-Echo` 条目值为 `prefix-kid-hdr-a-suffix`（客户端原始 Key 被掩码替换为 key_id）；
- `Authorization` 条目的实际值记录为**上游 Provider Key**（AI 模式在转发前把请求头原地改写为上游凭证，到达日志阶段已是上游值）——该断言固化"数据面不限制白名单内容"的实际行为，凭证管控由上层配置管理承担；
- 字节级扫描全条日志（含所有字段、所有白名单条目）不含客户端原始 Key `ak_hdr_a`。

## 清理

测试结束时关闭 BFE 与 mock 后端。
