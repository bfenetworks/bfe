# TC-01 白名单采集与规范化键

## 目的

验证 `mod_access_pb.data` 白名单采集的基础行为：请求头/响应头按白名单写入 `req_headers`/`res_headers`，proto `key` 为 HTTP 规范化形式，多值头 `,` 拼接，未命中头不写条目。

## 前置条件

- BFE 已启动，`mod_access_pb3.conf` 配置 `DataConfPath`；
- `mod_access_pb.data`：

```json
{
    "Version": "20261115090000",
    "access_header": {
        "req_headers": ["business_type", "x-multi"],
        "res_headers": ["x-trace-id", "x-absent-resp"]
    }
}
```

- mock 后端为响应注入 `X-Trace-Id: trace-abc`。

## 请求构造

- 请求头：`Business-Type: rag`（注意传输键为规范化形式）、`X-Multi: v1` 与 `X-Multi: v2` 两个值（或单头多值）、`X-Not-Whitelisted: nope`；
- 客户端 token：`ak_hdr_a`。

## 执行步骤

1. 发送请求 → 200；
2. 收集并解码 b2log，取该请求的 `RequestLog`。

## 预期结果

- `req_headers` 恰含 2 条：
  - `{key: "Business_type", value: "rag"}`——`business_type` 配置名归一为 `Business_type`（下划线后不大写）；
  - `{key: "X-Multi", value: "v1,v2"}`——多值 `,` 拼接；
- `X-Not-Whitelisted` 不出现；
- `res_headers` 恰含 1 条 `{key: "X-Trace-Id", value: "trace-abc"}`；`x-absent-resp` 后端未返回，不出现；
- 其余字段（状态码、耗时、AI 字段）不受影响。

## 清理

测试结束时关闭 BFE 与 mock 后端。
