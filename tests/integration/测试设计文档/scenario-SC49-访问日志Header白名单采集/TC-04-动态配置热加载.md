# TC-04 动态配置热加载

## 目的

验证 `mod_access_pb.data` 经 `/reload/mod_access_pb3` 热加载即时生效：修改白名单后无需重启 BFE，新头开始采集、被移除的头停止采集。

## 前置条件

- 初始 `mod_access_pb.data`：

```json
{
    "Version": "20261115090000",
    "access_header": {
        "req_headers": ["business_type"],
        "res_headers": []
    }
}
```

## 请求构造

- 请求头同时携带 `Business-Type: rag` 与 `X-Request-Id: rid-1`；
- 客户端 token：`ak_hdr_a`。

## 执行步骤

1. 发送请求 → 200 → 解码断言：仅 `req_headers` 含 `Business_type`；
2. 改写 `mod_access_pb.data`（`Version` 更新为 `20261115100000`）：`req_headers` 改为 `["x-request-id"]`，`res_headers` 加 `["x-trace-id"]`；
3. 请求 BFE monitor 端口 `GET /reload/mod_access_pb3` → 返回成功；
4. mock 后端保持注入 `X-Trace-Id`，再次发送相同请求 → 200 → 解码断言。

## 预期结果

- 步骤 3 reload 接口返回成功（200，无 error）；
- 步骤 4：`req_headers` 仅含 `{key: "X-Request-Id", value: "rid-1"}`（`Business-Type` 不再采集）；`res_headers` 含 `{key: "X-Trace-Id", ...}`；
- 全程不重启 BFE；启动时的旧版本请求日志不受热加载影响（已落盘）。

## 清理

测试结束时关闭 BFE 与 mock 后端。
