# TC-02 大小写不敏感配置

## 目的

验证头名称匹配不区分大小写：白名单中的名称在加载时归一为 HTTP 规范化形式，传输键任意大小写均可命中。

## 前置条件

- 同 TC-01，但 `access_header.req_headers` 配置为混合/纯小写形态，例如：

```json
{
    "Version": "20261115090000",
    "access_header": {
        "req_headers": ["business_type", "X-request-ID"],
        "res_headers": ["X-TRACE-id"]
    }
}
```

## 请求构造

- 请求头以非规范形式传输：`BUSINESS_TYPE: rag`、`x-ReQuEsT-iD: rid-1`；
- mock 后端注入响应头 `x-trace-ID: trace-xyz`。

## 执行步骤

1. 发送请求 → 200；
2. 解码 b2log 取 `RequestLog`。

## 预期结果

- `req_headers` 含 `{key: "Business_type", value: "rag"}` 与 `{key: "X-Request-Id", value: "rid-1"}`；
- `res_headers` 含 `{key: "X-Trace-Id", value: "trace-xyz"}`；
- 所有 `key` 均为规范化形式，与 TC-01 一致（下游 Doris 聚合键稳定）。

## 清理

测试结束时关闭 BFE 与 mock 后端。
