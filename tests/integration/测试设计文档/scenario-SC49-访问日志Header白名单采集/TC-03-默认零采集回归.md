# TC-03 默认零采集回归

## 目的

验证默认行为与旧版完全一致（存量部署零配置升级）：不配数据文件、或段缺失、或空白名单时，均不采集任何头，`req_headers`/`res_headers` 字段缺席（proto 不序列化），日志体积零增长。

## 前置条件

三个对照组（可三个子用例或顺序重置环境）：

- 组 A：`mod_access_pb3.conf` **不设** `DataConfPath`（验证可选性）；
- 组 B：设 `DataConfPath` 但**不创建**数据文件（Init 缺失容忍路径）；
- 组 C：数据文件存在但 `access_header` 段缺失，及 `req_headers`/`res_headers` 均为 `[]` 的形态。

## 请求构造

- 请求带任意头（如 `Business-Type: rag`）；
- 客户端 token：`ak_hdr_a`。

## 执行步骤

1. 每组：启动 BFE → 发送请求 → 200 → 解码 b2log 取 `RequestLog`；
2. 组 B 额外断言：BFE 启动日志含 data conf 缺失 Warn，启动未失败。

## 预期结果

- 三组：`req_headers` 与 `res_headers` 均为空/缺席，行为逐字节等价旧版（其余字段正常）；
- 组 A：无任何与数据文件相关的 Warn（未启用即不打扰）；
- 组 B：启动成功 + 单次 Warn；
- 组 C：启动成功，按空白名单运行。

## 清理

测试结束时关闭 BFE 与 mock 后端。
