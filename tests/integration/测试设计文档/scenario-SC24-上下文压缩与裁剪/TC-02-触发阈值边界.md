# TC-02 触发阈值边界

## 用例编号与名称

TC-02 触发阈值边界

## 所属场景

SC24 上下文压缩与裁剪

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_context`）

## 测试目的

验证主动触发阈值 `budget × triggerRatio`（= 150 × 0.8 = **120 token**）的上下边界：估算值恰好低于阈值的请求零改写透传，恰好高于阈值的请求触发管线。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程。

## 前置条件

同 TC-01。测试代码使用模块自带的 `HeuristicEstimator` 计算请求体估算值，按 4 字节步长填充至目标值，保证估算与 bfe 内部完全一致。

## 配置构造

同 TC-01（触发线 120）。

## BFE 请求

| 步骤 | Host | Path | Authorization | Body 要点 |
|------|------|------|---------------|-----------|
| 1 | `ctx.example.org` | `/v1/chat/completions` | `Bearer ak_ctx` | system + 单 user，估算值恰好 **119**（< 120） |
| 2 | 同上 | 同上 | 同上 | user + assistant `tool_calls` + tool 结果，估算值恰好 **121**（> 120） |

## 预期结果

- 步骤 1：
  - 返回 200，无 `x-ai-context-compression` 响应头；
  - mock 后端收到的 body 与客户端发送**逐字节一致**（未重序列化、未改写）；
  - 访问日志 `ai_context_compress_status=skip_under_threshold`，且不带 mode/tokens 字段。
- 步骤 2：
  - 返回 200，带 `x-ai-context-compression` 响应头；
  - mock 后端收到的 body 中 tool 结果被截断并带 `...[truncated]` 标记；
  - 访问日志 `ai_context_compress_status=trim`。
