# SC24 上下文压缩与裁剪

## 1. 场景背景与目的

`mod_ai_context` 在请求转发上游前，对 OpenAI 协议 `messages` 做减量处理：按目标模型上下文窗口做 token 预算预检，超阈值主动触发，避免 `prompt too long` / `context_length_exceeded`。一期能力：

- **无损裁剪层**：L1 工具结果截断（`toolResultMaxChars` + `...[truncated]` 标记）、L1.5 旧内联图片裁剪（只留最近 N 张）、L2 旧 thinking 块删除（只留最后一条 assistant）；
- **规则改写层（P2）**：tombstone 保护（代码块/行内代码/URL/路径/版本号/JSON key/数字字面量）→ lite/full 冗余改写 → 还原 → fidelity gate（保护 token 存活率 ≥ `protectedSurvivalRate`，不过则回退裁剪产物）；
- **结构保真（repair）**：tool_call/tool 配对修复、多趟孤儿清理；修复后仍非法则整体回滚原始 body（fail-open）；
- **可观测**：响应头 `x-ai-context-compression`、访问日志 793-796 字段（`ai_context_compress_status` / `ai_context_tokens_before` / `ai_context_tokens_after` / `ai_context_compress_mode`）、模块计数器。

本场景验证（设计文档 `2026-10-01-ai-context-compress/design-changes.md` §13.2）：

- 超预算请求被压缩后转发：messages 已裁剪/改写、结构合法、转发不截断、响应头标注、访问日志 4 字段正确；
- 触发阈值边界：估算值恰好低于/高于 `budget × triggerRatio` 的两个请求分别走零改写与管线；
- fallback 重试幂等：同一请求两个 cluster attempt 只压缩一次，重试重放压缩后的 body；
- 与 `mod_ai_cache` 共存：压缩不触碰最后一条 user 消息，exact cache key 不变；缓存命中路径零压缩；
- fail-open：畸形 body 透传原始字节，日志状态 `skip_parse_err` / `repair_rollback`。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程；TC04 额外启动内存 Redis 服务（`mod_ai_cache` 依赖）。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 4. 测试 Cluster 与压缩配置

### 4.1 压缩规则确定性触发

- 规则：`maxContextTokens=200`、`reserveTokens=50` ⇒ **budget = 150**；`triggerRatio=0.8` ⇒ **触发线 = 120 token**（`budget × triggerRatio`）。
- 估算公式：启发式 `len(json)/charsPerToken`（`charsPerToken=4`，向上取整），与 `mod_ai_context` 内部估算器一致；测试代码直接调用模块的 `HeuristicEstimator` 计算期望值，实现恰好等于/低于边界的请求体。
- `toolResultMaxChars=32` ⇒ L1 截断后 tool 结果为 32 字符 + `...[truncated]`（15 字符）。
- `thinkingPolicy=trim-all-but-last` ⇒ 非最后一条 assistant 的 `reasoning_content` 被 L2 删除。
- `rewrite.strength=lite`、`protectedSurvivalRate=0.95` ⇒ P2 冗余改写（含中文规则），tombstone 保护 URL/代码等结构化片段。

### 4.2 mock 后端

- `cluster_ctx_primary`：默认 200 + 非流式答案；TC03 改为 503 触发集群 fallback。
- `cluster_ctx_fallback`：200 + 答案。
- `cluster_cache`：200 + 答案（TC04）。

### 4.3 请求体构造

- **裁剪体**（TC01/TC03/TC04）：system + 早期 user/assistant（含 480 字节 `reasoning_content`）+ assistant `tool_calls` + 2000 字符 tool 结果 + 最后 user 问题。估算 ≈ 600+ token，远超触发线。
- **改写体**（TC01 第二阶段）：assistant  filler 由 15 段冗余短语组成（其中一段含 URL `https://bfe.example.com/v1.2/spec`），裁剪层无能为力，只有 P2 能减量；断言 URL 原样存活、改写标记 `[COMPRESSED:rewrite]` 恰好出现一次。
