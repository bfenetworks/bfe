# TC-06 档位语义差异

## 用例编号与名称

TC-06 档位语义差异（conservative / balanced / aggressive）

## 所属场景

SC24 上下文压缩与裁剪

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_context`）

## 测试目的

验证三档模式行为差异：conservative 只做无损裁剪（L1/L1.5/L2），balanced 追加 lite 强度规则改写（P2），aggressive 以 full 强度运行 P2。三种模式使用同一份超预算 body（L1 后估算仍超预算，是否改写完全由档位决定），核心断言是 **conservative 无 `[COMPRESSED:rewrite]` 标记而 balanced/aggressive 有**。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程。

## 前置条件

1. 同 TC-01。
2. 测试以独立 `context_rule.data` 启动（`Config` 三个 product 各一条规则，分别 `mode=conservative/balanced/aggressive`，均 `maxContextTokens=200, reserveTokens=50`）。

## 规则区分维度

**多 host → 多 product**：`host_rule.data` 增加 `ctx-cons.example.org` / `ctx-bal.example.org` / `ctx-agg.example.org` 三个 host，分别映射 `ai_product_cons` / `ai_product_bal` / `ai_product_agg`；`route_rule.data` 为三个 product 补 BasicRule（均指向 `cluster_ctx_primary`）。请求按 Host 头路由到不同 product，`mod_ai_context` 的 `Search(product)` 命中对应档位规则。路由仍走 `ak_ctx` 的 apikey 路由表（host 不影响 AI 路由）。

## 配置构造

- Defaults：`toolResultMaxChars=32`、`rewrite.strength=lite`、`protectedSurvivalRate=0.95`（aggressive 档下 P2 以 full 规则包执行）。
- body（`modeBody`）：system + assistant `tool_calls` + 2000 字符 tool 结果 + assistant filler（14 段 `Please note that the system is stable. `）+ 最后 user。
- 测试内以 `simulateToolTrim` 计算 L1 后估算并断言 > 150（budget），保证裁剪层不足以达标，P2 是否运行由档位决定。

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `ctx-cons.example.org` | `/v1/chat/completions` | `Bearer ak_ctx` | modeBody |
| 2 | `ctx-bal.example.org` | 同上 | 同上 | 同上 |
| 3 | `ctx-agg.example.org` | 同上 | 同上 | 同上 |

## 预期结果

- 三步骤均 200，响应头 `x-ai-context-compression` **精确值**断言（`tokens=<before>-><after>; mode=<档位>`，before/after 为测试内估算期望值）。
- 三步骤后端 body 均含 `...[truncated]`（L1 痕迹）。
- conservative：无 `[COMPRESSED:rewrite]` 标记；balanced / aggressive：有标记。
- 三步骤后端 messages 的 tool_call/tool 配对合法。
- 访问日志 3 条：conservative `status=trim`；balanced/aggressive `status=rewrite`；均 `before > after`、`mode` 与档位一致。

> 说明：当前 lite 与 full 规则包对 `modeBody` 的 filler 产物差异极小（full 的额外规则未命中该文本），故 aggressive 档以"改写成功 + trim/rewrite 两层痕迹俱在 + mode 字段正确"作为断言；full/lite 规则差异以模块单测 `TestRewriteFullStrength` 为准。
