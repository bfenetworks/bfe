# TC-01 触发压缩与改写验证

## 用例编号与名称

TC-01 触发压缩与改写验证

## 所属场景

SC24 上下文压缩与裁剪

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_context`）

## 测试目的

验证超预算请求的 OpenAI messages 被压缩后转发：无损裁剪层（L1 工具结果截断、L2 thinking 删除）与 P2 规则改写（含 tombstone 保护）两个出口都正确，转发不截断，响应头标注，访问日志 793-796 字段完整。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. mock 后端 `cluster_ctx_primary` 返回 200 与非流式答案。
3. 临时 BFE 配置已加载 `mod_ai_route`、`mod_ai_context`（规则 `balanced`，budget=150，触发线 120）、`mod_access_pb3`。
4. `ak_ctx` 路由命中 `cluster_ctx_primary`。

## 配置构造

- 压缩规则：`{"cond":"default_t()","mode":"balanced","maxContextTokens":200,"reserveTokens":50}`；Defaults：`toolResultMaxChars=32`、`thinkingPolicy=trim-all-but-last`、`rewrite.strength=lite`。

## BFE 请求

| 步骤 | Host | Path | Authorization | Body 要点 |
|------|------|------|---------------|-----------|
| 1 | `ctx.example.org` | `/v1/chat/completions` | `Bearer ak_ctx` | 裁剪体：system、早期 assistant（含 480B `reasoning_content`）、`tool_calls`、2000 字符 tool 结果、最后 user `current question` |
| 2 | 同上 | 同上 | 同上 | 改写体：assistant filler 为 15 段 `Please note that ...` 冗余短语（其中一段含 `https://bfe.example.com/v1.2/spec`） |

## 预期结果

- 两个请求均返回 200，响应头 `x-ai-context-compression: tokens=<before>-><after>; mode=balanced`。
- 裁剪体在 mock 后端处：
  - tool 结果变为 32 字符 + `...[truncated]`，原 2000 字符内容不复存在；
  - 早期 assistant 的 `reasoning_content` 被删除，`content` 原样保留；
  - `tool_calls` 与 tool 消息成对保留（结构合法）；
  - system 与最后一条 user 消息（`current question`）逐字节不动；
  - 请求体为合法 JSON（转发未截断）；若声明了 `Content-Length` 则与实收字节数一致。
- 改写体在 mock 后端处：
  - `Please note that` 冗余短语全部被 lite 规则改写；
  - URL `https://bfe.example.com/v1.2/spec` 原样存活（tombstone 保护）；
  - `[COMPRESSED:rewrite]` 标记恰好出现一次；
  - system 与最后 user 不动。
- 访问日志各一条记录：步骤 1 `ai_context_compress_status=trim`、步骤 2 `=rewrite`；均带 `ai_context_tokens_before > ai_context_tokens_after > 0` 与 `ai_context_compress_mode=balanced`。
