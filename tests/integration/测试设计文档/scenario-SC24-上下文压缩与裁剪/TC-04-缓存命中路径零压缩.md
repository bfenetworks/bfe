# TC-04 缓存命中路径零压缩

## 用例编号与名称

TC-04 缓存命中路径零压缩

## 所属场景

SC24 上下文压缩与裁剪

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_context` 与 `mod_ai_cache`）

## 测试目的

验证压缩与 `mod_ai_cache` 精确缓存共存无冲突：

- 压缩不触碰最后一条 user 消息 ⇒ exact cache key（取自最后 user 问题）在压缩前后不变，被压缩的请求仍可按原 key 命中缓存；
- 缓存命中在 `HandleAfterLocation` 短路，命中路径完全不经过 `HandleAfterAITargetModel`，零压缩。

## 运行模式

单组件模式：真实 `bfe` 进程 + 内存 Redis（`mod_ai_cache` 依赖）。

## 前置条件

1. 同 TC-01，另追加 `Modules = mod_ai_cache`（Init 顺序由 moduleList 固定，cache 在 context 之前）。
2. 内存 Redis 已启动；`mod_ai_cache` 规则 `lastQuestion` / TTL 3600。
3. `ak_cache` 路由命中 `cluster_cache`。

## 配置构造

- 压缩规则同 TC-01；缓存规则 `{"cond":"default_t()","cacheKeyStrategy":"lastQuestion","cacheTTL":3600}`。

## BFE 请求

| 步骤 | Host | Path | Authorization | Body 要点 |
|------|------|------|---------------|-----------|
| 1 | `ctx.example.org` | `/v1/chat/completions` | `Bearer ak_cache` | assistant `tool_calls` + 2000 字符 tool 结果 + 最后 user `what is bfe?` |
| 2 | 同上 | 同上 | 同上 | 与步骤 1 逐字节相同 |

## 预期结果

- 步骤 1（miss）：
  - 返回 200，带 `x-ai-context-compression` 响应头；
  - `cluster_cache` 被命中 1 次，收到的 body 已压缩（tool 结果带截断标记）；
  - Redis 出现 `ai_cache:unknown:<sha>` 缓存键（最后 user 问题未被压缩改动，key 稳定）。
- 步骤 2（hit）：
  - 返回 200，响应头 `X-Bfe-Ai-Cache: hit`，**无** `x-ai-context-compression`；
  - `cluster_cache` 命中数仍为 1（不调用上游）。
- 访问日志 2 条：
  - 步骤 1：`ai_cache_status=miss`、`ai_context_compress_status=trim`、`before > after`、`mode=balanced`；
  - 步骤 2：`ai_cache_status=hit`，**无**任何 793-796 压缩字段（status 为空、tokens/mode 字段缺席）——命中路径零压缩。
