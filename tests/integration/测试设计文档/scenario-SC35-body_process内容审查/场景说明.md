# SC35 body_process 流式处理与内容审查

## 1. 场景背景与目的

`mod_body_process` 于 2025-08-24 随 AI 网关底座引入（`c369350b`），提供流式 body 处理框架：decoder（line/json/sse/按 Content-Type 自适应）→ processors（当前为 `textfilter` 内容审查）→ encoder。请求侧的 `textfilter` 是 **filter** 语义（命中 `REJECT`/`REVIEW` 时中止请求），响应侧是 **replace** 语义（用 `ResultText` 改写事件）。此前的集成测试只间接触发其 usage 解析，框架本身没有回归。

本场景验证：

- 请求体审查放行：转发内容语义不变、以 chunked 方式发送、审计服务收到完整文本；
- 请求体审查拒绝：返回 500、不返回上游响应、不重试；
- 响应体审查改写（`/text-replace` 的 `ResultText`）；
- SSE 逐事件审查：首帧在 backend 仍持有流时即可到达客户端（非整体缓冲）；
- line decoder：按行事件处理、字节保持；
- 审计服务不可达时 fail-open 放行（现状基线）；
- 非 AI 请求（`EnableAiGateway=false`）不处理 body；
- 模块监控指标；
- 规则条件匹配与 `/reload/mod_body_process` 热加载。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程；
- AI 后端为进程内 mock；审计服务为进程内 mock（`/text-filter` 与 `/text-replace`）；
- Redis 为进程内 miniredis（仅用于 token 规则加载）；
- 除 TC-07 外均 `EnableAiGateway=true`（框架只处理 AI 请求）。

## 4. 行为事实（实施记录）

- 请求体被处理后 `ContentLength=-1` 且删除 `Content-Length`，上游收到 `Transfer-Encoding: chunked`；
- 审计服务返回 `RiskLevel=REJECT`（或 `REVIEW` 且 `SentimentScore < -0.5`）时，请求以 500 `ErrBkBodyProcess` 结束并关闭连接；由于 body 是流式转发，上游连接可能已经建立（`hits` 最多 1），但不会拿到完整请求或返回上游响应，也不会重试；
- 审计服务不可达时 `Process` 内部 `continue`，请求照常转发（fail-open 现状基线）；
- SSE 事件的 `txt` 已包含 `data: ` 前缀，replace 结果回写后会再带一次前缀，断言应基于审计标记而不是 `data:` 计数。
