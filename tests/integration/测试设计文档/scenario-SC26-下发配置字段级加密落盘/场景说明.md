# SC26 下发配置字段级加密落盘（BFE 加载点解密）

## 1. 场景背景与目的

本场景验证「下发配置文件敏感字段加密落盘」在真实 BFE 进程中的行为：控制面导出的
`token_rule.data`（下游虚拟密钥，api-key 值为 Tokens 外层键）与 `cluster_conf.data`
（上游 provider 密钥，`AIConf.Keys[].Key`）中的密钥类敏感字段以 `enc$v1$` 前缀的
字段级密文落盘，BFE 加载时用 `bfe.conf` `[Security]` 段配置的 keyring 文件解密进
内存，磁盘/备份/误打包外泄无明文。

核心验证点：

1. 密文配置可正常加载：解密后内存结构与明文配置一致，下游鉴权、上游 key 注入
   行为不变；
2. 磁盘文件直读断言：敏感字段为 `enc$v1$` 密文且无密钥明文，非敏感字段（key_id、
   weight、模型映射等）保持可读（`cat` 排障能力保留）；
3. 失败语义：keyring 缺失/错误时加载失败、reload 失败旧配置保留、首启 fail-fast；
4. 热加载：更新 keyring 文件后触发既有 reload 端点即生效，无需重启（轮换路径）；
5. 兼容性：明文直通、明文/密文混合共存、无 keyring + 全明文正常启动。

对应设计文档：`bfe/docs/zh_cn/modifications/2026-10-05-export-config-field-encryption/design-changes.md`、
`bfe/docs/zh_cn/sys_design/config_file_field_encryption.md`。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，不涉及 `ai-gateway-api` 与 `conf-agent`；
  密文配置由测试代码按控制面同一信封规范（`enc$v1$<base64(keyID|nonce|AES-256-GCM)>`）
  现场加密生成，keyring 文件由测试代码生成（0600，置于临时工作目录）。
- 每个测试例拥有独立临时工作目录：复制 `testdata/` 模板后改写配置文件，再启动 BFE。
- `bfe.conf` 模板预置 `[Security]` 段（`#KeyFile` 注释行）；用例启动前由测试代码将其
  改写指向本用例生成的 keyring（`conf/keys/export.keys`，0600；生产形态的"conf 目录
  之外"由部署纪律保证，本场景只验证解密行为）；无 keyring 用例保持注释态。
- 下游鉴权通过真实 HTTP 请求验证（正确 key 放行 / 错误 key 401）；上游 key 注入通过
  mock 后端断言 `Authorization` 头为明文 provider key。
- 全部用例不依赖 Redis（token 均 `unlimited_quota`，不配置 RMB 计费所需的 Redis 配额）。

## 6. 公共基础设施

- **加密 helper**：测试内实现 enc$v1$ 信封加密（AES-256-GCM，keyID 1B + nonce 12B，
  与控制面 `lib/xcrypto` 同格式），输入明文+keyID+key 输出 `enc$v1$...` 字符串。
- **keyring 生成 helper**：输入 map[keyID]key 输出 TOML keyring 文件（0600）。
- **harness 增量**：`common.ProcessEnv.StartBFERaw`（错误返回版启动，供 fail-fast 断言，
  `StartBFE` 仍为主动失败包装，既有场景零影响）；`[Security]` 段改写为测试代码内的
  `setSecurityKeyFile`；用例在 BFE 运行期改写配置文件后调用 `/reload/<mod>`（既有能力）。
- **磁盘断言 helper**：直读工作目录下 `token_rule.data` / `cluster_conf.data`，
  断言指定字段为 `enc$v1$` 前缀、文件中不含给定明文密钥；同时断言非敏感字段值可读。
- **reload 断言**：解析 monitor 端口返回 JSON `{"error": ...}`。
