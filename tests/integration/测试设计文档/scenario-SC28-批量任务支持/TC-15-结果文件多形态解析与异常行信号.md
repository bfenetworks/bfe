# TC-15-结果文件多形态解析与异常行信号

## 目的

验证下载拦截的结果文件解析在三种行形态下都按契约工作，且异常行**可观测**而不再静默：

1. `response.body.usage`（OpenAI Batch 真实契约，issue #254 的复现形态）——必须计费；
2. `response.usage`（扁平旧形态，历史夹具与非标准上游）——仍必须计费（向后兼容）；
3. 错误行 / 无 usage 行 / 非法 JSON 行——不计费，且分别计入不同计数器。

覆盖的缺陷（修复前实测）：`handleLine` 只按扁平 `response.usage` 解析，真实契约行全部落空 → `usageParsed` 永不为真 → 不发布结算契约、`SETTLE_USAGE_PARSE` 恒为 0、`SETTLE_USAGE_PARSE_ERR` 声明的计数器从未有 `Inc` 调用（解析失败也无信号）。

## 前置条件

见 `../场景说明.md` §2/§3。本用例特有：结果文件由 `resultJSONLMixed` 提供，四类行各一条：

```jsonl
{"custom_id":"body","response":{"status_code":200,"body":{"model":"gpt-4o","usage":{"prompt_tokens":10,"completion_tokens":5,"total_tokens":15}}},"error":null}
{"custom_id":"flat","response":{"model":"gpt-4o","usage":{"prompt_tokens":3,"completion_tokens":2,"total_tokens":5}},"error":null}
{"custom_id":"no-usage","response":{"status_code":200,"body":{"model":"gpt-4o"}},"error":null}
{"custom_id":"error-row","response":null,"error":{"message":"upstream failed"}}
not-a-json-line
```

## 请求构造

与 TC-14 相同（上传 → 创建 → 查询 → 下载），仅把 mock provider 的下载响应替换为 `resultJSONLMixed`（`mockBatchProvider.resultOverride`）。

## 后端响应

下载：`200` + 上述五行 jsonl（**逐字节**返回，用于透传断言）。

## 执行步骤

1. 启动 BFE（余额充足，含 `gpt-4o` 批量价）。
2. 上传 → 创建 → 查询。
3. 下载输出文件，断言响应体与 `resultJSONLMixed` 逐字节一致（拦截不改变字节）。
4. `waitForRedis` 等结算落库，读 `BATCH_TASK:batch-1` 与计数器。

## 预期结果

**A. 计费口径（只统计可计费的两行）**

| 字段 | 期望 |
|------|------|
| `usage_in` / `usage_out` | `13` / `7`（`body` 行 10/5 + `flat` 行 3/2） |
| `settle_units` | `2700`（与 TC-02/TC-14 同价同口径，证明两种形态等价计费） |
| `settle_status` | `settled` |
| `usage_source` | `download` |

**B. 异常行信号**

| 计数器 | 期望 | 语义 |
|--------|------|------|
| `SETTLE_USAGE_PARSE` | `1` | 本次下载完成解析（按下载计次，不按行） |
| `SETTLE_NO_USAGE` | `1` | `no-usage` 行：有 `response` 对象但两处都取不到 usage |
| `SETTLE_USAGE_PARSE_ERR` | `1` | `not-a-json-line` 行：整行非法 JSON |
| `TASK_SETTLE_WRITE` | `1` | finish 阶段回写结算字段 |

注：`error-row`（`response:null` + `error` 非空）是**正常错误行**，既不进 `SETTLE_NO_USAGE` 也不进 `SETTLE_USAGE_PARSE_ERR`——错误行计数为 0 由 A 组 `usage_in/out` 精确值间接证明（若被计入，`13/7` 会失真）。

**C. 访问日志**：下载行 `ai_batch_settle=settle`（结算契约已发布）。

## 观测点

miniredis 哈希 `BATCH_TASK:batch-1`、`mod_ai_batch` 计数器（`SETTLE_USAGE_PARSE` / `SETTLE_NO_USAGE` / `SETTLE_USAGE_PARSE_ERR` / `TASK_SETTLE_WRITE`）、下载响应体字节一致性、访问日志。

## 清理

同 TC-14（`testEnv.Close()`）。

## 说明

- 本用例是 **TC-14 的补充而非替代**：TC-14 锁定"真实契约 + 全字段落库"，本用例锁定"解析口径兼容性与异常行可观测性"。二者共用 `runLifecycleToDownload` + `downloadResult`，不重复生命周期步骤。
- 若将来上游出现第三种 usage 位置（如 `response.body.choices[*]`），应新增用例而不是放宽本用例断言——计数器的精确值（1/1/1）就是"未识别形态不会被静默计费"的守门断言。
