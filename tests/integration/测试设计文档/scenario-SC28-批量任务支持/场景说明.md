# SC28 批量任务支持（mod_ai_batch）

## 1. 场景背景与目的

`mod_ai_batch` 为 OpenAI Batch API（`/v1/files`、`/v1/batches`）透传提供：端点识别（`ModeFile`/`ModeBatch`）、上传行/字节流式计数、批量上下文拦截、batch 级 key 亲和、配额"预留-结算-释放"后置计费、批量限流维度。本场景在真实 BFE 进程中端到端验证：

- 批量全生命周期（上传 → 创建 → 查询 → 下载）经网关走通，响应字节与 mock provider 完全一致（功能等价）；
- 访问日志批量字段（`ai_batch_id`/`ai_file_id`/`ai_batch_op`/`ai_file_lines`/`ai_file_bytes`/`ai_batch_status`/`ai_batch_settle`，pb 901-907）正确落盘；
- 批量计费：下载结果文件按行内 model 分组按 batch 价结算，RMB 配额扣减正确；预留镜像随结算/取消释放；
- batch 级粘性：上传/创建/查询/下载四步落到同一上游 key（双 key 集群下验证）；
- 批量限流：`batch_limits.max_file_bytes` 超限上传 413（`BATCH_FILE_TOO_LARGE`）；`max_create_rpm` 超限拒绝；
- 取消释放预留：cancel 被上游接受后预留释放，日志 `ai_batch_settle=release`；
- 余额预检：配额不足时创建被拒（`QUOTA_EXHAUSTED`），不发生转发。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程 + 嵌入式 miniredis（配额/限流/BATCH_* 状态/亲和共用）。
- provider 上游为测试框架的 mock 后端（`ResponseFunc` 按路径模拟 files/batches 各端点）。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | `EnableAiGateway`；加载 `mod_ai_token_auth`/`mod_ai_route`/`mod_body_process`/`mod_ai_rate_limit`/`mod_ai_batch`/`mod_access_pb3`；`[AIKeyAffinity] Disabled=false` + `ServiceConf=redis_bns`（batch 亲和依赖 server 侧 Redis） |
| `mod_ai_route/ai_route.data` | `ak_batch` 路由：`targets=[cluster_batch]`，无 fallback（批量不重试不降级） |
| `mod_ai_batch/mod_ai_batch.conf` | 模块基础配置；Redis Bns 由 builder 重写指向 miniredis |
| `mod_ai_batch/mod_ai_batch.data` | 全局硬顶 100MB/5 万行、预留估算默认值 |
| `mod_ai_rate_limit/mod_ai_rate_limit.conf` + `ai_rate_limit.data` | 后者由测试代码运行时生成（TC 按需配置 `batch_limits` 并绑定 `ak_batch`） |
| `mod_ai_token_auth/token_rule.data` | 由测试代码运行时生成（`ak_batch` + RMB/total_token 配额计划） |
| `mod_access_pb3/mod_access_pb3.conf` | protobuf 访问日志（`pb_access3.log`） |
| `server_data_conf/host_rule.data` | `batch.example.org` → `ai_product` |
| `cluster_conf/gslb.data` | 静态模板，仅 `cluster_batch`（sub_sub） |

观测手段：`common.ParseAccessLog` 断言 pb 字段；miniredis 直读配额/预留镜像键；mock 后端记录的上游请求头（粘性断言）。

## 4. 测试用例

| 编号 | 名称 | 一句话描述 |
|------|------|------------|
| TC-01 | 全生命周期走通与功能等价 | 上传（multipart jsonl）→ 创建 → 查询 → 下载四步响应字节与 provider 一致；日志批量字段（op/id/lines/bytes/status）正确 |
| TC-02 | 下载结算与计费正确 | RMB 计划 + chat/batch 双价；下载结果文件后余额扣减 = usage × batch 价；`BATCH_RESERVE` 镜像清零；日志 `ai_batch_settle=settle` |
| TC-03 | 四步操作同上游 key | 双 key 集群（`SessionAffinity=false` 排除客户端亲和干扰）：四步携带同一 provider key |
| TC-04a | 批量限流-文件上限 | `batch_limits.max_file_bytes=100`：上传 200 字节返回 413 `BATCH_FILE_TOO_LARGE`（limit_type=batch_file，响应含策略名） |
| TC-04b | 批量限流-创建速率 | `max_create_rpm=1`：第一次创建成功、第二次 429 且错误信息命中策略名 |
| TC-05 | 取消释放预留 | 创建（预留写入）→ cancel（上游接受）→ 预留镜像归零、`BATCH_SETTLED` 占位、日志 `ai_batch_settle=release`；余额未被结算扣减 |
| TC-06 | 余额预检拒绝 | 低余额 RMB 计划下创建被拒 `QUOTA_EXHAUSTED`，mock provider 零命中 |
| TC-07 | 归属校验拒绝 | 第二个 apikey 下载他人输出文件 → 404 `BATCH_FILE_FORBIDDEN`（不暴露存在性） |
| TC-08 | 归属 miss 放行 | 下载无绑定的 file_id → 200（`OwnerCheckMissPolicy=allow_log` 放行策略） |
| TC-09 | 失败终态释放预留 | get 返回 `expired` → 预留镜像清零、`BATCH_SETTLED` 占位、日志 `ai_batch_settle=release`（查询路径释放，区别于 cancel） |
| TC-10 | chunked 超限中断 | 无 Content-Length 上传超过 `max_file_lines` → 流传输中断（provider 收到截断 body） |
| TC-11 | 未配批量价 0 费 | ModelTable 无 batch 价行 → 下载结算计 0 费放行（`PriceLookupMiss`，不回退 chat 价），余额不变 |
| TC-12 | 低估预留照实结算 | `ReservePerLineMicros` 热加载调小 → 实结金额 > 预留，余额按实结扣减、镜像清零 |
| TC-13 | failover 404 摘除 | provider 对绑定 key 返回 404 → BFE 删绑定 + 60s 惩罚 → 下一查询确定性落到另一 key 并 200 |
