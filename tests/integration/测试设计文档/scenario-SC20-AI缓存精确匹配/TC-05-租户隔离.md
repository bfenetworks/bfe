# TC-05 租户隔离

## 用例编号与名称

TC-05 租户隔离

## 所属场景

SC20 AI 缓存精确匹配

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_cache`）

## 测试目的

验证缓存键强制带 API Key 的 `key_id` 前缀：不同租户（API Key）问同一问题互不走缓存，防止跨租户数据泄露。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. 嵌入式 Redis 已启动。
3. mock 后端 `cluster_cache` 已启动，返回 200 与非流式答案。
4. 临时 BFE 配置已生成并加载：
   - `mod_ai_cache` 规则（同 TC-01）；
   - token 规则包含两个 Key：`ak_cache`（`key_id=cache_key_id`）与 `ak_cache2`（`key_id=cache_key_id_2`），均绑定无限额计划；
   - `ai_route.data` 中两个 Key 分别绑定 `apikey_ak_cache` / `apikey_ak_cache2`，target 均为 `cluster_cache`。

## BFE 请求

| 步骤 | Authorization | Body |
|------|---------------|------|
| 1 | `Bearer ak_cache` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"what is bfe?"}]}` |
| 2 | `Bearer ak_cache2` | 同上 |
| 3 | `Bearer ak_cache` | 同上 |
| 4 | `Bearer ak_cache2` | 同上 |

## 预期结果

- 步骤 1：miss，上游命中 1 次；Redis 出现 `ai_cache:cache_key_id:*` 键。
- 步骤 2：同一问题但不同租户，**不得命中** Key 1 的缓存；无 `X-Bfe-Ai-Cache: hit` 头；上游命中 2 次。
- 步骤 3、4：两个 Key 各自命中自己的缓存项，上游命中保持 2 次；Redis 同时存在 `ai_cache:cache_key_id:*` 与 `ai_cache:cache_key_id_2:*` 两组键。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录。
