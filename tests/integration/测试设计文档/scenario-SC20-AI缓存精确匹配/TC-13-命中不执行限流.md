# TC-13 命中不执行限流

## 用例编号与名称

TC-13 命中不执行限流

## 所属场景

SC20 AI 缓存精确匹配

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_cache`、`mod_ai_rate_limit`）
- 条款依据：`docs/zh_cn/modifications/2026-10-20-issue-1433-cache-hit-policy-matrix/design-changes.md` §3.1 条款 **T-1433-1（命中不执行成本类策略）**

> **本用例是条款 T-1433-1 的负向回归，不是缺陷修复。** 缓存命中时不检查、不消耗 rpm/tpm/concurrency 额度是产品 owner 已确认的预期行为（命中不产生 provider 调用、不占上游容量、不计费），本用例只把这个事实钉住，不改变任何数据面行为。

## 测试目的

验证限流（`mod_ai_rate_limit.targetModelCheckHandler`，注册在 `HandleAfterAITargetModel`）在缓存命中路径上**不被求值**：

1. 某 Key 的 RPM 额度（`max_requests=1`）被第一条请求耗尽后，同一请求的**第二次发送命中缓存**，返回 `200` + `X-Bfe-Ai-Cache: hit`，**不出现 429**，也不消耗额度；
2. 对照请求（新问句 + `x-bfe-skip-ai-cache: on`，走未命中链路）返回 **429 `RPM_LIMIT_EXCEEDED`**，证明额度确实已耗尽、限流策略确实生效。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis（同时承载配额、限流计数与缓存）。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. 嵌入式 Redis（miniredis）已启动，供 `mod_ai_token_auth`、`mod_ai_rate_limit`、`mod_ai_cache` 共用。
3. mock 后端 `cluster_cache` 已启动，返回 200 与非流式答案（见"后端响应"）。
4. 临时 BFE 配置已生成并加载：
   - `bfe.conf` 加载 `mod_ai_token_auth`、`mod_ai_route`、`mod_ai_cache`、`mod_ai_rate_limit`；
   - 缓存规则：`cond=default_t()`、`cacheKeyStrategy=lastQuestion`、`cacheTTL=3600`、`maxBodyBytes/maxValueBytes=1048576`；
   - token 规则：无限配额方案 `unlimited_plan`，除既有 `ak_cache` / `ak_cache2` 外，**新增本用例专属 Key** `ak_cache_rl`（`key_id=cache_key_id_3`）；
   - 路由：`ak_cache_rl` → `apikey_ak_cache_rl` → `cluster_cache`（`Model=""`）；
   - 限流策略（仅绑定到 `ak_cache_rl`，其余 Key 不绑定任何策略，因此 TC-01..TC-12 不受影响）：

     | 项 | 值 |
     |----|----|
     | policy id / name | `rlp-sc20` / `sc20-rpm`（`enabled=true`） |
     | 产品规则 | `cond=default_t()`，`hit_action=FINISH` |
     | RPM 规则 | `name=sc20-rpm-rule`，`window_minutes=1`，`max_requests=1`，`burst=1`，`models=["*"]`，`redis_key=RL_RPM_rlp-sc20_0` |
     | Key 绑定 | `ApikeyRateLimitPolicyBindings: {"ak_cache_rl": ["rlp-sc20"]}` |

## BFE 请求

Host 固定 `cache.example.org`，Path 固定 `/v1/chat/completions`。

| 步骤 | Authorization | 附加头 | Body |
|------|---------------|--------|------|
| 1（填充缓存 + 消耗唯一 rpm 额度） | `Bearer ak_cache_rl` | - | `{"model":"deepseek-chat","messages":[{"role":"user","content":"what is bfe?"}]}` |
| 2（主断言：命中） | `Bearer ak_cache_rl` | - | 同步骤 1 |
| 3（对照组：未命中链路） | `Bearer ak_cache_rl` | `x-bfe-skip-ai-cache: on` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"what is a cache?"}]}` |

## 后端响应

mock 后端 `cluster_cache` 返回 `200`：

```json
{"choices":[{"index":0,"message":{"role":"assistant","content":"BFE is a layer-7 load balancer"},"finish_reason":"stop"}],"usage":{"prompt_tokens":10,"completion_tokens":8,"total_tokens":18}}
```

## 执行步骤

1. 启动 BFE（缓存规则 `defaultCacheRule()`，token 规则含 `ak_cache_rl`，限流策略绑定 `ak_cache_rl`）。
2. 发送步骤 1 的请求：未命中，回源，回写缓存，同时消耗 rpm 额度（`max_requests=1`）。
3. 轮询 Redis 确认缓存键 `ai_cache:cache_key_id_3:*` 已写入。
4. 发送步骤 2 的请求（同一问句，不带 skip 头）：命中缓存。
5. 发送步骤 3 的对照请求（新问句 + skip 头）：走未命中链路，触发限流判定。

## 预期结果

- 步骤 1：返回 200，响应无 `X-Bfe-Ai-Cache: hit`；上游被调用 1 次；缓存键写入 Redis；RPM 额度被消耗至 0。
- 步骤 2（主断言）：返回 **200**，响应头 `X-Bfe-Ai-Cache: hit`，响应体为缓存答案；**不出现 429**；上游调用次数**不增加**（仍为 1，命中不打上游）；限流计数器不再增长。
- 步骤 3（对照组，证明额度确实耗尽）：返回 **429**，响应体 `error.code == "RPM_LIMIT_EXCEEDED"`；上游调用次数**不增加**。

即：命中 ⟹ 限流不检查、不计量、不消耗额度（T-1433-1），而未命中链路的限流判定保持不变（T-1433-5：错误码只在未命中链路出现）。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录（由测试框架 `t.TempDir()` 自动回收）。
