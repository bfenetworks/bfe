# TC-12 命中不执行模型访问控制

## 用例编号与名称

TC-12 命中不执行模型访问控制

## 所属场景

SC20 AI 缓存精确匹配

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_cache`、`mod_ai_token_auth`）
- 条款依据：`docs/zh_cn/modifications/2026-10-20-issue-1433-cache-hit-policy-matrix/design-changes.md` §3.1 条款 **T-1433-1（命中不执行成本类策略）**

> **本用例是条款 T-1433-1 的负向回归，不是缺陷修复。** 缓存命中时不执行模型访问控制（`allow_models` / `block_models`）是产品 owner 已确认的预期行为（允许模型仅用于成本/配额治理，命中不产生 provider 调用、不计费），本用例只把这个事实钉住，不改变任何数据面行为。

## 测试目的

验证模型访问控制（`mod_ai_token_auth.targetModelCheckFilter`，注册在 `HandleAfterAITargetModel`）在缓存命中路径上**不被求值**：

1. 把 API Key 的 `allow_models` 收紧到不含当前请求模型后，**带 `x-bfe-skip-ai-cache: on` 的对照请求**仍被 `400 MODEL_NOT_ALLOWED` 拒绝（证明收紧已生效）；
2. 同一问题**不带** skip 头时命中缓存，返回 `200` + `X-Bfe-Ai-Cache: hit`，**不产生 `MODEL_NOT_ALLOWED`**，且不调用上游。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis（miniredis，进程内，BFE 重启后数据仍在）。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. 嵌入式 Redis 已启动，并在两次 BFE 启动之间保持存活（缓存项跨重启存在）。
3. mock 后端 `cluster_cache` 已启动，返回 200 与非流式答案（见"后端响应"）。
4. 临时 BFE 配置已生成并加载：
   - `bfe.conf` 加载 `mod_ai_token_auth`、`mod_ai_route`、`mod_ai_cache`、`mod_ai_rate_limit`；
   - 缓存规则：`cond=default_t()`、`cacheKeyStrategy=lastQuestion`、`cacheTTL=3600`、`maxBodyBytes/maxValueBytes=1048576`；
   - token 规则：无限配额方案 `unlimited_plan`，Key `ak_cache`（`key_id=cache_key_id`）的 `allow_models="deepseek-chat"`；
   - 路由：`ak_cache` → `apikey_ak_cache` → `cluster_cache`（`Model=""`，即目标模型 = 请求体模型 `deepseek-chat`）；
   - 限流：`ai_rate_limit.data` 为空绑定（本用例不涉及限流）。

## BFE 请求

Host 固定 `cache.example.org`，Path 固定 `/v1/chat/completions`。

| 步骤 | Authorization | 附加头 | Body |
|------|---------------|--------|------|
| 1（填充缓存） | `Bearer ak_cache` | - | `{"model":"deepseek-chat","messages":[{"role":"user","content":"how does bfe route?"}]}` |
| 2（重启 BFE，`allow_models` 收紧为 `other-model`） | - | - | - |
| 3（对照组） | `Bearer ak_cache` | `x-bfe-skip-ai-cache: on` | 同步骤 1 |
| 4（主断言） | `Bearer ak_cache` | - | 同步骤 1 |

## 后端响应

mock 后端 `cluster_cache` 返回 `200`：

```json
{"choices":[{"index":0,"message":{"role":"assistant","content":"BFE is a layer-7 load balancer"},"finish_reason":"stop"}],"usage":{"prompt_tokens":10,"completion_tokens":8,"total_tokens":18}}
```

## 执行步骤

1. 以 `allow_models="deepseek-chat"` 启动 BFE；发送步骤 1 的请求（miss，回源并回写缓存）。
2. 轮询 Redis 确认缓存键 `ai_cache:cache_key_id:*` 已写入。
3. 停止 BFE（`stopBFE()`），用同一 Redis、同一缓存规则、`allow_models="other-model"` 重启 BFE。
4. 发送步骤 3 的对照请求（skip 头，跳过缓存读，走正常未命中链路）。
5. 发送步骤 4 的主断言请求（同一问句，不带 skip 头）。

## 预期结果

- 步骤 1：返回 200，响应无 `X-Bfe-Ai-Cache: hit`；上游被调用 1 次；缓存键写入 Redis。
- 步骤 3（对照组，证明白名单已生效）：返回 **400**，响应体 `error.code == "MODEL_NOT_ALLOWED"`；上游调用次数**不增加**（仍为 1）。
- 步骤 4（主断言）：返回 **200**，响应头 `X-Bfe-Ai-Cache: hit`，响应体为缓存的 `BFE is a layer-7 load balancer`；上游调用次数与步骤 3 之后**相同**（仍为 1，命中不打上游）；**不出现** `MODEL_NOT_ALLOWED`。

即：命中 ⟹ 模型访问控制未求值（T-1433-1），而未命中链路的 allowlist 校验保持不变（T-1433-5：错误码只在未命中链路出现）。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录（由测试框架 `t.TempDir()` 自动回收）。
