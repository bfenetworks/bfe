# SC15 长度分档计费与 1h 缓存写价

## 1. 场景背景与目的

BFE AI 网关在 2026-09-09 起支持长度分档计费与 1h TTL 缓存写价（见 `modifications/2026-09-09-length-tier-and-cache-1h-billing/design-changes.md`）。本场景验证：

- **长度分档**：`ModelTable` 配置 `PriceInputCostPerTokenAbove272kTokens` / `PriceOutputCostPerTokenAbove272kTokens` 后，当请求输入 token 总数超过 272k 阈值时，**整单**输入/输出按档价计费（TC-01 超档、TC-02 未超阈值对照臂）；
- **1h 缓存写价拆分**：配置 `PriceCacheCreationInputTokenCost1h` 后，上游报文中的 1h TTL 缓存写部分按 1h 价单独计价，余量按 5m 基础缓存写价计价：
  - Anthropic 扩展字段 `usage.cache_creation.ephemeral_1h_input_tokens`（OpenAI 风格 body 承载，1h 部分已含在 `cache_write_tokens` 内）（TC-03）；
  - relay 扁平兜底字段 `usage.cache_creation_input_tokens_1h`（TC-04）；
  - **未配置 1h 价时**：上游即使上报 1h 部分，全部缓存写仍按 5m 基础价计价，与存量计费行为逐分一致（TC-05 回归臂）；
  - SSE 流式响应路径同样拆分（TC-06）。

正常输入 token 口径：`normal_input = prompt_tokens - cache_write_tokens`（缓存写部分不计入普通输入价）。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程；
- 计费断言使用进程内 miniredis（`common.RedisServer`），不引入 `ai-gateway-api` 与 `conf-agent`；
- 客户端 API Key `ak_user_a`（KeyId `user_a_key_id`），RMB 配额方案 `plan_rmb`（Unit=`RMB`，Redis Key `quota:plan_rmb`，初始配额 10000000000）；
- 请求：`POST /v1/chat/completions`，Host `sc15.example.org`，`Authorization: Bearer ak_user_a`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_route`、`mod_ai_token_auth`、`mod_body_process` |
| `mod_ai_route/mod_ai_route.conf`、`ai_route.data` | apikey 级路由规则 |
| `mod_ai_token_auth/mod_ai_token_auth.conf` | token 鉴权配置（Bns 由 builder 重写为 miniredis；token 规则由测试代码动态生成，含 `plan_rmb` 方案与 `CHECK_TOKEN` 默认规则） |
| `mod_body_process/mod_body_process.conf`、`body_process.data` | 流式响应 quota 处理（TC-06 依赖） |

| `tls_conf/*` | 测试桩证书（复制自既有场景） |

## 5. 计费断言说明

- 断言值用 `quota.CalcCostUnits(tokens, price)` 逐项计算求和，避免硬编码魔法数；
- 计费在 `HandleRequestFinish` 异步完成，断言前 sleep 500ms；
- 扣款后余额断言：`quota:plan_rmb` = 10000000000 - want。
