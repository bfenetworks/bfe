# SC20 标准库 crypto/tls 适配（bfe_tls fork 下线）

## 1. 场景背景与目的

BFE 历史上内嵌一份 Go 1.9 时代 fork 的 `bfe_tls`（仅支持 TLS 1.2），用于 MultiCert、ServerRule、JA3、握手耗时、Redis session cache 等扩展能力。本次改造删除整个 `bfe_tls` 包，TLS 能力全部回归标准库 `crypto/tls`：

- 证书选择 → `tls.Config.GetCertificate`（VIP→SNI→默认三级回退）。
- 规则下发 → `tls.Config.GetConfigForClient`（ALPN 灰度、ClientAuth、ClientCAs、CRL 校验）。
- 会话恢复 → 标准库 session ticket（Redis 跨实例共享移除）。
- TLS 版本放开到 1.3，下限提到 1.2（标准库已不支持 1.0/1.1）。
- Grade/Chacha20/DynamicRecord、JA3、SSLv2 等能力废弃。
- `mod_key_log` 改用标准库 `tls.Config.KeyLogWriter`（NSS 格式）。

对应设计文档：`bfe/docs/zh_cn/modifications/2026-10-14-remove-bfe-tls-fork/design-changes.md`。

本场景的目的是在**真实 BFE 进程**上验证 fork 删除后 TLS 数据面行为与设计一致：版本协商、SNI 选证书、ALPN、双向认证、CRL、会话票据、废弃字段兼容、密钥日志。

> 与 SC13 的关系：SC13 验证 `/reload/tls_conf?path=` 的**配置加载路径**（client CA 目录取自版本目录），其中已覆盖 reload 后 ClientAuth 生效；本场景聚焦**协议行为本身**，规则在启动时即生效，不依赖 reload。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程 + `httptest` mock 后端，不依赖 conf-agent / ai-gateway-api / Redis。
- 客户端为测试进程内的 `crypto/tls` 直连（`tls.Dial`/`http.Client`），通过 `ConnectionState` 与真实 HTTP 请求断言。
- 全部 TLS 证书材料（CA、服务器双证书、客户端证书、CRL）由测试代码用 `crypto/x509` **现场程序化生成**，不再携带历史 PEM 常量（历史证书只有 legacy CN，Go ≥1.15 标准库拒绝用于名校验）。
- mock 后端为 HTTP（明文）；BFE→后端链路不做 TLS 要求。

| 文件 | 说明 |

| `bfe.conf` | 启用 https/monitor；TC-07 额外包含已废弃的 session cache 字段，验证解析兼容 |

| `tls_conf/tls_rule_conf.data` | VIP/SNI 规则、NextProtos（h2 灰度）、ClientAuth、废弃字段（Grade 等） |
| `tls_conf/certs/*` | 测试代码现场生成的双 SAN 服务器证书与私钥 |
| `tls_conf/client_ca/example_ca.crt` | 测试代码现场生成的客户端 CA |
| `tls_conf/client_crl/example_ca/*.crl` | TC-05 使用：测试代码现场签发的 CRL（含被吊销序列号） |
| `tls_conf/session_ticket_key.data` | 32 字节会话票据密钥（标准库格式；TC-06 验证 reload 轮换） |

| `cluster_conf/*`、`server_data_conf/*`、`mod_ai_route/*` | 复用 SC01 模板结构，保证 BFE 可启动并能回源 mock 后端 |

## 5. 公共断言方式

- **TLS 层**：`tls.Dial` 后检查 `conn.ConnectionState()`：
  - `Version`：`tls.VersionTLS13` / `tls.VersionTLS12`；
  - `PeerCertificates[0]`：Subject/DNSNames，用于 SNI 选证断言；
  - `NegotiatedProtocol`：`h2` / `http/1.1`；
  - 会话恢复：1.3 用 `ConnectionState.DidTLS13Resume`，1.2 用 `ConnectionState().DidResume`（客户端侧 session cache 复用）。
- **TLS 1.3 客户端认证的可观察性**：服务端 Finished 先于客户端证书校验，无证书时 `tls.Dial` 可能成功，强制行为通过连接上首个 HTTP 请求失败（alert/连接关闭）断言；TLS 1.2 下无证书握手同步失败（与 SC13 TC01 同一结论）。
- **HTTP 层**：经 ALPN 协商的连接发送 `GET / HTTP/1.1`（或 h2 请求），断言收到 mock 后端的响应体，证明端到端转发正常。
- **reload**：monitor 端口 `GET /reload/tls_session_ticket_key` / `/reload/tls_conf`，响应 `{"error": ...}`，`error` 为空表示成功。

## 6. 公共基础设施

- `common.ProcessEnv`：编译/缓存 bfe 二进制、分配随机端口、启停进程。
- `common.BFEConfigBuilder`：从 `testdata/` 模板生成 conf 目录、注入 mock 后端地址。
- 测试内新增 PKI 辅助函数（仅本 scenario）：
  - `newTestCA(name)`：自签 CA（cert + key + PEM）；
  - `newServerCert(ca, dnsNames...)`：SAN 服务器证书；
  - `newClientCert(ca, serial)`：指定序列号的客户端证书（供 CRL 吊销）；
  - `newCRL(ca, revokedSerials...)`：DER/PEM 编码 CRL 文件。
- mock 后端：`common.NewMockBackend`，回 200 与可识别响应体。

## 7. 与其他场景的依赖关系

- 无运行时依赖；独立启动独立销毁。
- 与 SC13 互补：SC13 管 reload 路径重定位，SC20 管协议行为。
- TC-03 的 h2 协商为 SC01~SC19 所有 HTTPS 场景提供「h2 链路未因 fork 删除而损坏」的专项保证（其余场景默认只走 http/1.1）。
