# TC-07 废弃配置字段向后兼容

## 目的

验证 fork 下线后所有废弃配置保持「**可解析、不生效、不阻断启动**」：线上存量配置无需修改即可滚动升级。

对应实现（Phase 6）：`TestTC07_DeprecatedFieldsCompat`。

## 前置条件

- `tls_rule_conf.data` 的规则中显式包含废弃字段：
  ```json
  "Grade": "A+",
  "Chacha20": true,
  "DynamicRecord": true
  ```
  同时包含顶层 `"DefaultChacha20": true`。
- `bfe.conf` 包含已废弃的 `[SessionCache]` 段（`SessionCacheDisabled = true`，并填写 `Servers`/`KeyPrefix`/`ConnectTimeout` 等存量字段），以及 https 基础段中的 `EnableSslv2ClientHello`。

## 执行步骤

1. 使用上述存量配置启动 BFE。
2. 发起 TLS 1.3 握手 + HTTP 请求（SNI=example.org）。
3. 发起 TLS 1.2 握手 + HTTP 请求。
4. 检查 BFE 日志不包含配置解析错误（废弃字段仅可能输出忽略类 WARN）。

## 预期结果

- 第 1 步 BFE 正常启动并完成全量配置加载，无 fatal。
- 第 2、3 步握手与请求均成功（200）；密码套件/版本由标准库默认安全策略决定，Grade/Chacha20/DynamicRecord 不产生任何行为效果。
- 不发生任何 Redis 连接尝试（session cache 字段被忽略，会话恢复走标准库 ticket，见 TC-06）。

## 补充说明

`ClientAuth` 旧布尔字面量的兼容解析（`true → RequireAndVerifyClientCert`）在 TC-04 覆盖；本用例只覆盖其余废弃字段。

## 清理

- 停止 BFE、关闭 mock 后端。
