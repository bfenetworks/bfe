# SC38 HTTPS 后端 TLS

## 1. 场景背景与目的

BFE 支持以 HTTPS 访问后端，2026-02-05 的 `481eb13e` 修正了连接 HTTPS 后端时的 ServerName 取法：优先 `HTTPSConf.RSHost`，否则使用后端地址中的 host（`cm.tlsHost()`），并统一了客户端证书与 `RSCAList` 的加载时序。此前该能力没有进程级回归。

本场景验证：

- `RSHost` 决定 SNI 与证书校验名，握手成功；
- 未配 `RSHost` 时回落到后端地址（`127.0.0.1`），仅含 DNS SAN 的证书校验失败；补配 `RSHost` 后同一拓扑成功；
- `RSInsecureSkipVerify=true` 跳过证书校验；
- 未配 `RSCAList` 时使用系统 CA，私有 CA 证书被拒绝；
- `RSCAList` 完全替代系统 CA：正确 CA 成功、无关 CA 失败；
- 双向 TLS：配置 `BFECertFile/BFEKeyFile` 时后端收到客户端证书；不配置时握手被拒；
- TLS 失败基线：请求快速失败、后端 handler 不被调用、BFE 继续服务后续请求。

> 实施发现（缺陷记录）：当 `HTTPSConf.RSCAList` 非空且未写 `RSInsecureSkipVerify` 时，`bfe_http/transport.go:652` 会解引用空指针导致进程 panic。测试通过显式写入 `RSInsecureSkipVerify:false` 规避，并建议在配置加载处补默认值（`BackendHTTPSCheck` 中 `nil -> false`）。建议另开缺陷单跟踪。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，`EnableAiGateway=false`；
- 后端为进程内 HTTPS mock（`httptest` + 调用方提供的证书），记录 SNI 与客户端证书 CN；
- 证书由 Go 在测试内生成（CA/服务端/客户端），不依赖外部 openssl 或静态 PEM。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | `EnableAiGateway=false`；不加载 AI 模块 |
| `server_data_conf/host_rule.data` | `ai_product` 对应 `tls.example.org` |
| `server_data_conf/route_rule.data` | 默认路由到 `cluster_tls` |
| `cluster_conf/gslb.data` | `cluster_tls` 单子集群 |
| `cluster_conf/cluster_table.data` / `cluster_conf.data` | 运行时生成；`BackendConf.Protocol=https`，按用例注入 `HTTPSConf` |
| `tls_conf/backend_rs/*` | 运行时写入测试 CA、客户端证书与私钥 |

## 4. 测试 Cluster 与配置

- `cluster_tls`：单 HTTPS mock 后端；
- `HTTPSConf` 字段：`RSHost`、`RSInsecureSkipVerify`、`RSCAList`、`BFECertFile`、`BFEKeyFile`；
- 证书材料：测试内生成 CA（1 小时有效期）、服务端证书（DNS SAN 或 IP SAN）、客户端证书（CN=`bfe-client`）。
