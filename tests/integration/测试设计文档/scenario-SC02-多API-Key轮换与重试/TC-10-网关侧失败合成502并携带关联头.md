# TC-10 网关侧失败合成 502 并携带关联头

## 用例编号与名称

TC-10 网关侧失败合成 502 并携带关联头（issue #1441 步骤 3 + 第二轮）

## 所属场景

SC02 多 API-Key 轮换与重试

## 版本声明

- `bfe`：v1.8.9-dev 分支 + issue #1441 修复（`ServeHTTPForAI` 网关侧失败出口由空体 500 改为统一 `BACKEND_UNAVAILABLE`(502) 错误体，`f4feae5b`）
- `bfe`：v1.8.9-dev 分支 + issue #1441 第二轮修复（网关自生成错误响应携带 §3.3 关联头：`X-Bfe-Log-Id` 恒写、`X-Request-ID` 回显）

## 测试目的

验证**后端不可达**（连接失败）时，`ServeHTTPForAI()` 网关侧出口返回统一 AiError 形态的 **502 `BACKEND_UNAVAILABLE`**（而非修复前的空体 500），且与合成 429 一样携带 §3.3 关联头——作为「非 429 单点补丁」的上游不可用代表例。

本用例同时收口第一轮 #1441 的遗留项「502 路径端到端集成测试」：现有设计文档中的 502（SC03/SC05/SC27）全部是**上游返回体**或归一映射，本用例是 BFE **本地合成**的 502。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程。

## 前置条件

1. 已编译含 issue #1441（含第二轮）修复的 `bfe` 可执行文件。
2. 本场景 `testdata` 同步扩展（随本 TC 落地）：
   - `server_data_conf/host_rule.data` 增加 host `deadbackend.example.org`；
   - `mod_ai_route/ai_route.data` 的 `apikey_ak_user_a` 路由表增加规则 `user_a-deadbackend`（条件 `req_host_in("deadbackend.example.org")`，targets=`cluster_dead_backend`，**无 fallbacks**）；
   - `cluster_conf/gslb.data` 增加 `cluster_dead_backend`（`GSLB_BLACKHOLE: 0`，`sub_dead: 100`）；
   - `tests/integration/common/util.go` 的 `clusterSubName` 新增 case `cluster_dead_backend → dead`。
3. 公共框架 `common.BFEConfigBuilder.StaticBackends`（既有能力）用于把 `cluster_dead_backend` 指向一个**无监听**的 `127.0.0.1` 端口。

## 配置构造

- `cluster_dead_backend` 的 `AIConf`（本用例通过 `BFEConfigBuilder.AIConfs` 注入）：
  - `Keys`：`[{Name:"key-dead", Key:"sk-key-dead", Weight:100}]`（保证选 Key 成功，失败发生在**连接后端**阶段，而非选 Key 阶段）；
  - `KeyPolicy.MaxRetries`：0（连接失败一次即出口，避免退避等待拖长用例）。
- `BFEConfigBuilder.StaticBackends["cluster_dead_backend"] = "127.0.0.1:<closedPort>"`，`<closedPort>` 在测试内取空闲端口（`net.Listen("tcp","127.0.0.1:0")` 后立即关闭）得到；该地址无进程监听，BFE 拨号即 `connection refused`。

## BFE 请求

| 字段 | 值 |
|------|-----|
| Host | `deadbackend.example.org` |
| Path | `/v1/chat/completions` |
| Authorization | `Bearer ak_user_a` |
| Body | `{"model":"gpt-4"}` |
| X-Request-ID | `tc10-req-id` |

## 执行步骤

1. 按上述构造启动 BFE。
2. 发送请求，读取响应状态码、响应头与 body。
3. 检查 BFE 运行日志（`log/bfe.log`）出现后端连接失败记录（`dial ... connection refused` 一类）。
4. 检查 exception.log 无新增 panic/异常。

## 预期结果

- 响应状态码：**502**（不是空体 500）；
- 响应 `Content-Type: application/json`，body 解析后 `error.code == "BACKEND_UNAVAILABLE"`、`error.type == "internal_error"`、`error.message` 非空（通用文案，不泄漏内部拓扑）；
- 响应头 `X-Bfe-Gw-Error: 1`（归一器跳过标记）；
- **无** `Retry-After` 响应头（仅 Key 耗尽 429 携带）；
- 响应头 `X-Bfe-Log-Id` 非空（纯十进制、值 ∈ `(0, 2^63-1]`；本场景未加载 `mod_logid`，走 §3.3 回退链由网关现场生成并回写 `req.LogId`）；
- 响应头 `X-Request-ID` 与请求值 `tc10-req-id` 字节相等；
- 响应头 `Server: bfe`；
- BFE 日志出现连接失败记录；exception.log 无 panic。

## 清理

停止 `bfe` 进程与所有 mock 后端，删除临时目录。

## 备注

- 与 SC27 502 类用例的区别：SC27 的 502 是**上游返回的错误体**（mock 后端应答 502）或归一映射（`UPSTREAM_*`），本用例的 502 是 BFE 拨号失败后在 `ServeHTTPForAI` 本地合成的 `BACKEND_UNAVAILABLE`，零上游字节返回。
- 本场景 `bfe.conf` 仅加载 `mod_ai_route`（无 `mod_logid`/`mod_access_pb3`），故关联头走「现场生成」回退链；响应与访问日志 `logid` 的同源恒等由 SC27/TC-09（加载 `mod_access_pb3`）承担。
- `<closedPort>` 的「取端口后释放」存在理论端口复用竞态（另一个进程恰好监听该端口）；为此 `AIConf` 配了真实 Key，即使竞态发生也只会变成一次普通转发失败/成功，用例会显式失败而非误判通过。
