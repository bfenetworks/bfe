# TC-05 开关关闭基线

## 用例编号与名称

TC-05 开关关闭基线

## 所属场景

SC27 上游错误体归一

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.NormalizeUpstreamError` 实现）

## 测试目的

验证默认关闭的兼容性基线：不配置 `NormalizeUpstreamError` 的集群，上游错误
（状态码与响应体）**逐字节透传**、不产生任何归一日志字段——证明存量集群行为
与历史版本完全一致（回归锚点）。

## 运行模式

单组件模式：真实 `bfe` + 脚本化错误 mock 后端，无 Redis。

## 前置条件

1. `cluster_err` AIConf：**不配置** `NormalizeUpstreamError` 字段
   （仅 `Keys`）。
2. `ak_front` 无限额配额计划。

## 配置构造

```json
"AIConf": {
    "Keys": [{"Name": "key-primary", "Key": "sk-upstream-secret", "Weight": 100}]
}
```

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `front.example.org` | `/v1/chat/completions` | `Bearer ak_front` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"hi"}]}` |

## 后端响应

同 TC-01（401 OpenAI envelope，body 回显 key）。

## 执行步骤

1. 启动 BFE，发送请求；
2. 比对响应与上游脚本逐字节一致；
3. 检查日志记录。

## 预期结果

- 响应状态码 **401**（上游原样）；
- 响应 body 与上游脚本**逐字节一致**（含 `sk-upstream-secret` 明文——
  开关关闭的集群维持现状行为，不脱敏）；
- 响应头**无** `X-Bfe-Gw-Error`；
- 访问日志：`ai_upstream_status` / `ai_upstream_err_code` /
  `ai_err_normalized` / `ai_err_normalize_miss` / `ai_stream_error_rewritten` /
  `ai_stream_truncated` **全部缺省**（proto optional 未设置）。

## 清理

停止 `bfe` 进程与 mock 后端，删除临时目录。
