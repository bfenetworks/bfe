# TC-03 未识别错误体透传与脱敏

## 用例编号与名称

TC-03 未识别错误体透传与脱敏

## 所属场景

SC27 上游错误体归一

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.NormalizeUpstreamError` 实现）

## 测试目的

验证未识别错误体（非协议 envelope，如上游代理 HTML 错误页）的默认
`passthrough` 行为：状态码与语义保不变，但 `RedactSecrets`（默认开启）仍对
body 中的 cluster key 脱敏——消除"未识别错误成为凭证泄漏通道"的残留风险。

## 运行模式

单组件模式：真实 `bfe` + 脚本化错误 mock 后端，无 Redis。

## 前置条件

1. `cluster_err` AIConf：`NormalizeUpstreamError={Enabled:true}`（
   `UnrecognizedAction` 缺省 = passthrough）。
2. `ak_front` 无限额配额计划。

## 配置构造

同 TC-01。

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `front.example.org` | `/v1/chat/completions` | `Bearer ak_front` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"hi"}]}` |

## 后端响应

`cluster_err` 返回 502 HTML 错误页（body 含 cluster key）：

```http
HTTP/1.1 502 Bad Gateway
Content-Type: text/html

<html><body>proxy error: backend rejected key sk-upstream-secret</body></html>
```

## 执行步骤

1. 启动 BFE，发送请求；
2. 解析响应状态/体与日志记录。

## 预期结果

- 响应状态码 **502**（保持上游状态码，不归一）；
- 响应 `Content-Type: text/html`；
- 响应 body 结构原样（HTML），其中 `sk-upstream-secret` 被替换为
  `••••••••`（passthrough 语义不受损、脱敏生效）；
- 响应头**无** `X-Bfe-Gw-Error`（未重写）；
- 访问日志：`ai_err_normalized` 未设置、`ai_err_normalize_miss=true`、
  `ai_upstream_status=502`。

## 清理

停止 `bfe` 进程与 mock 后端，删除临时目录。
