# SC18 Key 模型白名单按目标模型校验

## 1. 场景背景与目的

BFE AI 网关自 issue #1387 修复起，API Key 的 `allow_models` / `block_models` 列表改为按「转发后目标模型」校验（模型重定向之后），而非请求体原始模型（见 `docs/zh_cn/modifications/2026-09-23-issue-1387-key-model-allowlist-target-model/design-changes.md`）。本场景验证：

- 鉴权期（`ValidateUserTokenByReq`）不再因模型不在白/黑名单内拒绝请求；模型校验移至 `bfe_server/reverseproxy.go` 的 `doSingleAIForward` 内、转发到后端之前，由 `ModuleAITokenAuth.ValidateTargetModel`（`bfe_modules/mod_ai_token_auth/model_check.go`）对目标模型执行；
- 目标模型计算（`computeTargetModel`）= 路由目标 Model 覆盖 → StripPrefix → 集群 ModelMapping（`cluster_conf.AIConf.ModelMapping`），白/黑名单匹配该最终值；
- 拒绝时响应 400 `MODEL_NOT_ALLOWED`，`details.model` 为目标模型（而非请求体原始模型），请求未到达后端、不产生计费扣减；
- `block_models` 与 `allow_models` 对称按目标模型匹配（block 原始模型名不影响重定向后的请求）；
- 无重定向时目标模型等于请求体原始模型，行为与修复前一致（不退化）；
- 集群级 fallback 时对每个 attempt 的目标模型复校验：校验失败的本地 400 在 key 轮换循环 default 分支停止轮换，但 400 在默认 `aiFallbackStatusCodes` 内触发集群级 fallback，下一 attempt 重算目标模型并复校验；
- gemini 路径模型语义继承（issue #1384）：请求体无 `model` 字段时经 `extractClientModel` 路径兜底进入 `ClientModel`，无覆盖/映射时目标模型继承 `ClientModel`。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程。
- 计费断言使用进程内 miniredis（`common.RedisServer`），不引入 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_route`、`mod_ai_token_auth`、`mod_body_process`（沿用 SC16 模板） |
| `mod_ai_route/mod_ai_route.conf` | 指定 `ai_route.data` 路径 |
| `mod_ai_route/ai_route.data` | 定义 apikey 级路由规则：按 Host 路由到 `cluster_redirect` / `cluster_plain`，`fallback.example.org` 主目标 `cluster_plain` + fallback `cluster_redirect`，`gemini.example.org` 路由到 `cluster_gemini` |
| `mod_ai_token_auth/mod_ai_token_auth.conf` | token 鉴权配置（Bns 由 builder 重写为 miniredis） |
| `mod_body_process/mod_body_process.conf`、`body_process.data` | 流式响应 quota 处理（本场景依赖默认 streamcompletion 处理器） |
| `server_data_conf/host_rule.data` | 声明 `ai_product` 产品线对应的 4 个 Host |
| `server_data_conf/route_rule.data` | 默认路由（BasicRule 默认 cluster 为 cluster_plain） |
| `cluster_conf/cluster_conf.data` | 运行时根据 mock 后端与 `AIConfs` 动态生成 |
| `cluster_conf/gslb.data` | GSLB 权重配置 |
| `cluster_conf/cluster_table.data` | 运行时根据 mock 后端地址动态生成 |

## 5. 路由规则

| 规则名 | 条件 | targets | fallbacks |
|--------|------|---------|-----------|
| user_a-redirect | `req_host_in("redirect.example.org")` | `cluster_redirect`，Model 为空 | 无 |
| user_a-plain | `req_host_in("plain.example.org")` | `cluster_plain`，Model 为空 | 无 |
| user_a-fallback | `req_host_in("fallback.example.org")` | `cluster_plain`，Model 为空 | `cluster_redirect`，Model 为空 |
| user_a-gemini | `req_host_in("gemini.example.org")` | `cluster_gemini`，Model 为空 | 无 |

## 6. 计费断言说明

客户端 API Key 为 `ak_user_a`（token 配额方案 `plan_token`，Unit=`total_token`，初始配额 1000000，Redis Key `quota:plan_token`）。计费在 `HandleRequestFinish` 异步完成，断言前 sleep 500ms（与 SC03/SC16 相同）。

## 7. 测试用例列表

| 用例 | 名称 | 优先级 |
|------|------|--------|
| TC-01 | allow_models 按重定向后目标模型放行（issue 复现主链路） | P0 |
| TC-02 | 目标模型不在 allow_models 内拒绝（details.model 为目标模型） | P0 |
| TC-03 | block_models 按目标模型校验（block 原始模型名不影响重定向后请求） | P0 |
| TC-04 | 无重定向行为不退化（目标模型等于请求体原始模型） | P0 |
| TC-05 | fallback 复校验目标模型（主目标校验失败未达后端，fallback 重算后放行） | P0 |
| TC-06 | gemini 路径模型回归（目标模型继承 ClientModel） | P0 |
