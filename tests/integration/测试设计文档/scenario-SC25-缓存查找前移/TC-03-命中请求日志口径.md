# TC-03 命中请求日志口径

## 用例编号与名称

TC-03 命中请求日志口径

## 所属场景

SC25 缓存查找前移

## 版本声明

- `bfe`：当前源码版本（缓存查找已前移至 `HandleFoundProduct`，含 `mod_ai_intent`、`mod_access_pb3`）

## 测试目的

锁定前移后的访问日志口径（下游报表适配依据）：

- **命中**请求：短路在路由求值之前 → 无路由结果、无意图求值——
  `ai_cache_status=hit`，`ai_route_rule_hits` / `ai_target_model` / `ai_intent_*` 缺省或为空；
- **未命中**请求：三者正常非空。

## 运行模式

单组件模式：真实 `bfe` + 嵌入式 Redis + mock 决策服务 + mock 后端 +
`mod_access_pb3` 输出 b2log 二进制访问日志（测试解析 `RequestLog` 断言）。

## 前置条件

1. 同 TC-01（b2log 输出目录指向临时目录）。
2. mock 决策服务 `Calls()=0`。
3. `mod_access_pb3` 已加载，访问日志输出开启。

## BFE 请求

同 TC-01：同一问题「帮我给这个函数写单元测试」连续请求 2 次。

## 预期结果

- 请求层面：第 1 次 miss / 第 2 次 hit，决策服务 `Calls()==1`，`cluster_flash` `Hits()==1`（同 TC-01）。
- BFE 停止前等待 500ms 确保日志落盘，解析 b2log 得到 2 条 `RequestLog`：
  - **miss 那条**：`ai_cache_status == "miss"`；`ai_route_rule_hits` 非空（命中
    intent-flash）；`ai_target_model == "deepseek-v4.1-flash"`；
    `ai_intent_question/answer/confidence` 非空（task_type / test_writing / 0.93）、
    `ai_intent_source` 为模型分类值；
  - **hit 那条**：`ai_cache_status == "hit"`；`ai_route_rule_hits` 缺省或空；
    `ai_intent_*` 整组缺省（路由未执行 → 懒解析未触发）；
    `ai_target_model` **非空且等于客户端模型 `deepseek-chat`**——`InitAiBasicInfo`
    在路由前即把 TargetModel 置为客户端 model（`http_conn.go:568`），命中请求
    不经过路由改写，故该字段不能区分命中/未命中，判别依据是前两个字段。

## 清理

停止 `bfe` 进程、mock 后端、mock 决策服务与嵌入式 Redis，删除临时目录（含 b2log 目录）。
