# TC-04 跳过头走完整链路

## 用例编号与名称

TC-04 跳过头走完整链路

## 所属场景

SC25 缓存查找前移

## 版本声明

- `bfe`：当前源码版本（缓存查找已前移至 `HandleFoundProduct`，含 `mod_ai_intent`）

## 测试目的

验证 `x-bfe-skip-ai-cache: on` 在新回调位置下的语义不变：既不读也不写缓存，
请求走完整链路（鉴权 → 缓存 skip → 路由 → 懒解析 → 上游）。

## 运行模式

单组件模式：真实 `bfe` + 嵌入式 Redis + mock 决策服务 + `cluster_flash` / `cluster_kimi` mock 后端。

## 前置条件

1. 已编译 `bfe` 可执行文件，嵌入式 Redis 已启动。
2. 已有一个缓存问题：先用同一问题正常请求 1 次（miss 回写缓存，
   决策服务 `Calls()==1`，`cluster_flash` `Hits()==1`）。

## BFE 请求

| 步骤 | Host | Path | Authorization | Header | Body |
|------|------|------|---------------|--------|------|
| 1 | `front.example.org` | `/v1/chat/completions` | `Bearer ak_front` | `x-bfe-skip-ai-cache: on` | 同前置步骤的问题 |

## 预期结果

- 响应 200，但**无** `X-Bfe-Ai-Cache: hit` 响应头（跳过头生效，不读缓存）。
- 响应体来自 `cluster_flash`（路由照常求值、意图分流——完整链路的证据）。
- mock 决策服务 `Calls()` **仍为 1**（同 prompt 的再次分类被进程内意图 LRU
  吸收，SC22 TC-10 同款行为）；`cluster_flash` `Hits() == 2`（skip 后正常转发上游）。
- Redis 中既有缓存键不被覆盖、不新增同名键（`cache_status=skip` 不写）。

## 清理

停止 `bfe` 进程、mock 后端、mock 决策服务与嵌入式 Redis，删除临时目录。
