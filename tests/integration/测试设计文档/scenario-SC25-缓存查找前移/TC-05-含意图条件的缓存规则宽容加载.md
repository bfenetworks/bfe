# TC-05 含意图条件的缓存规则宽容加载

## 用例编号与名称

TC-05 含意图条件的缓存规则宽容加载

## 所属场景

SC25 缓存查找前移

## 版本声明

- `bfe`：当前源码版本（缓存查找已前移至 `HandleFoundProduct`，`cache_rule_load.go`
  含 `req_ai_intent_in` 加载期 WARN）

## 测试目的

验证缓存规则 Cond 引用 `req_ai_intent_in` 时**宽容加载**：规则照常生效（WARN
不拒绝）。该配置会抵消懒解析下沉收益（缓存查找阶段触发分类），属误配，
但不得导致加载失败或模块不可用。

> WARN 日志文本的代码路径由模块单测 `TestProductRuleConfLoadWithIntentCond`
> 锁定；本用例从功能层面验证"误配不破坏缓存服务"。

## 运行模式

单组件模式：真实 `bfe` + 嵌入式 Redis + mock 决策服务 + mock 后端。

## 前置条件

1. 已编译 `bfe` 可执行文件，嵌入式 Redis 已启动。
2. mock 决策服务 `Calls()=0`。

## 配置构造

- 缓存规则（Cond 引用意图原语——误配样例）：

```json
{
    "cond": "req_ai_intent_in(\"task_type\", \"doc_writing\") && default_t()",
    "cacheKeyStrategy": "lastQuestion",
    "cacheTTL": 3600,
    "maxBodyBytes": 1048576,
    "maxValueBytes": 1048576
}
```

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `front.example.org` | `/v1/chat/completions` | `Bearer ak_front` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"写文档：补充这个模块的 README"}]}` |
| 2 | `front.example.org` | `/v1/chat/completions` | `Bearer ak_front` | 同上 |

## 预期结果

- BFE 正常启动，`mod_ai_cache` 规则加载成功（启动日志含 WARN，人工核对关键字
  `negate the lookup-early benefit`）。
- 第 1 次请求：缓存规则条件求值触发懒解析（误配生效的证明）→ 决策服务
  `Calls()==1`；规则条件命中（doc_writing）→ 缓存生效检查 miss →
  `cluster_kimi` `Hits()==1`；响应 200。
- 第 2 次请求：hit（`X-Bfe-Ai-Cache: hit`）——规则条件再次求值，但进程内意图
  LRU 吸收（key=问题文本+questions 版本，命中不回访决策服务），`Calls()` **仍为
  1**；`cluster_kimi` `Hits()` 仍为 1。WARN 针对的是该求值路径本身会在 LRU 未命中
  /过期时于命中请求上触发分类（单测 `TestProductRuleConfLoadWithIntentCond` 锁定
  告警代码路径）。

## 清理

停止 `bfe` 进程、mock 后端、mock 决策服务与嵌入式 Redis，删除临时目录。
