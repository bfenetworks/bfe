# SC37 集群 Host 与健康检查开关

## 1. 场景背景与目的

2026-02-05 的 `0fb8f0a3` 为集群增加了两个开关，用于对接外部 Web 服务：

- `ClusterBasic.DisableHostHeader`：为 `true` 时不向 后端设置原始 Host，传输层回落到后端地址；
- `ClusterBasic.DisableHealthCheck`：为 `true` 时请求失败不计入失败数、不摘除后端，也不启动主动健康检查。

两个开关只有在特定外部服务对接场景使用，此前没有进程级回归。本场景验证：

- 默认 `DisableHostHeader=false`：后端收到客户端原始 Host；
- `DisableHostHeader=true`：后端收到后端地址（`127.0.0.1:<port>`）；
- `DisableHealthCheck=true`：连续 5xx 不摘除后端，`/healthcheck` 探测数为 0；
- `DisableHealthCheck=false`：达到 `CheckConf.FailNum` 后摘除，后续业务请求不再到达后端，主动健康检查启动；
- 健康检查成功后（`SuccNum`）后端恢复接流；
- 两个字段缺省时按 BFE 默认值（false/false）工作。

> 实施说明：共享 harness 为兼容既有场景把 `DisableHealthCheck` 预置为 `true`（`common/bfe_config_builder.go`）。TC-06 通过 `ClusterOverride.RemoveClusterBasic` 删除该键，验证 BFE 自身默认值；其余用例显式覆盖。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，`EnableAiGateway=false`（两个开关属于通用转发能力）；
- 后端为进程内 `httptest` mock，可按路径区分业务请求与 `/healthcheck`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | `EnableAiGateway=false`；不加载 AI 模块 |
| `server_data_conf/host_rule.data` | `ai_product` 对应 `switch.example.org` |
| `server_data_conf/route_rule.data` | 默认路由到 `cluster_switch` |
| `cluster_conf/gslb.data` | `cluster_switch` 单子集群 |
| `cluster_conf/cluster_table.data` / `cluster_conf.data` | 运行时生成；按用例注入 `ClusterBasic`/`BackendConf`/`CheckConf` 覆盖 |

## 4. 测试 Cluster 与配置

- `cluster_switch`：单 mock 后端；
- 健康检查参数（TC-03~06）：`Schem=http`、`Uri=/healthcheck`、`Host=example.org`、`StatusCode=200`、`FailNum=1`、`SuccNum=1`、`CheckInterval=100ms`；
- 5xx 摘除判据：`BackendConf.OutlierDetectionHttpCode="5xx"`。
