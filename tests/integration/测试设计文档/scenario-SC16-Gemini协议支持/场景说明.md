# SC16 Gemini 协议支持

## 1. 场景背景与目的

BFE AI 网关在 2026-09-09 起支持识别并转发 Google Gemini generateContent / streamGenerateContent 请求（见 `modifications/2026-09-09-gemini-protocol-support/design-changes.md`）。本场景验证：

- BFE 能根据 `x-goog-api-key` 头与 `:generateContent` / `:streamGenerateContent` / `/v1beta/models/` 路径形态识别 `gemini` 协议风格；
- 按 gemini 风格向上游注入 `x-goog-api-key` 认证头（无 `Authorization`、无版本头）；
- `AIConf.ModelProtocols` 校验请求协议与集群 provider 支持协议，不匹配时拒绝（`PROVIDER_PROTOCOL_MISMATCH`）；
- 多协议集群（`["openai","gemini"]`）可同时支持两种请求，认证头按协议各自注入；
- gemini 非流式 `usageMetadata`（camelCase）被正确解析并计费（total_token 配额按 `totalTokenCount` 扣减）；
- gemini 流式每个 chunk 携带累积 `usageMetadata` 且无 SSE 终止事件：计费按最后一个含 usage 的 chunk 入账（取中间 chunk 会少计）；
- `Authorization` 与 `x-goog-api-key` 并存时 Authorization 优先（既有优先级不回退）；
- 无凭证请求在 AI 网关模式下被路由层拦截（404 "AI route not found"），不到达转发层——gemini 路径识别规则（`DetectProtocol`）集成层面不可达，由 `bfe_model_protocol` 单元测试直接覆盖（本场景 TC-06 锁定该路由拦截行为）；
- gemini 上游 401 时 key 级轮换兜底。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程。
- 计费断言使用进程内 miniredis（`common.RedisServer`），不引入 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_route`、`mod_ai_token_auth`、`mod_body_process` |
| `mod_ai_route/mod_ai_route.conf` | 指定 `ai_route.data` 路径 |
| `mod_ai_route/ai_route.data` | 定义 apikey 级路由规则，按 Host 路由到不同 cluster |
| `mod_ai_token_auth/mod_ai_token_auth.conf` | token 鉴权配置（Bns 由 builder 重写为 miniredis） |
| `mod_body_process/mod_body_process.conf`、`body_process.data` | 流式响应 quota 处理（本场景依赖默认 streamcompletion 处理器） |
| `server_data_conf/host_rule.data` | 声明 `ai_product` 产品线对应的 4 个 Host |
| `server_data_conf/route_rule.data` | 默认路由（BasicRule 默认 cluster 为 openai-only） |
| `cluster_conf/cluster_conf.data` | 运行时根据 mock 后端与 `AIConfs` 动态生成 |
| `cluster_conf/gslb.data` | GSLB 权重配置 |
| `cluster_conf/cluster_table.data` | 运行时根据 mock 后端地址动态生成 |

TC-06（路径识别）使用独立的 `testdata_routeonly/` 模板：仅加载 `mod_ai_route`（不加载 `mod_ai_token_auth`），使无凭证请求可达转发主路径，BasicRule 默认路由到 gemini-only cluster。

## 5. 计费断言说明

客户端 API Key 为 `ak_user_a`（token 配额方案 `plan_token`，Unit=`total_token`，初始配额 1000000，Redis Key `quota:plan_token`）。BFE 按识别出的协议用 cluster key 替换上游凭证：

- gemini 请求：上游收到 `x-goog-api-key: <cluster key>`，无 `Authorization`；
- openai 请求：上游收到 `Authorization: Bearer <cluster key>`。

计费在 `HandleRequestFinish` 异步完成，断言前 sleep 500ms（与 SC03 相同）。
