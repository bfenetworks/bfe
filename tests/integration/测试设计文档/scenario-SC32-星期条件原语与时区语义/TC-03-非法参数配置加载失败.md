# TC-03 非法参数配置加载失败

## 用例编号与名称

TC-03 非法参数配置加载失败

## 所属场景

SC32 星期条件原语与时区语义

## 版本声明

- `bfe`：当前源码版本（`time_weekday_in` 的参数在**配置加载期**校验：`NewWeekdayMatcher` 校验星期列表与时区字母，
  `parser/semant.go` 的 `prototypeCheck` 校验参数个数与类型）

## 测试目的

锁定 `time_weekday_in` 的**非法参数 fail-fast**行为：错误的规则必须在配置加载阶段被拒绝并给出可直接定位
（含规则原文与非法值）的错误信息，而不是加载成功后在运行期静默不命中。后者会让运营看到"规则明明配了却不生效"，
是条件原语类问题最难排查的形态。

覆盖三类错误来源：

| 类别 | 拦截点 | 期望错误信息（片段） |
|------|--------|----------------------|
| 星期取值非法 | `NewWeekdayMatcher`（`condition.Build` 阶段） | `invalid weekday:7, should be an integer in [0, 6]` |
| 时区字母非法 | `NewWeekdayMatcher`（`condition.Build` 阶段） | `invalid zone:QQ` |
| 参数类型/个数非法 | `prototypeCheck`（`parser.Parse` 阶段） | `primitive time_weekday_in arg 0 expect STRING, got INT` / `primitive args len error, expect 2, got 1` |

## 运行模式

单组件模式：仅使用已编译的 `bfe` 二进制做**配置校验**（`bfe -c <confDir> -t`，`-t` 为 test configuration and exit），
不启动服务、不发请求。

## 前置条件

1. 已编译 `bfe` 可执行文件（`common.ProcessEnv.Build()` 的产物）。
2. 每臂一份独立的临时配置目录：以 `testdata/` 为模板，仅替换 `mod_ai_route/ai_route.data` 中
   承载非法条件的规则，其余配置与基线一致（基线必须校验通过，作为对照，避免把其它配置问题误判为本用例结论）。

## 配置构造

基线 `ai_route.data` 的动作见「场景说明 §4.1」；各臂只改一条规则的 `Cond`：

| 臂 | 被改规则的 `Cond` |
|----|-------------------|
| 基线（对照） | `req_host_in("weekday.example.org") && time_weekday_in("1\|2\|3\|4\|5", "H")` |
| A | `req_host_in("weekday.example.org") && time_weekday_in("7", "H")` |
| B | `req_host_in("weekday.example.org") && time_weekday_in("0", "QQ")` |
| C | `req_host_in("weekday.example.org") && time_weekday_in(0)` |
| D | `time_weekday_in("0", "H", "Z")`（参数个数超出） |

## 执行步骤

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | `bfe -c <基线confDir> -l <logDir> -t` | 退出码 0；输出含 `configuration file <...>/bfe.conf test is successful` |
| 2 | `bfe -c <A confDir> -l <logDir> -t` | 退出码非 0；输出含 `time_weekday_in "7": invalid weekday:7, should be an integer in [0, 6]`，且含触发规则的原文（`rule[<规则名>] build cond[<Cond>] err: ...`，即 `mod_ai_route` 规则校验路径的错误格式） |
| 3 | `bfe -c <B confDir> -l <logDir> -t` | 退出码非 0；输出含 `time_weekday_in "0": invalid zone:QQ` |
| 4 | `bfe -c <C confDir> -l <logDir> -t` | 退出码非 0；输出含 `primitive time_weekday_in arg 0 expect STRING, got INT` |
| 5 | `bfe -c <D confDir> -l <logDir> -t` | 退出码非 0；输出含 `primitive args len error, expect 2, got 3` |

## 预期结果

- 步骤 1 校验通过（对照臂），证明本用例的配置模板本身合法，失败只可能来自被改的那条 `Cond`；
- 步骤 2–5 全部**加载失败**且错误信息含原语名、非法值与规则原文，满足"可定位"要求；
- 步骤 2/3 由 `condition.Build` 阶段拦截、步骤 4/5 由 `parser.Parse` 阶段拦截，错误文案与
  「修改说明 §四 错误处理与边界」表格一致；
- **明确不在本用例范围**：热加载（`reload`）失败时保留旧配置的语义，以及 `time_weekday_in` 之外的
  既有原语行为回归（前者由 reload 相关场景覆盖，后者由单元测试与既有集成场景覆盖）。

## 清理

删除各臂的临时配置目录与日志目录；本用例不遗留运行中的进程。
