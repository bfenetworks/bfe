# TC-01 星期编号语义与集合命中

## 用例编号与名称

TC-01 星期编号语义与集合命中

## 所属场景

SC32 星期条件原语与时区语义

## 版本声明

- `bfe`：当前源码版本（含条件原语 `time_weekday_in`：`bfe_basic/condition/primitive.go` 的 `WeekdayMatcher`、
  `bfe_basic/condition/build.go` 的 `case "time_weekday_in"`、`bfe_basic/condition/parser/semant.go` 的原型登记）

## 测试目的

锁定 `time_weekday_in` 的**星期编号语义**与**集合判定**：

- `0` = 周日、`1` = 周一、…、`6` = 周六（与 Go `time.Weekday`、cluster 分时段计价 `weekdays` 约定一致）；
- 集合 `1|2|3|4|5`、`6`、`0` 的命中/未命中与「互斥且穷尽」的路由分支一一对应。

编号错位（例如把 `0` 当成周一）是本原语最容易出现且最难在单测之外察觉的缺陷：路由不会报错，
只会静默走到错误的 cluster。因此本用例用**一周七天的完整遍历**直接暴露编号错位，而不是只测两侧样本。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. mock 后端已启动：`cluster_weekday_work` / `cluster_weekday_sat` / `cluster_weekday_sun` /
   `cluster_weekday_utc_work` / `cluster_weekday_utc_default` / `cluster_weekday_default` 均返回 200，
   响应体含 cluster 名（用于判定命中哪个 cluster）。
3. `weekday.example.org` 与 `weekday-utc.example.org` 已加入 `host_rule.data` 的 `ai_product`；
   `ak_user_a` 在 `ApikeyRouteTableBindings` 中绑定 `apikey_ak_user_a`。
4. `bfe.conf` 启用 `EnableAiGateway` 并加载 `mod_ai_route`。

## 配置构造

- `mod_ai_route/ai_route.data`：路由表 `apikey_ak_user_a` 的规则见「场景说明 §4.1」；
- Host `weekday.example.org` 的三条规则覆盖一周七天，按星期集合互斥且穷尽；
- 时间由请求头 `X-Bfe-Debug-Time`（格式 `yyyymmddhhmmssZ`，`Z` 为时区字母）指定，
  使判定与用例运行当天无关（确定性）。

## BFE 请求

请求：`POST http://127.0.0.1:<bfePort>/v1/chat/completions`，Host `weekday.example.org`，
Header `Authorization: Bearer ak_user_a`、`X-Bfe-Debug-Time: <下表时间>`，body `{"model":"m","messages":[]}`。

2019-02-03 为周日，2019-02-04 为周一，其后依次顺延。

| 步骤 | `X-Bfe-Debug-Time`（北京时间） | 期望命中 cluster | 期望结果 |
|------|-------------------------------|------------------|----------|
| 1 | `20190204203000H`（周一 20:30） | `cluster_weekday_work` | 200 |
| 2 | `20190205203000H`（周二 20:30） | `cluster_weekday_work` | 200 |
| 3 | `20190206203000H`（周三 20:30） | `cluster_weekday_work` | 200 |
| 4 | `20190207203000H`（周四 20:30） | `cluster_weekday_work` | 200 |
| 5 | `20190208203000H`（周五 20:30） | `cluster_weekday_work` | 200 |
| 6 | `20190209203000H`（周六 20:30） | `cluster_weekday_sat` | 200 |
| 7 | `20190203203000H`（周日 20:30） | `cluster_weekday_sun` | 200 |
| 8 | **不带** `X-Bfe-Debug-Time`（真实系统时钟） | 由测试按 `time.Now()` 在 UTC+8 下的星期推算：周一至周五 → `cluster_weekday_work`；周六 → `cluster_weekday_sat`；周日 → `cluster_weekday_sun` | 200 |

## 预期结果

- 步骤 1–7：每步仅目标 cluster 命中 1 次，其余 cluster 命中数均为 0；
  步骤 6/7 必须分别落在 `sat`/`sun` 分支——若落入 `work` 或其它 cluster，即编号语义错误。
- 步骤 8：命中 cluster 与按 `time.Now()` 推算的期望一致，证明**非调试头路径**（进程系统时钟）同样生效。
  该步骤存在午夜跨日竞态：请求前后各取一次 `time.Now()` 的星期，若发生跨越则重发一次并重新推算期望
  （记录在测试日志中，不视为失败）。
- 全部步骤期望 HTTP 200，响应体来自 mock 后端，且不出现 `AI route not found`（所有请求都应命中规则）。

## 清理

停止 `bfe` 进程与所有 mock 后端，删除临时目录。
