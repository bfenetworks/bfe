# TC-18 未调用后端请求的耗时字段兜底（issue #1391）

## 用例编号与名称

TC-18 未调用后端请求的耗时字段兜底（401 鉴权拒绝 / 429 配额拒绝）

## 所属场景

SC05 AI 访问日志字段校验

## 版本声明

- `bfe`：当前源码版本（含 issue #1391 修复）

## 测试目的

验证未调用后端即结束的请求，PB 访问日志（`mod_access_pb3`）的耗时字段不产生超出 MySQL `INT` 范围的溢出值， particularly `proxy_delay_time` 使用数据库可接受的兜底值 `0`。

修复前（issue #1391）：`reqTimeInfoGen` 未校验 `BackendFirst` 是否有效，未调用后端的请求（`BackendFirst` 为 `time.Time` 零值）算出饱和负 Duration，经 `uint32` 截断后成为恒定垃圾值 `2217714954`（大于 `INT` 最大值 `2147483647`），导致 log-reader `mod_log_mysql` 批量 INSERT 报 `Error 1264`，同批正常记录随整批重试耗尽后被丢弃。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis。

## 前置条件

1. 同 TC-01，但额外准备两个拒绝臂：
   - 臂 A（无效 Key）：请求携带不存在的 API Key，触发 401 鉴权拒绝；
   - 臂 B（配额耗尽）：Redis 中 `quota:plan_rmb = 0`，`ak_user_a` 绑定 `plan_rmb`，触发 429 配额拒绝。
2. 两个臂的请求均在 `HandleFoundProduct` 阶段被短路，不进入 reverseproxy 转发，`cluster_rmb` 后端命中 0 次。

## BFE 请求

依次发送 2 次 POST 请求：

| 臂 | Host | Path | Authorization | Body | 预期状态码 |
|----|------|------|---------------|------|------------|
| A | `rmb.example.org` | `/v1/chat/completions` | `Bearer ak-not-exist`（无效 Key，脱敏占位值） | `{"model":"deepseek-chat"}` | 401 |
| B | `rmb.example.org` | `/v1/chat/completions` | `Bearer ak_user_a` | `{"model":"deepseek-chat"}` | 429 |

## 预期结果

- `cluster_rmb` 收到 0 次命中（两臂均未调用后端）。
- b2log 中存在 2 条 `RequestLog`，逐条断言：
  - `proxy_delay_time` = 0（修复前为恒定溢出值 `2217714954`，本用例即针对该回归）；
  - `cluster_serve_time` = 0、`backend_serve_time` = 0、`connect_backend_time` = 0（未调用后端，双零端点相减，修复前后均为 0，作为对照字段锁住行为）；
  - `all_time`、`read_client_time`、`write_client_time`、`session_offset_time` 均 ≤ `2147483647`（不引入新的溢出点；401/429 响应经 `send_response` 路径写出，这两个端点有效，值应非负且远小于上限）；
  - 臂 A：`ai_auth_reject_reason` 非空且包含 `INVALID_API_KEY`；臂 B：`ai_auth_reject_reason` 非空（`QUOTA_EXHAUSTED` 形态）；
  - 臂 B：`ai_auth_reject_quota_plans` = `["plan_rmb"]`（与 TC-04 一致）；
  - `ai_route_rule_hits`、`ai_cluster_key_names` 为空（请求在认证阶段被拒绝，未进入路由）。
- 公共断言：凭据脱敏（`mustFindSingleLog` 扩展为多日志版本后逐条执行 `assertNoSensitiveCredential`，臂 A 请求中的占位 Key 不得出现在日志中）。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录。

## 实施备注

- 实现为 `sc05_access_log_ai_fields_test.go` 中 `TestTC18_NoBackendTimeFieldsFallback`，复用 TC-04 的环境构造（`newTestEnv` + `rmbQuotaPlan(0)`），臂 A 直接以未配置的 Key 发送请求即可，无需新增配置；
- 多日志断言复用 `e.accessLogs()`（参考 TC-07/TC-16/TC-17 的用法），需保证解析到恰好 2 条 `RequestLog` 并按 `ai_auth_reject_reason` 区分两臂；
- 本用例在修复落地前应当失败（`proxy_delay_time` 断言得到 `2217714954`），修复后通过，符合"先红后绿"的回归用例定位。
