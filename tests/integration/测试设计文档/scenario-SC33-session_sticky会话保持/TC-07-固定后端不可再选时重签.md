# TC-07 固定后端不可再选时重签

## 用例编号与名称

TC-07 固定后端不可再选时重签

## 所属场景

SC33 session_sticky 会话保持

## 版本声明

- `bfe`：当前源码版本

## 测试目的

验证 Cookie 指向的后端权重为 0 后，请求重新均衡并重签 Cookie。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程；后端与审计服务均为进程内 mock。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. `cluster_sticky` 内启动 2 个 mock 后端（同一子集群，权重相同），用于区分 sticky 是否命中。
3. `bfe.conf`：`EnableAiGateway=false`，`Modules = mod_session_sticky`。
4. 需要 Redis 的用例启动 miniredis，并由 harness 将 `[redis] Bns` 重写为测试实例。

## 配置构造

- 同 TC-01。
- 构造指向 backend A 的 Cookie；改写 cluster_table 将 backend A 权重置 0 并 `/reload/gslb_data_conf`。

## BFE 请求

| 步骤 | Host | Path | 关键设置 | 说明 |
|------|------|------|----------|------|
| 1 | sticky.example.org | /v1/chat/completions | 指向 A 的 Cookie | A 已不可选 |

## 预期结果

- HTTP 200；backend A 命中 0，backend B 命中 1。
- 响应 `Set-Cookie` 解密后指向 backend B 的端口。
