# SC33 session_sticky 会话保持

## 1. 场景背景与目的

`mod_session_sticky` 于 2026-07-07 引入（`945b28ae`），随后增加 Redis 缓存与 JSON 字段支持（`ff2d42ce`）。模块提供两种会话保持模式：

- **Cookie 模式**：把后端信息加密后写入 Cookie，后续请求解密后固定到同一后端；
- **Sticky 模式**：把 stickyid 与后端的映射写入本地 LRU 或 Redis，stickyid 可来自 Cookie、Header、URI 参数或 JSON 请求体，也可从 JSON 响应体提取。

该模块此前完全没有集成测试。本场景验证：

- Cookie 模式的注入/绑定/命中、Cookie 属性、篡改回退、备用掩码兼容、RenewWindow 续期、后端不可选时重签；
- Sticky 模式的来源优先级（Cookie > Header > URIParam > JSON 请求字段）、JSON 响应字段提取；
- Redis 缓存跨 BFE 重启复用与 ExpireSeconds 过期；
- 规则条件隔离、规则热加载、非法 CacheType 启动失败。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，`EnableAiGateway=false`，只加载 `mod_session_sticky`；
- 同一 cluster 内 **2 个 mock 后端**（权重相同），用命中数区分 sticky 是否生效；
- Redis 为进程内 miniredis（Sticky 模式 Redis 缓存用例，可推进虚拟时钟）。

| 文件 | 说明 |

## 4. 配置要点与实现事实

- Cookie 值 = `base64.RawStd(XOR(json, mask))`，json 形如
  `{"ip":"127.0.0.1","port":<port>,"subcluster":"<subKey>","renewtime":<unix>}`；
- `subcluster` 使用 cluster_table 的子集群键（本场景为 `sub_sub`），不是 gslb 中的简称 `sub`。构造 Cookie/Redis 映射时必须使用该键，否则 `LookupStickyBackend` 找不到子集群；
- Redis 映射键为 `bfe:stickyid:<id>`，值为 `{"addr","port","sub_cluster","created_at"}`，TTL 由 `ExpireSeconds` 控制；
- `CacheSize` 在代码中钳制为最小 10000，LRU 淘汰不做集成测试（由模块单测覆盖）；
- Cookie 的 `Domain` 属性中前导点会被 `net/http` 序列化去掉（浏览器同样忽略该点），测试按序列化后的形式断言。
