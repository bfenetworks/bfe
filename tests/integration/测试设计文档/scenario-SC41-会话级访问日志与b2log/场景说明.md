# SC41 会话级访问日志与 b2log 封装

## 1. 场景背景与目的

`mod_access_pb3` 于 2026-07-03 引入（`e10dcbe0`），除请求级 `RequestLog` 外，还为每个连接输出一条会话级 `BfeLog`（`LogType=session`）。日志文件使用 `b2log` 二进制封装（24 字节头 + protobuf 载荷），由 log-reader 等下游解析。已有场景（SC05）只覆盖请求级 AI 字段，会话级记录与封装格式没有回归。

本场景验证：

- 会话日志基本字段：`log_type=session`、`log_tag`、`logid`、`timestamp`、`proto`、`req_num`；
- VIP → product 的 `log_tag=session_<product>`（通过 `Layer4LoadBalancer=PROXY` + PROXY 协议头构造 VIP）；
- 请求日志 `session_id` 与会话日志 `logid` 的关联（加载 `mod_logid` 时）；
- HTTPS 会话的 TLS 信息（`tls_version`、`cipher_suite`、`handshake_time`）；
- 握手失败会话：`log_tag=session_err_*` 与 `err_code`/`err_msg`；
- b2log 封装：每条记录魔数/版本/长度合法、载荷可反序列化为 `BfeLog`、无残留字节。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，`EnableAiGateway=false`；
- 后端为进程内 mock；HTTPS 使用 testdata 中的 `example.org` 证书；
- 不使用 Redis。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | `Modules = mod_logid`、`mod_access_pb3`；`Layer4LoadBalancer` 按用例改写为 `""` 或 `"PROXY"` |
| `server_data_conf/host_rule.data` | `ai_product` 对应 `log.example.org` |
| `server_data_conf/vip_rule.data` | `ai_vip` 对应 `127.0.0.1`（PROXY 用例的 VIP） |
| `server_data_conf/route_rule.data` | 默认路由到 `cluster_log` |
| `cluster_conf/gslb.data` / `cluster_conf.data` | `cluster_log` 单子集群，运行时生成 |
| `tls_conf/tls_rule_conf.data` | `SniConf=example.org`；握手失败用例把 `ClientAuth` 改为 `true` |
| `mod_access_pb3/mod_access_pb3.conf` | `LogPrefix=pb_access3`、`LogDir=../log` |

## 4. 行为事实（实施记录）

- 会话的 `Product` 来自 **VIP → product 表**（`vip_rule.data`），不是请求 Host；未启用 `Layer4LoadBalancer` 时 `GetVipPort` 失败，`Product` 为空，`log_tag` 回落为 `session_bfe`。用 `Layer4LoadBalancer="PROXY"` + PROXY v1 头（目的地址 127.0.0.1）可得到 `session_ai_vip`；
- `SessionLog` 当前只填充 `tls_version`、`cipher_suite`、`session_resume`、`ocsp_staple`、`handshake_time`；proto 中的 `tls_cert_common_name` 未填充，也没有 SNI 字段；
- `lost_type` 仅在错误消息命中 `mod_crypto RsaDecrypt failed` 时置为 `Bfe`；普通 TLS 握手失败只体现在 `err_code=CLIENT_TLS_HANDSHAKE` 与 `err_msg`；
- 请求日志的 `session_id` 与会话日志的 `logid` 都来自 `session.SessionId`；未加载 `mod_logid` 时该字段为空，两条写路径各自生成随机兜底值，二者**不相等**。TC-02 因此加载 `mod_logid`；
- b2log 记录头：`HEADER_SIZE=24`、`MAGIC_NUMBER=0xB0AEBEA7`、`HEADER_VERSION=1`；当前不压缩，`CompressLen=0`，载荷长度取 `UnCompressLen`；
- 测试框架的 `WaitForTCP` 就绪探测会产生一条 `CLIENT_CLOSE`、`req_num=0` 的会话日志，断言时按 `req_num>0` 过滤。
