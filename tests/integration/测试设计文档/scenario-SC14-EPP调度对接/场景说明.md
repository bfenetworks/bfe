# SC14 EPP 调度对接（ext-proc）

## 1. 场景背景与目的

本场景验证 BFE 与 EPP（Endpoint Picker，基于 Envoy ext-proc 协议的外部调度器）对接的核心行为：`BalanceMode = "EPP"` 的 cluster 把后端选择委托给 EPP，EPP 通过 dynamic metadata 返回选中的推理实例地址，BFE 按该地址转发，并在响应阶段把响应头/响应体回传给 EPP。

EPP 侧使用**测试进程内 mock server**（`common/mock_epp.go`）：实现 ext-proc v3 `ExternalProcessor` 服务与 gRPC health 服务，TLS 自签证书（BFE 在 `EPPTLS` 未配置时跳过证书校验但仍走 TLS），可按测试脚本返回调度地址或注入 gRPC 错误，并记录每个流上的 pool metadata、请求头/体、响应头/体供断言。

后端使用真实 [llm-d-inference-sim](https://github.com/llm-d/llm-d-inference-sim) 进程（OpenAI 兼容的 vLLM 模拟器，echo 模式），验证 EPP 决策的地址确为 BFE 实际转发的目标。

对应设计文档：`bfe/docs/zh_cn/sys_design/epp_integration.md`（BFE 对接 EPP 调度设计）。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程；EPP 为进程内 mock（gRPC server 监听 127.0.0.1 随机端口），不依赖 `ai-gateway-api` 与 `conf-agent`。
- 本场景**启用 AI 网关模块**（`EnableAiGateway = true`，加载 `mod_ai_route`）：请求携带 API Key（`Authorization: Bearer ak_epp`），经 apikey 路由表（`req_host_in("epp.example.org")`）命中 `cluster_epp_sim`；`BalanceEpp` 由核心反代路径按 `BalanceMode == EPP` 触发。
- `cluster_conf.data` 由 harness 按测试参数生成（`BalanceMode=EPP`、`EPPAddr` 为 mock EPP 地址、可带 `EPPCheck`/`EPPTimeout`/`EPPBreaker`）；`cluster_table.data` 由 harness 根据 inference-sim 地址生成。
- 每个测试例独立启动 inference-sim、mock EPP 与 BFE 进程，端口全部动态分配。
- inference-sim 二进制缺失时（`INFERENCE_SIM_BIN` 未设置且 `../llm-d-inference-sim/bin` 不存在）整个场景 `t.Skip`。

## 4. 测试例清单

| 编号 | 名称 | 一句话描述 |
|------|------|------------|
| TC-01 | EPP 决策转发与 pool metadata | EPP 返回 inference-sim 地址，请求按决策转发；cluster 名以 `llm-d.ai/inference-pool` metadata 送达 EPP；请求体完整回传 |
| TC-02 | SSE 流式响应回传 | 流式（SSE）响应的响应头与完整响应体（分块重组、EOS 终结）送达 EPP，客户端收到完整流 |
| TC-03 | 健康检查主备 failover | 主 EPP 宕机后，健康检查（短周期参数）触发 failover，活跃地址切到备，后续请求由备调度 |
| TC-04 | 错误驱动即时重试 | 主 EPP 返回 `Unavailable / cell is not serving`，同一请求不经健康检查周期直接在备地址重试成功 |
| TC-05 | unknown inference pool 降级本地 | 主备均返回 `Internal / unknown inference pool`，请求回退本地 WRR 均衡成功并打点 |
| TC-06 | EPP 宕机降级本地 | 单 EPP 地址进程消失，请求回退本地均衡成功并打点 |
| TC-07 | 熔断器 OPEN | 连续 EPP 失败使熔断器 OPEN（状态迁移打点），请求短路走本地均衡且全部成功 |

## 5. 公共断言方式

- **转发结果**：响应 200 且 body 为 inference-sim echo 内容（含请求中的唯一标记串），证明请求确实到达 EPP 指定的后端。
- **mock EPP 记录**：`Pools()`（pool metadata）、`RequestHeadersList()`、`RequestBodies()`、`ResponseHeadersList()`、`ResponseBodies()`、`StreamCount()`。
- **指标**：monitor 端口 `/monitor/epp_metrics`（prometheus text），轮询直至满足条件：`epp_calls_total{cluster,result}`、`epp_failover_total{cluster}`、`epp_fallback_local_total{cluster}`、`epp_breaker_transitions_total{cluster,state}`、`epp_active_addr_index{cluster}`。

## 6. 注意事项

- BFE 到 EPP 的连接**始终使用 TLS**（`EPPTLS` 未配置时仅跳过证书校验），mock EPP 必须以 TLS 提供服务。
- BFE 的 ext-proc 请求头使用 `RawValue` 承载值，`Value` 为空；mock 侧解析需回退读 `RawValue`。
- inference-sim 以 `--model epp-test-model` 启动，请求体中的 `model` 必须一致，否则 sim 返回 404（模型不存在）。
- `epp_calls_total` 记录的是**请求级最终结局**（在备地址重试成功记为 `ok`），中间地址的错误类别不在该指标中体现。
