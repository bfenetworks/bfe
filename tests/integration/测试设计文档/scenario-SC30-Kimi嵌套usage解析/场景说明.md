# SC30 Kimi 嵌套 usage 解析（issue #1401）

## 1. 场景背景与目的

本场景验证 BFE issue #1401 的修复在真实 BFE 进程中的行为。issue #1401（#1398 facet-2）：Kimi（kimi-for-coding）在客户端不带 `stream_options.include_usage` 时，把最终 usage **嵌在流式 finish chunk 的 `choices[0]` 内**（`choices[0].usage`，cache 字段名为 `cached_tokens`），且**忽略** BFE 注入的 `stream_options.include_usage`。修复前 `ParseOpenAIUsageFields` 只读顶层 `usage.*`，嵌套 usage 解析为全 0 → `isguess=true` → 不计 final usage：

- `EstimateToken=true`：日志/计费落**估算伪造值**（prompt=请求体/4、completion=chunk/4，与真实值无 causal 关系）；
- `EstimateToken=false`：日志落 `(0, -1, 0)` 脏数据（负 output tokens），计费副本进清零块按 0 扣费。

修复（治本）：`ParseOpenAIUsageFields` 增加 `choices[N].usage` 回退（逐 choice 扫描、主链优先、`cached_tokens`/`prompt_tokens_details.cached_tokens` 映射）。回退命中后 `UsedQuota>0` → `isguess=false` → OpenAI 适配器白名单（`type==""`）识别为 final usage → 既有累加/守卫/副本链路按**真实 usage** 计费与落日志，与估算开关无关。

与既有场景的关系：

- **SC29**（#1398）：usage 抹零修复与 include_usage 注入。本场景是其 facet-2 延续——注入对 Kimi 无效（上游忽略），parser 回退是唯一可靠来源；SC29 的三个 TC 全部回归执行。
- **SC1401-TC022/TC023**（外部测试设计）：双开关矩阵判例，其真实 usage 探针为 Anthropic 非流式，**不覆盖** Kimi 嵌套 `choices[0].usage` 形态——本场景即该覆盖缺口的补齐。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程与内存 Redis（测试框架提供），mock 后端为 `httptest.Server`（固定回放 Kimi 形态的 SSE 事件序列，忽略收包中的 `stream_options`）。
- 需要加载 `mod_access_pb3` 以断言 pb3 访问日志字段。
- 双开关矩阵：`EstimateToken = true`（模板 conf）与 `EstimateToken = false`（测试在 `builder.Build()` 后重写生成的 `bfe.conf`，显式 conf 值覆盖程序默认值）。两 TC 除开关外前置条件完全一致。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 4. 测试 Cluster 与 AIConf 设计

### 4.1 cluster_nested_usage

配置一个 `kimi-for-coding` 模型（`gpt-4` 经 ModelMapping 映射），复用 SC29 单价（定点，1 单位 = 1e-8 元）：输入 300/token、输出 900/token。**不配置 cache 单价**——`calcChatCost` 仅在配置了 cache 单价时才拆分 cache read/write，未配置时整 prompt 按输入价计，扣费公式保持 `prompt*300 + completion*900`；`cached_tokens` 分项仅作日志断言。

## 6. 关键实现细节

- **嵌套事件序列**（两 TC 相同）：内容 chunk（`choices[0].delta`，无 usage）→ Kimi finish chunk（`choices[0].usage`，值为 issue 抓包实证数字 prompt=77207 / completion=168 / total=77375 / cached=73472）→ `[DONE]`。数值采用实证数字以便回归可直接对账 pcap。
- **判别力**：TC-01 中若回退未生效，`EstimateToken=true` 路径会落估算值（prompt=请求体/4≈25，远小于 77207）；TC-02 会落 (0,-1,0)。`ai_input_tokens=77207` 的断言对"估算/清零/负值"三种失效形态均判别。
- **透传断言**：客户端收到的 SSE 流必须原样包含嵌套 usage chunk（`"total_tokens":77375"`）与 `[DONE]`——parser 只读不改事件。
- **注入断言**（TC-01）：mock 后端收包必须带 `stream_options.include_usage=true`（缓解已生效），同时 mock 固定回放嵌套形态——精确复刻 facet-2 触发条件"注入生效 + 上游忽略"。
- **扣费断言**：Redis `quota:plan_rmb` 余额 = 初始值 − (77207×300 + 168×900) = 初始值 − 23313300。
- **日志断言**（pb3）：`ai_input_tokens=77207`、`ai_output_tokens=168`、`ai_total_tokens=77375`、`ai_cache_read_tokens=73472`（`cached_tokens` 映射）。
- `tests/integration/common/util.go` `clusterSubName` 新增 `cluster_nested_usage → nested_usage` 映射。
