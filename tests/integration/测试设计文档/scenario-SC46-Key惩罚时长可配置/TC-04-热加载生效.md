# TC-04 热加载生效（无需重启）

## 目的

验证惩罚时长是运行时配置：修改 `cluster_conf.data` 的 `SessionAffinityPenaltyTTLAuth`（120 → 60）后调用 `/reload/server_data_conf`，下一次惩罚写入立即使用新值，BFE 无需重启。

## 前置条件

- `cluster_penalty_ttl` 配 2 把 Key，`SessionAffinityPenaltyTTLAuth=120`；
- 上游对任意请求返回 401；
- miniredis 为空。

## 请求构造

同 TC-01。

## 后端响应

`401` + `{"error":"invalid api key"}`。

## 执行步骤

1. 启动 BFE（`auth=120`），发送 1 条请求，读取惩罚键 TTL（应约 120s）；
2. 用 `RedisServer.FastForward(121s)` 让惩罚键过期（不重启 BFE，也不删除键）；
3. 读取 `conf/cluster_conf/cluster_conf.data`，把该集群 `AIConf.KeyPolicy.SessionAffinityPenaltyTTLAuth` 改为 `60`，写回文件；
4. `GET http://127.0.0.1:<monitorPort>/reload/server_data_conf`，确认 reload 成功（响应体不含错误）；
5. 再发送 1 条请求，读取新的惩罚键 TTL。

## 预期结果

- 步骤 1：惩罚键 TTL 为 **120s**；
- 步骤 4：reload 成功（HTTP 200 且响应体无 `KeyPolicy` 相关错误）；
- 步骤 5：惩罚键 TTL 为 **60s**；
- 两次 TTL 不同即证明「改配置后新惩罚立即生效」，且 BFE 进程未重启（monitor 计数连续、无启动日志）。

## 清理

同 TC-01。若步骤 3 失败导致配置文件损坏，直接结束测试（临时目录随进程回收）。
