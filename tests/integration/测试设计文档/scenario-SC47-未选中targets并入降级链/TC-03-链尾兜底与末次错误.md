# TC-03 链尾兜底与末次错误

## 目的

验证两点：

1. 所有 targets（含未选中的兄弟 target）均失败后，配置在 fallbacks 中的集群才被尝试（链尾兜底）；
2. 全部尝试耗尽后，返回**最后一个 attempt** 的错误响应（"返回主选错误"优化未实施，维持现状语义）。

## 前置条件

- BFE 启动，路由规则 `target-fb-chain`：`targets=[cluster_ta:50, cluster_tb:50]`，`fallbacks=[cluster_fc]`；
- mock：三个 cluster 全部返回 500，且各自错误体带集群标识（如 `{"error":"500 from ta"}`）；
- 三个 cluster 初始命中数均为 0。

## 请求构造

| 字段 | 值 |
|------|-----|
| Method | POST |
| Host | `target-fb.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_target_fb`、`Content-Type: application/json` |
| Body | `{"model":"gpt-4"}` |

连续发送 20 条同构请求。

## 后端响应

| cluster | 行为 |
|---------|------|
| cluster_ta | 500 + `{"error":"500 from ta"}` |
| cluster_tb | 500 + `{"error":"500 from tb"}` |
| cluster_fc | 500 + `{"error":"500 from fc"}` |

## 执行步骤

1. 启动 BFE 与三个 mock 后端；
2. 连续发送 20 条请求；
3. 收集每条响应的 HTTP 状态码与错误体；
4. 读取三个 mock 的 `Hits()`。

## 预期结果

- 全部 20 条响应均为 500，错误体均为 `{"error":"500 from fc"}`——**最后一个 attempt（链尾 fallback）的错误透出**（若未来实施"返回主选错误"，此断言需相应改为首个 attempt 的错误）；
- `cluster_ta.Hits() + cluster_tb.Hits() + cluster_fc.Hits() == 60`：每条请求完整走完 `选中 → 兄弟 target → fallback` 全链，每个 cluster 恰好被尝试 1 次；
- 三个 cluster 的 Hits 均 `>= 1`：兄弟 target 与 fallback 均实际获得尝试机会（旧行为下未选中 target 的 Hits 为 0）。

## 清理

测试结束时关闭 BFE 与 mock 后端（`testEnv.Close()`）。
