# SC47 未选中 targets 并入降级链

## 1. 场景背景与目的

AI 路由规则（RouteRule）的 `targets` 是加权分流列表（权重和=100），`fallbacks` 是降级列表。旧行为中，BFE 每请求用 `SelectTarget` 加权随机**只选中一个** target 转发；该 target 所在集群整体失败后**直接**按 fallbacks 顺序降级，其余 targets 在同一请求内永远不会被尝试——多 targets 配置互不兜底，全部故障时流量直接涌向 fallbacks。

2026-11-12 的变更（`bfe/docs/zh_cn/modifications/2026-11-12-ai-route-targets-as-fallbacks/design-changes.md`）把未选中的其余 targets **按权重降序插入 fallbacks 之前**，构成统一尝试链：

```
attempts = [选中 target]
         + [未选中 targets 按权重降序，按 (cluster_name, model) 去重]
         + [fallbacks 按配置顺序，按 (cluster_name, model) 去重]
```

与 Bifrost 的负载均衡兜底语义对齐（`plugins/governance/main.go:624-651`）。去重针对的是 **targets↔fallbacks 跨组重复**——控制面契约（ai-gateway-api `00-common.md` §6）明确允许 `targets=[A/x:100]` + `fallbacks=[A/x, B/y]` 这类配置，同一 `(cluster_name, model)` 不允许在一次请求内被尝试两次。

本场景验证：

- 选中 target 故障时，未选中的兄弟 target 被尝试（targets 互为兜底），fallbacks 不被触及；
- targets 全部失败后才轮到 fallbacks；链尾兜底生效；
- 跨组重复（fallback 与选中 target 同 `(cluster_name, model)`）只尝试一次；
- 单 target 无 fallbacks 的旧行为完全不变（回归基线）；
- 全部尝试耗尽仍返回**最后一个 attempt** 的错误响应（"返回主选错误"优化不在本期）。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程 + 进程内 mock 后端（`common.MockBackend`）。
- 不启用 Key 亲和（无 `[AIKeyAffinity]` 配置、不涉及 Redis），排除 Key 轮换对降级链计数的干扰；每个集群配置单把 Provider Key 即可。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

| 文件 | 说明 |

| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_route`、`mod_ai_token_auth`、`mod_ai_rate_limit` |
| `mod_ai_route/mod_ai_route.conf` + `ai_route.data` | 定义 apikey 级路由与 targets/fallbacks 组合 |

| `cluster_conf/gslb.data` | gslb 权重 |
| `cluster_conf/cluster_table.data` | 运行时按 mock 后端地址生成 |
| `cluster_conf/cluster_conf.data` | 运行时生成，每集群一个 mock 后端 + 单把 Key |

## 4. 测试 Cluster 与关键配置

### 4.1 通用 Cluster 模板（每集群一份，按用例改名）

            {"Name": "key-a", "Key": "sk-key-a", "Weight": 100}

## 5. 测试例列表

| 编号 | 名称 | 核心验证点 |
|------|------|------------|
| TC-01 | 兄弟 target 兜底 | 选中项 500 时降级到未选中 target（200）返回；fallback 零命中；每条请求由兄弟 target 恰好服务一次 |
| TC-02 | 跨组重复去重 | fallback 与选中 target 同 `(cluster, model)` 时，该 cluster 全程只被尝试 1 次，请求最终由下一个 fallback（200）服务 |
| TC-03 | 链尾兜底与主选错误透出 | 两个 targets 均 500 后 fallbacks 被尝试；三个 cluster 各命中 1 次；全部尝试耗尽后透出**主选（首个 attempt）**的错误体 |
| TC-04 | 单 target 回归 | 单 target 无 fallbacks：500 直接返回，该 cluster 仅被尝试 1 次，行为与旧版一致 |

## 6. 每个测试例的详细说明

见同目录 `TC-01` ~ `TC-04` 独立文档。

## 7. 公共基础设施

1. `common/MockBackend`：`ResponseFunc` 按 cluster 返回定制状态码/响应体；`Hits()` 统计上游交互次数——本场景断言降级链走向的核心依据。
2. `common/BFEConfigBuilder`：按 `AIConfs` 生成 `cluster_conf.data`，按 `TokenRuleData` / `RateLimitPolicyData` 生成模块配置。
3. `common/ProcessEnv`：编译并启动真实 BFE 进程，自动分配端口。

## 8. 与其他场景的依赖关系

- 依赖 SC01 已验证的路由表查找与 apikey 绑定机制；
- 依赖 SC08 已验证的 fallback 时模型重算（model override）机制；
- 本场景不启用 Key 亲和，与 SC10/SC46 无依赖；计费、缓存场景无关。

## 9. 已知边界

- 选中哪个 target 是加权随机的：TC-01/TC-03 的断言基于"发多条请求后的**计数与响应归属**"，不要求指定选中项；若要强制选中某 target，无现成手段（`SelectTarget` 用 `rand.Intn`，测试不注入种子）。
- "未选中 targets 按权重降序"的严格顺序由 `bfe_server` 单测 `TestBuildAiForwardAttemptsRemainingTargetsWeightDescending` 覆盖，集成层只验证"targets 兜底优先于 fallbacks"。
- batch/文件透传禁用降级的既有行为（`isBatchPassthroughMode`）不在本场景重复验证，由既有 batch 场景守护。
