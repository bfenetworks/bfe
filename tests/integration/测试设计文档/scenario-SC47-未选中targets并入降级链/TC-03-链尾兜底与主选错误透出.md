# TC-03 链尾兜底与主选错误透出

## 目的

验证两点：

1. 所有 targets（含未选中的兄弟 target）均失败后，配置在 fallbacks 中的集群才被尝试（链尾兜底）；
2. 全部尝试耗尽后，返回**主选（首个 attempt）**的错误响应——fallback 的错误（如 model_not_found）不代表主路径故障性质，不应掩盖主选的真实故障。仅当主选 attempt 为纯传输错误（无响应）时才维持返回末次 attempt 的结果。

## 前置条件

- BFE 启动，路由规则 `target-fb-tc3`：`targets=[cluster_ta:50, cluster_tb:50]`，`fallbacks=[cluster_fc]`；
- mock：三个 cluster 全部返回 500，且各自错误体带集群标识（如 `{"error":"500 from ta"}`）；
- 三个 cluster 初始命中数均为 0。

## 请求构造

| 字段 | 值 |
|------|-----|
| Method | POST |
| Host | `tc3.target-fb.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_target_fb`、`Content-Type: application/json` |
| Body | `{"model":"gpt-4"}` |

连续发送 20 条同构请求。

## 后端响应

| cluster | 行为 |
|---------|------|
| cluster_ta | 500 + `{"error":"500 from ta"}` |
| cluster_tb | 500 + `{"error":"500 from tb"}` |
| cluster_fc | 500 + `{"error":"500 from fc"}` |

## 执行步骤

1. 启动 BFE 与三个 mock 后端；
2. 连续发送 20 条请求；
3. 收集每条响应的 HTTP 状态码与错误体；
4. 读取三个 mock 的 `Hits()`。

## 预期结果

- 全部 20 条响应均为 500，错误体为 `{"error":"500 from ta"}` 或 `{"error":"500 from tb"}`——即**主选（加权随机首个 attempt）**的错误透出，绝不透出链尾 fc 的（旧行为透出末次 attempt 的错误，该断言为新旧行为的区分点）；
- `cluster_ta.Hits() == cluster_tb.Hits() == cluster_fc.Hits() == 20`：每条请求完整走完 `选中 → 兄弟 target → fallback` 全链，每个 cluster 恰好被尝试 1 次；
- bfe.log 含 `fallback exhausted, return primary error` 日志，同时记录主选与末次 cluster/status。

## 清理

测试结束时关闭 BFE 与 mock 后端（`testEnv.Close()`）。
