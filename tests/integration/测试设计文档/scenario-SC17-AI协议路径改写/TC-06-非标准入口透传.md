# TC-06 非标准入口透传

## 用例编号与名称

TC-06 非标准入口透传

## 所属场景

SC17 AI 协议路径改写（AIConf.ProtocolPaths）

## 版本声明

- `bfe`：当前源码版本

## 测试目的

验证 `ProtocolPaths` 已配置时，**非标准入口路径仍永不改写**：

1. provider 原生路径（`/compatible-mode/v1/chat/completions`）——客户端按 provider 原生路径访问的透传模式不受影响；
2. 形似但不匹配的前缀（`/v10/xxx`）——标准入口判定（`reqPath == "/v1"` 或以 `"/v1/"` 开头）不会误伤。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程。

## 前置条件

`cluster_primary.AIConf`：

```json
{
    "Type": 0,
    "ModelProtocols": ["openai", "anthropic"],
    "ProtocolPaths": {"openai": "/api/v3"}
}
```

## BFE 请求

按序发送 2 次 openai 风格请求（Host `api.example.org`，`Authorization: Bearer ak_user_a`）：

| 序号 | 请求路径 | 判定 |
|------|----------|------|
| 1 | `/compatible-mode/v1/chat/completions` | 非标准入口（不以 `/v1` 开头） |
| 2 | `/v10/xxx` | 非标准入口（`/v10` 不等于 `/v1`，前缀判定不匹配） |

## 改写计算

两条请求均不满足 `isStandardV1Prefix`，落入透传分支：`upstream = reqPath`。第二条若误用 `strings.HasPrefix(path, "/v1")` 实现，会被 `/v10` 命中并改写成 `/api/v3/0/xxx`——本用例的断言能暴露该实现错误。

## 预期结果

| 断言 | 预期 |
|------|------|
| 两次响应状态码 | 200 |
| `cluster_primary` 后端收到的路径序列 | `[/compatible-mode/v1/chat/completions, /v10/xxx]`，与请求路径逐一相等 |
| `cluster_fallback` 命中数 | 0 |
