# SC17 AI 协议路径改写（AIConf.ProtocolPaths）

## 1. 场景背景与目的

不同 model provider 的上游路径各不相同，且同一 provider 的不同协议（OpenAI 兼容 / Anthropic 兼容）挂在不同前缀下（如百炼 `/compatible-mode/v1` vs `/apps/anthropic`、Kimi Code `/coding/v1` vs `/coding`、火山 `/api/v3` vs `/api/coding`）。`AIConf.ProtocolPaths` 允许按协议声明上游 API 基路径（该协议 SDK `base_url` 的 path 部分），BFE 在 `doSingleAIForward` 中将客户端入口路径（openai 兼容带 `/v1` 与不带 `/v1` 的标准端点、anthropic 的 `/v1/messages`）改写到该基路径。本场景验证：

- openai / anthropic 两种协议分别按配置改写（含双协议 cluster 独立改写）；openai 协议带 `/v1` 与不带 `/v1` 的客户端入口改写为**相同**上游路径（issue #1379：兼容 Trae 等直连 `base_url` 的客户端）；
- cluster 级 fallback 时，fallback cluster 从**原始客户端路径**重新计算上游路径，不继承主 cluster 的改写结果；
- 未配置 `ProtocolPaths` 时请求路径逐字节透传（向后兼容）；
- 非标准入口路径（provider 原生路径、`/v10/xxx`、gemini 风格路径）与未命中 openai 标准端点的路径永不被改写（透传模式不受影响）。

对应设计文档：`bfe/docs/zh_cn/sys_design/ai_protocol_paths.md`、`bfe/docs/zh_cn/modifications/2026-09-14-ai-protocol-paths-rewrite/design-changes.md`。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程。
- 不涉及 `ai-gateway-api` 与 `conf-agent`；`AIConf.ProtocolPaths` 由测试代码经 `BFEConfigBuilder` 直接写入生成的 `cluster_conf.data`。
- mock AI 后端通过 `common.MockBackend` 启动，新增 `URLPaths()` 观测点记录后端收到的请求路径。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 加载 `mod_ai_route`（不加载 `mod_ai_token_auth`，apikey 仅用于路由查找） |
| `mod_ai_route/ai_route.data` | apikey 级路由：`ak_user_a` 命中 `default_t()` 规则 → `cluster_primary`，fallback 至 `cluster_fallback` |
| `server_data_conf/host_rule.data` / `route_rule.data` / `vip_rule.data` | 产品线 Host、basic 路由（basic 路由引用 `cluster_default`）、VIP 配置 |
| `cluster_conf/gslb.data` | `cluster_primary` / `cluster_fallback` / `cluster_default` 的 subcluster 权重 |
| `cluster_conf/cluster_table.data` | 运行时根据 mock 后端地址动态生成 |
| `cluster_conf/cluster_conf.data` | 运行时动态生成，按测试例注入各 cluster 的 `AIConf`（含 `ProtocolPaths` 与 `ModelProtocols`） |

## 4. 测试 Cluster 与 AIConf 配置

所有测试例的 `cluster_primary` / `cluster_fallback` 均声明 `ModelProtocols: ["openai", "anthropic"]`（否则 anthropic 请求在协议匹配处被 `PROVIDER_PROTOCOL_MISMATCH` 拒绝）；`ProtocolPaths` 按测试例变化：

| 测试例 | cluster_primary ProtocolPaths | cluster_fallback ProtocolPaths |
|--------|------------------------------|-------------------------------|
| TC-01 openai 改写 | `{openai: /compatible-mode/v1}` | 无 |
| TC-02 anthropic 改写 | `{anthropic: /apps/anthropic}` | 无 |
| TC-03 双协议改写 | `{openai: /coding/v1, anthropic: /coding}` | 无 |
| TC-04 fallback 路径重算 | `{anthropic: /apps/anthropic}`（返回 503） | `{anthropic: /coding}` |
| TC-05 未配置透传 | 无（AIConf 为 nil） | 无 |
| TC-06 非标准入口透传 | `{openai: /api/v3}` | 无 |
| TC-07 无 /v1 入口改写（issue #1379） | `{openai: /compatible-mode/v1}` | 无 |
| TC-08 无 /v1 入口未配置透传（issue #1379） | 无（AIConf 为 nil） | 无 |
