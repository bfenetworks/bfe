# SC23 AI 缓存语义缓存

## 1. 场景背景与目的

`mod_ai_cache` 二期语义缓存在一期 Redis 精确匹配之上叠加向量相似度缓存：Redis 精确优先 → embedding 向量化 → Chroma 向量检索 → 阈值判定；响应阶段双写回（Redis 同步 + 向量异步）；embedding / 向量库任一故障 fail-open 降级为纯精确流程。本场景验证：

- 精确命中不触发 embedding 调用（第二次相同问题直接命中 Redis）；
- 换说法的问题（embedding 相似）命中语义缓存：`ai_cache_status=hit_semantic`、响应头 `X-Bfe-Ai-Cache: hit_semantic`、访问日志 `ai_cache_semantic`/`ai_cache_similarity`（791/792 字段，相似度与向量库实算一致）；
- 低于阈值（不相似向量）不命中，请求到达上游；
- 租户隔离：另一 API Key 问同一问题不命中语义缓存，查询 where 条件真实携带另一 `tenant_id`；
- embedding 服务故障（HTTP 500）降级为纯精确流程，主请求成功、精确缓存不受影响、向量库零写入；
- 流式（SSE）语义命中返回完整 SSE 序列（含 `data:[DONE]`）；
- 语义 TTL 过期：`created_at` 超期的向量记录被 where 条件过滤，不命中；
- 语义命中不计费：命中后配额计数不变。

embedding 与向量库（Chroma）一律使用进程内 mock 服务（`httptest`），不依赖外部组件。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程与内存 Redis 服务（miniredis），embedding / Chroma 为进程内 `httptest` mock。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_token_auth`、`mod_ai_route`、`mod_ai_cache`、`mod_access_pb3` |
| `mod_ai_route/ai_route.data` | 定义 apikey 级路由规则，命中 `cluster_cache` |
| `mod_ai_token_auth/mod_ai_token_auth.conf` | 指定 token 规则路径 |
| `mod_ai_cache/mod_ai_cache.conf` | 在 SC20 模板基础上新增 `[embedding]`/`[vector]` 段（host/port 为占位值，运行时由 builder 重写到 mock 地址） |
| `mod_access_pb3/mod_access_pb3.conf` | 访问日志（b2log），用于 789-792 字段断言 |
| `server_data_conf/host_rule.data` | 声明 `ai_product` 产品线对应的 Host `cache.example.org` |
| `server_data_conf/route_rule.data` | 默认路由到 `cluster_cache` |
| `cluster_conf/gslb.data` | GSLB 权重配置 |

> 说明：`mod_ai_cache_rule.data` 由测试代码按 `AiCacheRuleData` 动态生成，含顶层 `Semantic` 块（`topK=1`、`threshold=0.15`、`thresholdRelation=lt`）与 `enableSemanticCache=true` 的规则；Redis 连接通过 `name_conf.data` 映射到内存 Redis。

## 4. mock 服务设计

### 4.1 embedding mock（`common/mock_embedding_service.go`）

- 实现 OpenAI 兼容 `POST /v1/embeddings`：请求 `{model,input}`，响应 `{data:[{embedding:[...]}]}`（与 `provider/embedding/openai.go` 的解析严格对齐）。
- 关键字→向量脚本（最长关键字优先，同 `DecisionScript` 模式）：

| 关键字 | 问题 | 向量 |
|--------|------|------|
| `what is bfe` | what is bfe? | [1, 0, 0] |
| `introduce bfe` | could you introduce bfe to me please? | [0.99, 0.01, 0] |
| `cook rice` | how to cook rice at home? | [0, 1, 0] |
| （无匹配） | — | [0, 0, 1]（默认，远离所有脚本向量） |

- 相似度设计：`what is bfe` 与 `introduce bfe` 的 cosine distance ≈ 0.00005 < 0.15（语义命中）；与 `cook rice` 的 distance = 1.0（阈值外未命中）。
- 特性：并发安全调用计数（`Hits`/`Calls`）、强制故障开关（`SetFailAll` → HTTP 500）、请求体记录。

### 4.2 Chroma mock（`common/mock_chroma_service.go`）

- 实现 `provider/vector/chroma.go` 消费的 API 子集：
  - `GET /api/v1/heartbeat`
  - `POST /api/v1/collections`（get_or_create）
  - `POST /api/v1/collections/{name}/upsert`：内存存储 document/metadata/embedding
  - `POST /api/v1/collections/{name}/query`：对存储向量做**真实 cosine distance 计算**，升序取 topK；响应 `ids/distances/metadatas/documents` 按批量维度嵌套，与 chroma.go 的解析严格对齐
- where 表达式真实求值：`tenant_id $eq`（租户隔离）与 `created_at $gt`（TTL），支持 `$and`/`$or` 合取与 `$eq/$ne/$gt/$gte/$lt/$lte`。
- 特性：分端点并发计数器（heartbeat/collections/upsert/query）、故障开关（`SetFailAll` → HTTP 500）、无结果开关（`SetEmptyResults`）、查询 where 记录（`QueryFilters`，供租户隔离断言）、`UpsertRecord` 直接注入记录（用于注入"过期 created_at"记录）。

## 5. 测试例列表

| 编号 | 名称 | 核心验证点 |
|------|------|------------|
| TC-01 | 精确命中不触发 embedding | 首个请求 miss 触发 1 次 embedding 并写回向量库；相同问题第 2/3 次请求精确命中（`X-Bfe-Ai-Cache: hit`），embedding 零新增调用、向量库零新增查询 |
| TC-02 | 语义命中 | 换说法问题命中：`X-Bfe-Ai-Cache: hit_semantic`、上游仅 1 次、embedding=2/query=2；访问日志 `ai_cache_status=hit_semantic`、`ai_cache_semantic=true`、`ai_cache_similarity` 与 mock 实算 cosine similarity 一致（1e-9 精度） |
| TC-03 | 低于阈值未命中 | 不相关问题（distance=1.0 ≥ 0.15）miss，到达上游（backend=2） |
| TC-04 | 租户隔离 | apiKey2 同问题文本不命中（backend=2）；`QueryFilters` 断言第二次查询 where 携带 `tenant_id $eq cache_key_id_2`；apiKey2 再次请求命中自己的缓存项 |
| TC-05 | embedding 故障降级 | embedding mock 500：主请求成功（纯精确流程）、向量库零查询零写入、精确缓存读写不受影响 |
| TC-06 | 流式语义命中 | SSE 答案跨 chunk 累积并写回向量库；换说法流式请求命中语义缓存，返回完整 SSE 序列（含 `data:[DONE]`），上游仅 1 次 |
| TC-07 | 语义 TTL 过期 | 注入 `created_at` 为 2 小时前的记录（TTL=3600s），相同问题不命中过期答案，重新回源 |
| TC-08 | 语义命中不计费 | 有限 `total_token` 配额：miss 扣 18、语义命中不扣、再次 miss 再扣 18 |

## 6. 公共基础设施

本场景在 SC20 基建上增量扩展：

1. **`common/bfe_config_builder.go`**：`AiCacheRuleData` 支持顶层 `Semantic` 块与规则 `enableSemanticCache`；新增 `EmbeddingServiceAddr`/`VectorServiceAddr`，运行时重写 `mod_ai_cache.conf` 的 `[embedding]`/`[vector]` 段 host/port 指向 mock 服务（仿 `rewriteDecisionServiceAddr`）。对未使用该能力的既有场景（如 SC20）完全向后兼容。
2. **`common/mock_embedding_service.go` / `common/mock_chroma_service.go`**：新增 mock，不影响既有 mock。
3. 向量异步写回、配额异步扣减与 SC20 一样通过轮询断言消除竞态。

## 7. 与其他场景的依赖关系

- 复用 SC20 已验证的精确缓存、租户隔离、配额断言与 SSE 模式；
- mock 外部 HTTP 服务模式参照 SC22（httptest + 脚本 + 并发安全计数器 + 故障开关）；
- 设计规格见 `docs/zh_cn/modifications/2026-09-30-ai-cache-semantic-cache/design-changes.md` 13.2 节。
