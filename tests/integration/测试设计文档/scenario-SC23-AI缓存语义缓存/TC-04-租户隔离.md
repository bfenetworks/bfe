# TC-04 租户隔离

## 用例编号与名称

TC-04 租户隔离

## 所属场景

SC23 AI 缓存语义缓存

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_cache` 语义缓存二期）

## 测试目的

验证语义缓存的租户隔离：第二个 API Key 询问相同问题文本时，不得读到第一个租户（Key ID 不同）的向量记录；Chroma 查询的 where 条件必须携带请求方自己的 `tenant_id`。

## 运行模式

单组件模式：真实 `bfe` 进程 + 内存 Redis + 进程内 embedding mock / Chroma mock。

## 前置条件

1. 同 TC-01 前置条件 1-3。
2. token 规则含两个 API Key：`ak_cache`（KeyId=`cache_key_id`）与 `ak_cache2`（KeyId=`cache_key_id_2`），均绑定无限额配额计划。
3. Chroma mock 记录每次 query 的 where 表达式（`QueryFilters`），供租户断言。

## 配置构造

- 同 TC-01（`Semantic` 块 `topK=1`/`threshold=0.15`/`thresholdRelation=lt`，规则 `enableSemanticCache=true`）。

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `cache.example.org` | `/v1/chat/completions` | `Bearer ak_cache` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"what is bfe?"}]}` |
| 2 | 同上 | 同上 | `Bearer ak_cache2` | 同上（相同问题文本） |
| 3 | 同上 | 同上 | `Bearer ak_cache2` | 同上（再问一次） |

## 预期结果

- 第 1 步（key1 miss，播种）：`backend=1`；轮询确认 Chroma `upsert=1`（记录归属 key1 租户）。
- 第 2 步（key2 问相同问题）：
  - 返回 200，**无** `X-Bfe-Ai-Cache` 响应头（不得读到 key1 的语义记录）；
  - `backend=2`（到达上游）；`embedding=2`、`query=2`；
  - `QueryFilters` 共 2 条，第 2 条（key2 的查询）where 中 `tenant_id $eq cache_key_id_2`（支持 `$and` 合取形式的解析）。
- 第 3 步（key2 再问）：`X-Bfe-Ai-Cache: hit`（命中 key2 自己刚写入的记录）；`backend=2`（key2 的精确缓存生效）。

## 清理

停止 `bfe` 进程、mock 后端、embedding mock、Chroma mock 与内存 Redis，删除临时目录。
