# TC-06 终止事件前挂断仍记客户端中断

## 用例编号与名称

TC-06 终止事件前挂断仍记客户端中断（issue #1473 对照臂）

## 所属场景

SC12 客户端中断计费

## 版本声明

- `bfe`：当前源码版本 + issue #1473 修复

## 测试目的

验证 issue #1473 的修复**没有放宽中断语义**：客户端在协议终止事件之前关闭连接，仍然按客户端中断记录，且与 TC-05 可机检区分——

1. 访问日志 `err_code=CLIENT_WRITE`；
2. `proxy_state` 的 `ERR_CLIENT_WRITE` **增长**，`REQ_AI_CLIENT_CLOSED_AFTER_COMPLETE` **不增**；
3. 访问日志 `ai_client_closed_after_complete`（字段 816）**未置位**；
4. `err_msg` 是客户端侧文案（`client closed connection` 或 `client write failed`），**不是**上游读错误文本。

## 运行模式

单组件模式：真实 `bfe` 进程 + 嵌入式 Redis + mock SSE 后端 + 裸 TCP 客户端。

## 前置条件

1. 已编译含 issue #1473 修复的 `bfe`，并加载 `mod_access_pb3`。
2. mock 后端发送 `message_start → content_block_delta → message_delta(usage)` 后 **hold 住**，`message_stop` 放在 `SSETrailing`（客户端断开后才发）。

## 执行步骤

1. 启动 BFE 与 Redis。
2. mock 后端写入三个事件并 hold。
3. 客户端读到 `message_delta` 后**直接关闭连接**（终止事件尚未到达）。
4. 采样 `proxy_state` 计数器。
5. 停止 BFE 解析 pb3 访问日志，断言字段。

## 预期结果

- `ERR_CLIENT_WRITE` ≥ 1，`REQ_AI_CLIENT_CLOSED_AFTER_COMPLETE` = 0；
- 访问日志 `err_code=CLIENT_WRITE`、`ai_client_closed_after_complete` 未置位；
- `err_msg` ∈ {`client closed connection`, `client write failed`}。

## 清理

停止 `bfe`、Redis 与 mock 后端，删除临时目录。

## 备注

- 与 TC-05 的唯一差别是"终止事件是否已解析"，因此两条记录的区分完全落在 `err_code` 与字段 816 上，不依赖 `err_msg` 文本（满足 issue 判据 2 的"不得仅靠 err_msg"）。
- `err_msg` 允许两种取值：CloseWatcher 先看到 FIN 时为 `client closed connection`；若写失败先发生则为 `client write failed`。两者都指向客户端侧。
