# TC-05 完整投递后客户端挂断不记为写错误

## 用例编号与名称

TC-05 完整投递后客户端挂断不记为写错误（issue #1473）

## 所属场景

SC12 客户端中断计费

## 版本声明

- `bfe`：当前源码版本 + issue #1473 修复（AI 出口三态归因、`ai_client_closed_after_complete` 字段 816、`REQ_AI_CLIENT_CLOSED_AFTER_COMPLETE` 计数）
- 依赖 `bfe-access-pb` **v0.3.18**（字段 816）

## 测试目的

验证"响应已完整投递（协议终止事件已解析）后客户端才挂断"不属于客户端中断：

1. 访问日志 `err_code` **为空**（不再出现 `CLIENT_WRITE`），`err_msg` 也不再是形如 `BodyProcessError: read tcp ...` 的上游读错误文案；
2. `proxy_state` 的 `ERR_CLIENT_WRITE` **不增**，`REQ_AI_CLIENT_CLOSED_AFTER_COMPLETE` **+1**；
3. 访问日志携带 `ai_client_closed_after_complete=true`（字段 816），`ai_stream_truncated` **不置位**；
4. 计费与正常完成一致（`ai_usage_source=parsed`，实际 usage）。

对应设计条款：`ai_error_codes.md` §2.4（`CLIENT_WRITE` = 客户端中断）、`ai_access_log_fields.md` §1.2-1、以及 #1415 的对偶原则。

## 运行模式

单组件模式：真实 `bfe` 进程 + 嵌入式 Redis + mock SSE 后端 + 裸 TCP 客户端。

## 前置条件

1. 已编译含 issue #1473 修复的 `bfe`，并加载 `mod_access_pb3`（本用例起为该场景开启，用于断言访问日志）。
2. cluster 为 anthropic 协议（`/anthropic/v1/messages`），`EstimateToken = true`。
3. mock 后端按 `message_start → content_block_delta → message_delta(usage) → message_stop` 顺序发送，并在终止事件后**保持连接不关**（`SSEHold`）。

> 保持连接不关是复现的关键：生产上上游常以 keep-alive 保持连接，客户端的 FIN 才是结束拷贝的唯一事件，CloseWatcher 路径因此可确定复现；若后端在终止事件后立即关闭，BFE 会先读到 clean EOF 而走正常完成路径。

## 执行步骤

1. 启动 BFE 与 Redis，配额充足。
2. mock 后端写入四个 Anthropic 事件并 hold 住流。
3. 客户端用裸 TCP 发起流式请求，读到 `message_stop` 后**直接关闭连接**（不等 chunked 终止块）。
4. 采样 `proxy_state` 计数器。
5. 断言计费。
6. 停止 BFE 解析 pb3 访问日志，断言字段。

## 预期结果

- `REQ_AI_CLIENT_CLOSED_AFTER_COMPLETE` = **1**，`ERR_CLIENT_WRITE` = **0**；
- 剩余配额 = 初始配额 −（prompt 320 × 452 + completion 150 × 2262），与 TC-03 完全一致；
- 访问日志：`err_code` 为空、`err_msg` 为空、`ai_client_closed_after_complete=true`、`ai_stream_truncated` 未置位、`ai_usage_source=parsed`。

## 清理

停止 `bfe`、Redis 与 mock 后端，删除临时目录。

## 备注

- 修复前的表现：`err_code=CLIENT_WRITE`、`ERR_CLIENT_WRITE+1`、`err_msg` 为 `BodyProcessError: read tcp ...`、访问日志写入 `req_err_*` 错误流。
- 实现落地时相对方案收紧了一处：只有 CloseWatcher 判定"客户端已关"才降级为"完整投递后挂断"；**写失败**（最后一批字节可能未送达）仍记 `CLIENT_WRITE`，`err_msg` 为 `client write failed`。
- 实施中发现并修掉一个真实缺陷：anthropic 适配器的线级终止标记是 `event: message_stop`，只发 `data:` 行的兼容实现匹配不到，会在 clean EOF/中断时被误标为截断并注入错误事件。现以"事件解析器已判完成"为线级标记的权威来源（`streamTruncationInjector.terminated()`）。
