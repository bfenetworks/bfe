# SC12 客户端中断计费（issue #1352 / #1478）

## 1. 场景背景与目的

本场景验证 BFE issue #1352 与 #1478 在真实 BFE 进程中的行为：

- **#1352（已完成）**：EstimateToken = true 时，客户端在 SSE 流式响应早期发送 TCP RST 中断，BFE 不得按完整请求体估算输入 token 并全量扣费；已收到最终 usage 后中断仍按实际 usage 计费。
- **#1478（本场景的重点改造）**：在 #1352 的安全侧改向——客户端中断且未拿到最终 usage 时，**按已转发内容估算计费**（鉴权期 prompt 播种 + 逐 chunk 已转发内容累加），后端未生成/未交付给客户端的内容不计费；`EstimateToken = false` 时保留零扣费并保留全部信号。计费臂与零扣费臂由两个 env 对照覆盖（同一模板仅翻转 `EstimateToken`）。

issue #1352/#1478 与 SC11 覆盖的 #1343/#1344/#1345 相关但独立：

- **SC11（#1343/#1344/#1345）**：cache token 归一化、`count_tokens` 端点豁免、重复扣费幂等。
- **本场景（#1352/#1478）**：请求完成判定与估算计费的边界——中断未拿到最终 usage 时的估算口径（按已交付内容）、估算关闭时的零扣费信号；已收到最终 usage 后中断仍按实际 usage 计费。

同时验证两个配套修复：

- Anthropic 流式初始 usage 位于 `message_start.message.usage`（此前只解析顶层 `usage`）。
- `message_delta` 只携带输出 token，需与 `message_start` 的输入 token 合并计费（此前 `message_start` 之后到达的最终 usage 会被忽略）。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，并启动内存 Redis 服务（由测试框架提供）。
- mock 后端支持 SSE 流式响应：先发送 `SSEEvents` 并 flush，随后阻塞在 `SSEHold` 上；释放后可追加发送 `SSETrailing`，用于模拟客户端中断后后端继续推数据的场景。
- 客户端使用裸 TCP 连接（`http.ReadResponse` 解析 chunked SSE），中断时设置 `SO_LINGER=0` 发送 TCP RST。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。
- **估算开关双 env**：TC-01~03 使用 `EstimateToken = true` 模板；TC-04 使用同一模板的 `EstimateToken = false` 变体（`newTestEnvWithEstimateToken(t, false)`，Build 后改写 bfe.conf）。

## 6. 关键实现细节

- `EstimateToken = true` 使请求鉴权阶段按请求体长度播种输入 token 估算值（`mod_ai_token_auth.go` `tokenFoundProductHandler`），是估算计费的前提；`mod_body_process` 在产品规则匹配时逐 chunk 累加已转发内容（无规则时不安装处理器、估算累加不发生，模板已内置 `default_t()` 规则）。
- 中断感知有两条路径：SSE 响应恒开 `cancelOnClientClose`，客户端 RST 后 CloseWatcher 关闭上游 body → 读错误 → 按客户端中断归因（主路径，TC-01/TC-02/TC-04 依赖它）；TC-04 另外在释放 `SSEHold` 后追加 1MB 大帧强制写失败（`ECONNRESET`），覆盖写错误路径。
- **注入帧计入估算**：关闭上游 body 会被 issue #1474 的 `streamTruncationInjector` 观察为"中途断流"，向客户端流补发一个协议错误事件帧；该帧进入同一读取路径并被 `QuotaUsageProcessor` 计入 completion 估算（约 33 token）。这是"按转发字节估算"口径的既定近似，TC-01 的期望金额显式预算该帧（与 bfe SC29 TC-07/08 口径一致）。
- 不含 usage 的中断形态下，计费完全由估算兜底决定：`promptEst = 请求体/4`、`completionEst = Σ(各事件 data 长度/4)`（逐事件整数除法）。若中断前已出现携带 usage 的帧（如带 `input_tokens` 的 `message_start`），则该观测值优先（TC-02 形态），估算不再叠加。
- TC-04 的 `EstimateToken=false` env 与 TC-01~03 共用同一 `testdata` 模板，`Build` 后把 `bfe.conf` 中的 `EstimateToken = true` 改写为 `false`（`newTestEnvWithEstimateToken`），避免复制整套静态配置。
- 计数器断言经 BFE `monitor` 端口的模块指标读取（`common.ModuleMetric` / `WaitForModuleMetric`）；扣费断言读取内存 Redis 中的 `quota:plan_rmb`。
