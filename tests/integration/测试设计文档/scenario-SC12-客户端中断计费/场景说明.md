# SC12 客户端中断计费（issue #1352）

## 1. 场景背景与目的

本场景验证 BFE issue #1352 的修复在真实 BFE 进程中的行为：EstimateToken = true 时，客户端在 SSE 流式响应早期（仅收到 `message_start`）发送 TCP RST 中断请求，BFE 不得按完整请求体估算输入 token 并全量扣费。

issue #1352 与 SC11 覆盖的 #1343/#1344/#1345 相关但独立：

- **SC11（#1343/#1344/#1345）**：cache token 归一化、`count_tokens` 端点豁免、重复扣费幂等。
- **本场景（#1352）**：请求完成判定与估算计费的边界——`ErrClientWrite` 且未收到最终 usage 时禁止估算扣费；已收到最终 usage 后中断仍按实际 usage 计费。

同时验证两个配套修复：

- Anthropic 流式初始 usage 位于 `message_start.message.usage`（此前只解析顶层 `usage`）。
- `message_delta` 只携带输出 token，需与 `message_start` 的输入 token 合并计费（此前 `message_start` 之后到达的最终 usage 会被忽略）。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，并启动内存 Redis 服务（由测试框架提供）。
- mock 后端支持 SSE 流式响应：先发送 `SSEEvents` 并 flush，随后阻塞在 `SSEHold` 上；释放后可追加发送 `SSETrailing`，用于模拟客户端中断后后端继续推数据的场景。
- 客户端使用裸 TCP 连接（`http.ReadResponse` 解析 chunked SSE），中断时设置 `SO_LINGER=0` 发送 TCP RST。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 6. 关键实现细节

- `EstimateToken = true` 使请求鉴权阶段按请求体长度播种输入 token 估算值（`mod_ai_token_auth.go` `tokenFoundProductHandler`），是复现 issue 多扣费的必要条件。
- 客户端 RST 后，mock 后端追加一个大体积 `content_block_delta` 帧（1MB），强制 BFE 向已关闭的连接写入时收到 `ECONNRESET`，从而设置 `ErrClientWrite`（与线上抓包一致）。
- 即使 BFE 未设置 `ErrClientWrite`（如后端直接 EOF），修复后的估算守卫（响应未完成时 `EstimateToken` 不生效）同样保证零扣费，TC-01 断言对两条路径均成立。
