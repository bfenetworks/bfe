# TC-05 多问题组合条件

## 用例编号与名称

TC-05 多问题组合条件

## 所属场景

SC22 AI 意图路由

## 版本声明

- `bfe`：当前源码版本（含 `mod_ai_intent`）

## 测试目的

验证多问题组合条件（与）：规则 3 要求 task_type=doc_writing 且 complexity∈{simple,medium} 同时成立。prompt「写文档」→ doc@0.95 + medium@0.90，两条件均满足 → `cluster_flash`；prompt「写设计文档」→ doc@0.90 + complex，complexity 选项不在规则集合内 → 规则 3 不命中 → 规则 4 `cluster_kimi`。

## 运行模式

单组件模式：真实 `bfe` 进程 + mock 上游后端（`cluster_flash` / `cluster_kimi`）+ mock 决策服务（测试进程内 `httptest.Server`）。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. mock 决策服务已启动，`Calls()` 计数清零，「写文档」脚本返回 doc_writing@0.95 + complexity score=1（medium，probabilities.medium=0.90）；「写设计文档」脚本返回 doc_writing@0.90 + complexity score=2（complex，probabilities.complex=0.88）。
3. mock 后端 `cluster_flash`、`cluster_kimi` 已启动，`Hits()` 计数清零。
4. 临时 BFE 配置已生成并加载（同 TC-01）。
5. `ak_intent` 绑定无限额配额计划。

## 配置构造

- 路由表 `apikey_ak_intent`（场景说明 §4.3）：规则 3 `req_ai_intent_in("task_type", "doc_writing") && req_ai_intent_in("complexity", "simple|medium")` → `cluster_flash`；规则 4 `default_t()` → `cluster_kimi`。

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `intent.example.org` | `/v1/chat/completions` | `Bearer ak_intent` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"帮我写文档，说明这个模块的用法"}]}` |
| 2 | `intent.example.org` | `/v1/chat/completions` | `Bearer ak_intent` | `{"model":"deepseek-chat","messages":[{"role":"user","content":"帮我写设计文档，梳理整体架构"}]}` |

> 注：「写设计文档」按长关键词优先匹配，不会命中「写文档」脚本。

## 预期结果

- 步骤 1 返回 200，响应体含 `from cluster_flash`；`cluster_flash` `Hits()=1` → 规则 3 命中（doc_writing 0.95≥0.6；medium 0.90≥0.7）。
- 步骤 2 返回 200，响应体含 `from cluster_kimi`；`cluster_kimi` `Hits()=1` → 规则 3 第一个条件成立（doc_writing 0.90≥0.6）但第二个条件不成立（complexity=complex ∉ {simple,medium}），落到规则 4。
- mock 决策服务 `Calls()=2`（每次请求各分类一次；同请求内两个 `req_ai_intent_in` 求值仅触发一次分类，Resolved 标记防重）。

## 清理

停止 `bfe` 进程、mock 后端与 mock 决策服务，删除临时目录。
