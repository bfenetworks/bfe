# SC29 usage 抹零修复与 include_usage 注入（issue #1398）

## 1. 场景背景与目的

本场景验证 BFE issue #1398 的修复在真实 BFE 进程中的行为。issue #1398：无 final usage 的清零块将 `TokenUsage` 全部字段置 0，而访问日志（mod_access_pb3）与计费扣减读同一对象，导致后端真实产出 token 的请求（实测 TTFT 全部 > 0）在统计明细与计费中落成 `total_tokens=0`（某小时 200 响应的 42.7%）。

修复包含四个部分，本场景覆盖前三个的端到端行为：

1. **计费/统计视图隔离**：请求结束阶段的"不可计费"清零守卫只作用于计费副本，共享 `TokenUsage`（日志视图）保留真实解析值/批准口径的估算值，不再静默记 0；
2. **OpenAI 流式自动注入 `stream_options.include_usage`**（`Server.InjectStreamUsage`，出厂默认 true）：客户端未显式设置时注入，从上游拿到真实 final usage chunk；
3. **`EstimateToken` 出厂默认改 true**：与"缺 Usage 按 ContentLength/4 估算"的既定口径（SC1301-TC044 判例）一致，估算兜底在"完成但无 usage"时生效；
4. final-usage 判定去掉 `CompletionTokens > 0` 前置（`output_tokens=0` 的最终事件也算 final）——由单元测试覆盖（`TestSSEEventGetQuotaUsage_CompletionFlags` 的 "openai final usage chunk zero completion" 臂），集成侧随 TC-01 链路间接生效。

与既有场景的关系：

- **SC03/SC11/SC12**：RMB 计费、计费修复、客户端中断计费（#1352）。本场景不重复其断言，运行回归时全部执行。
- **SC05**：访问日志字段。本场景聚焦 `ai_input_tokens` / `ai_output_tokens` / `ai_total_tokens` 在"不可计费守卫触发"时的保留行为。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程与内存 Redis（测试框架提供），mock 后端为 `httptest.Server`。
- 需要加载 `mod_access_pb3` 以断言 pb3 访问日志字段（参照 SC05 的 testdata 配置）。
- 客户端：TC-01/TC-02 使用普通 HTTP 客户端完整读取 SSE 流；TC-03 使用裸 TCP + `SO_LINGER=0` RST（复用 SC12 模式）。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 6. 关键实现细节

- **注入断言点**：mock 后端 `RequestBodies()` 捕获的收包体，用 gjson 读 `stream_options.include_usage`；TC-01 必须为 true（JSON 布尔），TC-02 必须为 false 且其余字段未被改写。
- **日志断言点**：停止 BFE 后 `common.ParseAccessLogAfterStop(logDir)` 解析 pb3 日志，取最后一条记录断言 `AiInputTokens` / `AiOutputTokens` / `AiTotalTokens`。
- **扣费断言点**：内存 Redis `quota:plan_rmb` 余额。TC-01 精确值；TC-02 按估算口径（请求体长度/4 与 SSE 事件长度/4，测试内用与实现相同的公式计算）；TC-03 余额不变。
- **估算口径**（TC-02）：prompt = 鉴权阶段原始请求体字节数/4（`tokenFoundProductHandler` → `GetPromptToken`）；completion = 流式过程中各 SSE 事件 data 长度/4 累加（`QuotaUsageProcessor`，含 `[DONE]` 事件）。
- TC-03 中 BFE 向已关闭连接写入 1MB 帧触发 `ErrClientWrite`（与 SC12 相同机制），`tokenRequestFinishHandler` 中断早退（零扣费）；日志视图的 input 估算由鉴权阶段播种、不再被守卫抹零。
