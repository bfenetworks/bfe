# TC-09 上游断流估算关闭时零扣费但保留信号

## 用例编号与名称

TC-09 上游断流估算关闭时零扣费但保留信号（issue #1474，信号链 issue #1410/#1414/#1480）

## 所属场景

SC29 usage 抹零修复与 include_usage 注入

## 版本声明

- `bfe`：当前源码版本（含 issue #1474 修复）

## 测试目的

验证 `EstimateToken=false` 时上游流中途死亡形态的处理：估算被关闭，断流请求**不可计费**（零扣费，#1352"未拿到 final usage 不估算"口径在上游断流臂保持），但绝不静默——必须保留三重信号：

1. 访问日志 `ai_usage_source=unrecognized`（usage 未识别）；
2. `ai_zero_cost_reason=upstream_dropped`（零成本归因专属原因码，区别于一般 unrecognized 与客户端 abort）；
3. `err_code=BK_READ_RESP_BODY`（读侧归因，不误报客户端写失败）。

同时验证（issue #1480）：不可计费的断流行仍输出完整三元组（`ai_total_tokens = ai_input_tokens + ai_output_tokens`），"字段缺席"与"用量为 0"保持可区分，对账不依赖跨字段矛盾签名。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. 嵌入式 Redis 已启动，并预置 `quota:plan_rmb = 10000000000`。
3. mock 后端 `cluster_usage_snapshot` 已启动，SSE 返回 1 个 content chunk 后突然中止连接（`SSEAbortAfter = 1`，kill -9 形态）。
4. `ak_user_a` 绑定 RMB 配额计划 `plan_rmb`；生成配置写入 `EstimateToken = false`（`rewriteEstimateToken`）。

## 配置构造

- 模型价格：`deepseek-chat`，`input_cost_per_token: 0.000003`、`output_cost_per_token: 0.000009`。

## BFE 请求

发送 1 次 POST 请求：

| 字段 | 值 |
|------|-----|
| Host | `usage.example.org` |
| Path | `/v1/chat/completions` |
| Authorization | `Bearer ak_user_a` |
| Body | `{"model":"gpt-4","stream":true,"messages":[{"role":"user","content":"hi"}]}` |

客户端使用容错读取（容忍流末尾的传输错误）。

## 预期结果

- 响应状态码：200。
- Redis `quota:plan_rmb` 余额**不变**（EstimateToken=false 时断流不可计费）。
- 访问日志：
  - `ai_total_tokens = ai_input_tokens + ai_output_tokens`（三元组完整，非字段缺席）；
  - `ai_usage_source=unrecognized`（不可计费形态保留 usage 未识别信号）；
  - `ai_zero_cost_reason=upstream_dropped`（专属归因，区别于客户端 abort 的 `aborted`）；
  - `err_code=BK_READ_RESP_BODY`。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录。
