# TC-03 客户端中断零扣费且日志保留观测值

## 目的

验证 issue #1398 的统计视图隔离在客户端中断场景下的行为：OpenAI 流式请求被客户端 RST 中断、无 final usage 时，计费侧零扣费（issue #1352 语义不变），但访问日志保留鉴权阶段播种的 prompt 估算值——**清零守卫不得抹掉日志视图的分项**。

issue 实测数据中 abort 特征行（`err=CLIENT_WRITE` 且分项有值）仅 6 条，说明旧实现中断路径（早退不清零）保留了分项；而守卫路径会把 input/cache 等已解析分项一并抹零。本 TC 同时约束中断早退路径不因后续重构退化为抹零。

对应实现：`TestTC03_ClientAbortKeepsLogViewZeroDeduction`（`scenario-SC29-usage-snapshot-billing/sc29_usage_snapshot_billing_test.go`）。

## 前置条件

- BFE 已启动并加载 `cluster_usage_snapshot`，`EstimateToken = true`、`InjectStreamUsage = true`，加载 `mod_access_pb3`。
- Redis 中 `quota:plan_rmb` 余额预置为 `10000000000`。
- mock 后端 SSE 模式：发送 content chunk 后阻塞在 `SSEHold`；释放后追加 1MB 帧强制 BFE 写客户端失败（`ErrClientWrite`，与 SC12 相同机制）。

## 请求构造

| 字段 | 值 |
|------|-----|
| Method | `POST` |
| Host | `usage-billing.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_user_a` |
| Header | `Content-Type: application/json` |
| Body | `{"model":"gpt-4","stream":true,"messages":[{"role":"user","content":"hi"}]}` |
| 连接 | 裸 TCP；收到 content chunk 后 `SO_LINGER=0` RST 中断 |

## 后端响应（SSE）

```
data: {"id":"chatcmpl-1","choices":[{"delta":{"content":"hello"}}]}

（阻塞，直至客户端中断后释放）

data: {"id":"chatcmpl-1","choices":[{"delta":{"content":"<1MB 填充>"}}]}
```

## 执行步骤

1. 启动 BFE、mock 后端与内存 Redis，预置余额。
2. 客户端通过裸 TCP 发送请求，读取 SSE 数据直至出现 content chunk。
3. 客户端设置 `SO_LINGER=0` 后关闭连接（TCP RST）。
4. 释放 `SSEHold`，后端追加 1MB 帧，BFE 写客户端失败（`ErrClientWrite`）。
5. 等待请求结束（扣减同步发生在 finish handler，sleep 1.5s 后查 Redis）。
6. 停止 BFE，`common.ParseAccessLogAfterStop(logDir)` 解析 pb3 日志。

## 预期结果

- Redis 余额不变（`remaining = 10000000000`，中断且未拿到 final usage → 零扣费，issue #1352）。
- pb3 日志（该请求）：`ai_input_tokens = 原始请求体字节数 / 4 > 0`（鉴权估算保留），`ai_total_tokens = 0`（未扣费，无 final usage）；`err_code` 为客户端写失败。
- 修复前守卫行为：若该请求落入清零块（非早退路径），`ai_input_tokens` 会被一并抹 0——本断言防回归。

## 清理

- 停止 BFE、关闭 mock 后端与 Redis。
