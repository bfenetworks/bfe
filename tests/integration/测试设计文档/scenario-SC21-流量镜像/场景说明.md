# SC21 流量镜像（mod_traffic_mirror）

## 1. 场景背景与目的

`mod_traffic_mirror` 在 AI 网关转发的同时，把请求的一份副本（方法、路径、Header、Body，可按规则改写）异步发往镜像目标集群，响应完整读空后丢弃，仅用于统计与验证。本场景验证该模块在真实 BFE 进程中的端到端行为：

- 规则命中后镜像副本与生产请求的一致性（body/path/header），Header 黑名单剔除与标识头注入；
- body `model` 字段改写、路径改写、自定义头注入；
- 百分比采样（0 / 100 / 50 统计分布）；
- 条件不匹配不镜像；
- AI fallback 重试时同一请求只镜像一次；
- SSE 流式响应完整读空至 `[DONE]`，并解析 `usage` / `finish_reason`；
- 镜像目标返回 OpenAI 错误 JSON 时的错误分类指标；
- 镜像目标连续失败触发熔断、冷却期丢弃、冷却后探测；
- 镜像响应超过读取上限时截断丢弃并计数；
- 客户端断连后镜像请求继续读完（样本完整性）；
- 访问日志记录 `mirror_hit` / `mirror_cluster`（异步结果不回写，镜像状态字段保持空）；
- 镜像规则文件热加载生效；
- 镜像流量不触发 token 配额扣减（计费隔离）。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程，并启动嵌入式 Redis 服务（`mod_ai_token_auth` 依赖）。
- 镜像目标、生产上游均为测试框架的 mock 后端；熔断场景使用指向已关闭端口的静态后端。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_logid`（注入 LogId）、`mod_ai_token_auth`、`mod_ai_route`、`mod_traffic_mirror`、`mod_body_process`、`mod_access_pb3` |
| `mod_ai_route/ai_route.data` | `ak_mirror` 路由：`targets=[cluster_primary]`，`fallbacks=[cluster_fallback]` |
| `mod_traffic_mirror/mod_traffic_mirror.conf` | 模块基础配置；`CircuitBreaker*` / `MaxResponseBodyBytes` 等由测试用例按需改写 |
| `mod_traffic_mirror/mirror_rule.data` | **由测试代码运行时生成**（每个 TC 独立构造规则），便于控制 cond/percentage/改写/超时 |
| `mod_ai_token_auth/token_rule.data` | 由测试代码运行时生成（`ak_mirror` + 配额计划） |
| `mod_access_pb3/mod_access_pb3.conf` | protobuf 访问日志（`pb_access3.log`） |
| `server_data_conf/host_rule.data` | 声明 `ai_product` 产品线对应 Host `mirror.example.org` |
| `cluster_conf/cluster_table.data` / `cluster_conf.data` | 运行时根据 mock 后端地址动态生成（含静态死端口后端） |

观测手段：

- 模块 Prometheus 指标：`GET /monitor/mod_traffic_mirror.prometheus`（如 `req_labeled_total{product,cluster,model}`、`skip_total{reason}`、`resp_status_total{cluster,status}`、`finish_reason_total{cluster,reason}`、`tokens_total{cluster,kind}`、`error_type_total{cluster,type,code}`、`fail_total{cluster,reason}`、`circuit_open_total{cluster}`、`resp_truncated_total{cluster}`、`inflight{cluster}`）；
- 规则热加载：`GET /reload/mod_traffic_mirror?path=<绝对路径>`；
- mock 后端计数：命中次数、请求体、model 字段、Authorization/Cookie/X-Api-Key、`X-Bfe-Mirror`、`X-Bfe-Logid`、路径与 query；
- 访问日志解析：`common.ParseAccessLog` 解码 `pb_access3.log`。

## 4. 测试 Cluster 拓扑

| Cluster | 角色 | 后端 |
|---------|------|------|
| `cluster_primary` | 生产上游（主 target） | mock 后端，默认 200 + 固定答案（含 usage） |
| `cluster_fallback` | 生产上游（fallback target） | mock 后端，200 |
| `cluster_mirror` | 镜像目标 | mock 后端，各 TC 自定义响应（JSON / SSE / 错误 / 大 body） |
| `cluster_mirror_dead` | 熔断用镜像目标 | 静态后端，指向已关闭端口（连接即拒绝） |

## 5. 测试用例一览

| 编号 | 名称 | 验证点 |
|------|------|--------|
| TC-01 | 基本命中与复制一致性 | 镜像副本 body/path/model 与生产一致；Authorization/Cookie/X-Api-Key 被剔除；注入 `X-Bfe-Mirror`/`X-Bfe-Logid`；主链路 header 不受影响；主响应不受影响 |
| TC-02 | body model 改写与路径改写 | 镜像 body model 改为 `shadow-v3`，路径整体替换且 query 保留；`setHeaders` 注入；生产侧保持原值 |
| TC-03 | 采样比例 0 不镜像 | 5 次请求全部跳过，`skip_total{reason="sample"}=5` |
| TC-04 | 采样比例 100 全量镜像 | 5 次请求全部镜像，镜像后端命中 5 次 |
| TC-05 | 采样比例 50 统计分布 | 200 次请求落在 100±40（约 ±5σ，防 flaky） |
| TC-06 | 条件不匹配不镜像 | cond 为其他路径前缀，镜像后端 0 命中且无镜像指标 |
| TC-07 | fallback 重试去重 | 主 cluster 503 → fallback 200；同一请求镜像恰好 1 次 |
| TC-08 | SSE 读空与 usage/finish_reason | 镜像后端 SSE 到 `[DONE]`；`finish_reason_total{stop}=1`、`tokens_total` prompt=7/completion=5 |
| TC-09 | 镜像错误分类 | 镜像后端 429 + OpenAI error JSON；`error_type_total{type,code}=1`、客户端无感 |
| TC-10 | 熔断与冷却 | 阈值 3：3 次失败熔断，冷却期内丢弃并计 `circuit_open_total`，主链路全 200；冷却后探测再次失败 |
| TC-11 | 响应截断 | 镜像响应 256KB > 上限 64KB；`resp_truncated_total=1` 且状态码仍计数 |
| TC-12 | 客户端断连镜像继续读完 | 客户端收首帧后断连；镜像后端仍收到完整请求并在断连后完成读空计数 |
| TC-13 | 访问日志镜像字段 | `pb_access3.log` 中 `MirrorHit=true`、`MirrorCluster` 正确、`MirrorStatus` 保持空 |
| TC-14 | 规则热加载 | p=0 → 热加载改 p=100 → 行为切换，reload 返回新 Version |
| TC-15 | 计费隔离 | 主请求扣 18 tokens；镜像 usage（99+77）不产生任何扣减 |

## 6. 公共前置条件

1. 已编译 `bfe` 可执行文件（首次运行自动编译并缓存）。
2. 嵌入式 Redis 已启动，`ak_mirror` 绑定配额计划。
3. 临时 BFE 配置已生成，`mirror_rule.data` 按用例构造。
4. 每个 TC 独立启动/停止 BFE 进程，互不影响。

## 7. 清理

每个 TC 结束后停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录（`t.TempDir()` 自动清理）。
