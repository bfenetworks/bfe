# SC31 EPP 非调度参数热更新

## 1. 场景背景与目的

本场景验证 BFE EPP（ext-proc）路径的**非调度类参数**在 `cluster_conf.data` + `/reload/server_data_conf` 热更新后的生效语义，对应设计文档 `bfe/docs/zh_cn/modifications/2026-10-10-epp-nonschedule-args-reload/design-changes.md`（issue #218）。

设计引入 **运行时签名 `runtimeSignature`**：把"是否重建 EPP runtime"的判据从"只看地址表"升级为
`addrs + EPPTLS{Insecure,CAFile,Plaintext} + EPPTimeout.Connect + EPPCheck.Disabled`。签名变化即**重建 runtime**
（新 `tlsConf`、新 data 连接、按新值起停 `healthLoop`），旧 runtime 走既有 grace-retire 平滑切换；
地址表未变时通过 `inheritStateFrom` 继承 `active`/`health`，避免 failover 状态丢失与抖动。其余"读取型"参数
（`EPPTimeout.Call`、`EPPCheck` 滞回）仍原地 `updateConf`；`eppBreaker.updateConf` 在配置未变时提前返回，避免
每次 reload 清空熔断窗口。

本场景以**真实 BFE 进程**验证该行为，覆盖设计中 D1–D5：

| 编号 | 问题 | 本场景用例 |
| --- | --- | --- |
| D1 | `EPPTLS` 热变更不生效（data 连接仍用旧凭据） | TC-01 |
| D2 | `Plaintext=true→false` 时 `rt.tlsConf` 仍为 nil | TC-02 |
| D3 | `EPPCheck.Disabled` 热切换不生效 | TC-03 |
| D4 | `EPPTimeout.Connect` 对已有连接不生效 | TC-07（重建 + 状态继承） |
| D5 | 每次 reload 无条件清空熔断窗口 | TC-05 |
| — | `Disabled=true` + `Plaintext=true` 组合（issue #218 生产形态） | TC-08 |
| — | `EPPBreaker.Disabled=true` + `Plaintext=true` 组合（issue #218 生产形态） | TC-09 |
| — | 读取型参数原地生效 | TC-04 |
| — | 拓扑型 `EPPAddr` 变更重建 | TC-06 |

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程；EPP 为进程内 mock（gRPC server，监听 127.0.0.1 随机端口），后端为进程内
  `httptest` mock backend；不依赖 `ai-gateway-api`、`conf-agent` 与 `llm-d-inference-sim`。
- 本场景启用 AI 网关模块（`EnableAiGateway = true`，`Modules = mod_ai_route`）：请求携带 API Key
  （`Authorization: Bearer ak_epp`），经 apikey/global 路由表命中 `cluster_epp_reload`。
- `cluster_conf.data` 由 harness 按 `EPPClusterConf` 生成（`BalanceMode=EPP`）；`cluster_table.data` 指向 mock backend。
  热更新通过重写 `cluster_conf/cluster_conf.data` 后调用 `/reload/server_data_conf`（该 reload 会重新加载
  `cluster_conf.data` 并调用 `BalTable.SetGslbBasic` → `BalanceGslb.SetGslbBasic` → `initEPP`）。
- 每个测试例独立启动 mock backend、mock EPP 与 BFE 进程，端口全部动态分配。

## 3. mock EPP 的双通道能力

`common/mock_epp.go` 新增 `WithDualMode()`：在**同一端口**同时提供 TLS 与明文 gRPC，按连接首字节分流
（TLS ClientHello 记录以 `0x16` 开头；明文 HTTP/2 以连接前言 `P...` 开头）。配套能力：

- `TLSConnCount()` / `PlaintextConnCount()`：分别统计已接受的 TLS / 明文连接数（data 与 probe 均计入）。
- `RestrictProtocols(tls, plaintext bool)`：只接受指定传输，并**关闭**已有的另一传输连接。用于在 reload 后
  "打断"被淘汰的传输——只有真正用新传输重建连接的客户端才能继续服务，从而证明 data 连接确实切换了传输。
- `SetDecisionDelay(d)`：延迟调度决策回包，用于验证 `EPPTimeout.Call`。

> 这是"地址不变、只改 EPPTLS"下唯一可靠的通道判定方式：若不重建 runtime，data 连接仍停留在旧传输，被
> `RestrictProtocols` 打断后将回退本地均衡，`epp_fallback_local_total` 增加。

## 5. 测试例清单

| 编号 | 名称 | 一句话描述 |
|------|------|------------|
| TC-01 | TLS→明文 热更新（D1） | 地址不变、`EPPTLS.Plaintext` false→true，reload 后 data 连接与探针均切明文（打断旧 TLS 后仍由 EPP 决策、无本地回退） |
| TC-02 | 明文→TLS 热更新（D2） | 地址不变、`Plaintext` true→false，重建出非 nil `tlsConf`，data 连接与探针均切 TLS（覆盖 D2） |
| TC-03 | `EPPCheck.Disabled` 热切换（D3） | 关闭健康检查后主 EPP 失活不触发 failover；重新开启后 loop 恢复并完成 failover |
| TC-04 | `EPPTimeout.Call` 原地热更新 | mock 延迟超过旧 Call 超时→本地回退；reload 更大超时后 EPP 决策成功且无新增回退 |
| TC-05 | 未变化 reload 不重置熔断窗口（D5） | reload 未改 `EPPBreaker` 时滑动窗口保留，第 5 次失败即 OPEN |
| TC-06 | `EPPAddr` 变更重建 | 地址表变化触发重建，后续请求由新 EPP 决策，旧 EPP 不再被调用 |
| TC-07 | `EPPTimeout.Connect` 变更重建并继承状态 | 连接型参数变化触发重建（地址不变），failover 状态（`active`）被继承，服务不中断 |
| TC-08 | `EPPCheck.Disabled=true` + `Plaintext=true` 组合热更新 | 一次 reload 同时停健康检查并切明文：data 连接切明文（打断旧 TLS 后仍由 EPP 决策、无回退），且明文连接数在多个探针周期内不增长（无 probe） |
| TC-09 | `EPPBreaker.Disabled=true` + `Plaintext=true` 组合热更新 | 控制面只下发明文（breaker 全程禁用）：data 连接切明文；持续 EPP 失败下熔断器永不 OPEN 且每请求仍调用 EPP；清除错误后恢复经 EPP 明文决策 |

## 6. 公共断言方式

- **转发结果**：HTTP 200 且 body 为 mock backend 固定内容（`epp-reload-backend`），证明请求到达 EPP 指定的后端。
- **mock EPP 记录**：`StreamCount()`（流数，证明请求确经 EPP 决策）、`TLSConnCount()` / `PlaintextConnCount()`（传输通道）。
- **指标**（monitor 端口 `/monitor/epp_metrics`）：`epp_calls_total{cluster,result}`、`epp_fallback_local_total{cluster}`、
  `epp_breaker_transitions_total{cluster,state}`、`epp_active_addr_index{cluster}`。
- **reload**：`/reload/server_data_conf` 返回 `{"error":null}` 视为成功。

## 7. 注意事项

- `EPPTLS.Plaintext=true` 与 `Insecure=true`/`CAFile` 互斥（`GslbBasicConfCheck` 校验拒绝），用例在明文与 TLS 配置间
  切换时按需替换整段 `EPPTLS`。
- 健康检查探针使用**短连接**（每轮新建），data 连接为**长连接**（首个请求时惰性建立），二者均计入连接数统计。
- 设计 §7 的单元用例（`bfe_balance/bal_gslb/epp_runtime_test.go`、`epp_breaker_test.go`）验证 runtime 复用/重建的内部
  判据（如 `assert.Same`、`rt.tlsConf != nil`）；本场景从进程外部验证可观测行为，二者互补。
