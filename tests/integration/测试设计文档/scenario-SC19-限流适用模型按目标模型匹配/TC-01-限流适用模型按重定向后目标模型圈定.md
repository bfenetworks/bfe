# TC-01 限流「适用模型」按重定向后目标模型圈定

## 用例编号与名称

TC-01 限流「适用模型」按重定向后目标模型圈定（issue 复现主链路）

## 所属场景

SC19 限流「适用模型」按目标模型匹配

## 版本声明

- `bfe`：issue #1387 姊妹卡修复起（`bfe_module.HandleAfterAITargetModel` 回调点 + `mod_ai_rate_limit.targetModelCheckHandler`）

## 测试目的

验证限流策略「适用模型=[`glm-5.2`]」按**重定向后的目标模型**匹配：`cluster_redirect` 配置 `ModelMapping: glm-5.2-abc → glm-5.2`，策略 RPM=1。请求 `model=glm-5.2-abc` 第 1 次放行（200，后端收到 model=`glm-5.2`），第 2 次本地 429（`RPM_LIMIT_EXCEEDED`，`details.limit_type=rpm`）。修复前按请求体原始模型 `glm-5.2-abc` 匹配，策略不生效，两次均 200（限流形同虚设）。

## 运行模式

单组件模式：真实 `bfe` 进程 + 进程内 miniredis（限流计数）。

## 前置条件

1. 环境：`mod_ai_token_auth` + `mod_ai_route` + `mod_ai_rate_limit`；token `ak_rl` 无 allow/block 列表，unlimited 配额方案。
2. `cluster_redirect` 单 provider key + `ModelMapping: {"glm-5.2-abc": "glm-5.2"}`，返回 200 与 `usage.total_tokens=15` 的 openai 非流式响应体。
3. 限流策略 `rlp-sc19`：RPM window=1min / max=1 / burst=1，`models=[glm-5.2]`，`redis_key=RL_RPM_rlp-sc19_0`，绑定 `ak_rl`。

## BFE 请求

POST `http://<bfe>/v1/chat/completions`，Host `redirect.example.org`（共 2 次，间隔 1 分钟内）：

| 字段 | 值 |
|------|----|
| Authorization | Bearer ak_rl |
| Content-Type | application/json |
| body | `{"model":"glm-5.2-abc","messages":[{"role":"user","content":"hello"}]}` |

## 目标模型计算

1. 路由目标 Model 覆盖：空，保持 `ClientModel=glm-5.2-abc`；
2. 无 StripPrefix；
3. `cluster_redirect` ModelMapping：`glm-5.2-abc` → `glm-5.2`；
4. 限流检查在 `doSingleAIForward` 内、`aiMeta.TargetModel=glm-5.2` 赋值后触发：`matchModel([glm-5.2], glm-5.2)` 命中 → RPM `Check(1)` → 首次放行 / 第二次 429。

## 预期结果

1. 第 1 次响应 200，响应体为后端透传（含 `"total_tokens":15`）；
2. `cluster_redirect` 命中 1 次，收到的请求体 model 为 `glm-5.2`（重定向后回写）；
3. 第 2 次响应 429，body `error.code=RPM_LIMIT_EXCEEDED`、`error.details.limit_type=rpm`、`error.details.api_key=ak_rl`；
4. 本地 429 未到达后端，`cluster_redirect` Hits 仍为 1。
