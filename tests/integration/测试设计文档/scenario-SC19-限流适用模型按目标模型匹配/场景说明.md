# SC19 限流「适用模型」按目标模型匹配

## 1. 场景背景与目的

BFE AI 网关自 issue #1387 姊妹卡修复起，API-Key 限流策略（TPM / RPM / 最大并发）的「适用模型」改为按「转发后目标模型」匹配（路由目标覆盖 + StripPrefix + ModelMapping 之后），而非请求体原始模型（见 `docs/zh_cn/modifications/2026-09-23-issue-1387-sister-rate-limit-models-target-model/design-changes.md`）。本场景验证：

- `mod_ai_rate_limit` 不再注册 `HandleFoundProduct`，改为以 `RequestFilter`（`targetModelCheckHandler`）注册到新框架回调点 `bfe_module.HandleAfterAITargetModel`，在 `bfe_server/reverseproxy.go` 的 `doSingleAIForward` 内、目标模型解析（`aiMeta.TargetModel` 赋值）之后、转发执行之前触发；
- 限流策略与规则项的模型匹配（`matchModel`）以 `aiMeta.TargetModel` 为对象：客户端发重定向别名（如 `glm-5.2-abc`）时，按 provider 真实模型（如 `glm-5.2`）圈定的策略正确生效；
- 每请求仅检查一次：`PolicyLimiterContext` 存在即跳过（幂等守卫），key 轮换 / 集群 fallback 的后续 attempt 不重复检查、不重复计数；
- 本地限流 429（`req.ErrCode = bfe_basic.ErrAiRateLimit`）显式阻断 provider key 轮换（`aiClusterInvoke` 内 `statusCode==429` 轮换 case 之前守卫返回，无 usedSet 标记、无 session-affinity penalty）与集群 fallback（fallback 循环 `shouldTriggerFallback` 之前守卫 break）；上游 429 行为不变（仍轮换 key）；
- 无重定向时目标模型等于请求体原始模型，行为与改动前一致（不退化）；无路由 404 等早期拒绝请求不再计入限流（检查点后移的语义修正）。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程。
- 限流计数 / 会话亲和惩罚使用进程内 miniredis（`common.RedisServer`），不引入 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_token_auth`、`mod_ai_route`、`mod_ai_rate_limit`（沿用 SC07 模板） |
| `mod_ai_route/mod_ai_route.conf` | 指定 `ai_route.data` 路径 |
| `mod_ai_route/ai_route.data` | 定义两个 apikey 级路由表：`ak_rl`（限流 key，按 Host 路由到 `cluster_redirect` / `cluster_multi` / `cluster_main`+fallback `cluster_backup` / `cluster_plain`）、`ak_up`（上游 429 key，路由到 `cluster_upstream`） |
| `mod_ai_token_auth/mod_ai_token_auth.conf` | token 鉴权配置（Bns 由 builder 重写为 miniredis） |
| `mod_ai_rate_limit/mod_ai_rate_limit.conf` | 限流配置（`ProductRulePath`、`IsRejectOnRedisError = true`，Bns 由 builder 重写为 miniredis） |
| `server_data_conf/host_rule.data` | 声明 `ai_product` 产品线对应的 6 个 Host（含不路由的 `noroute.example.org`） |
| `server_data_conf/route_rule.data` | 默认路由（BasicRule 默认 cluster 为 cluster_plain） |
| `cluster_conf/cluster_conf.data` | 运行时根据 mock 后端与 `AIConfs` 动态生成 |
| `cluster_conf/gslb.data` | GSLB 权重配置 |
| `cluster_conf/cluster_table.data` | 运行时根据 mock 后端地址动态生成 |

## 4. 测试 Cluster 与 Key 配置

### 4.1 cluster_redirect（TC-01，单 key + 模型重定向）

```json
{
    "AIConf": {
        "Type": 0,
        "ModelProtocols": ["openai"],
        "ModelMapping": {"glm-5.2-abc": "glm-5.2"},
        "Keys": [{"Name": "redirect-key", "Key": "sk-redirect-key", "Weight": 100}]
    }
}
```

### 4.2 cluster_multi（TC-02，多 key + 会话亲和 + 429 惩罚）

```json
{
    "AIConf": {
        "Type": 0,
        "ModelProtocols": ["openai"],
        "ModelMapping": {"glm-5.2-abc": "glm-5.2"},
        "Keys": [
            {"Name": "multi-key-1", "Key": "sk-multi-1", "Weight": 100},
            {"Name": "multi-key-2", "Key": "sk-multi-2", "Weight": 100}
        ],
        "KeyPolicy": {
            "Strategy": "weighted_random",
            "MaxRetries": 1,
            "SessionAffinity": true,
            "SessionAffinityPenaltyEnable": true
        }
    }
}
```

### 4.3 cluster_main / cluster_backup（TC-03 / TC-05，fallback 对）

两者均无 ModelMapping，各配置 1 个 provider key（`main-key` / `backup-key`）；`fallback.example.org` 主目标为 `cluster_main`，fallback 为 `cluster_backup`。

### 4.4 cluster_plain（TC-04，无重定向）

```json
{
    "AIConf": {
        "Type": 0,
        "ModelProtocols": ["openai"],
        "Keys": [{"Name": "plain-key", "Key": "sk-plain-key", "Weight": 100}]
    }
}
```

### 4.5 cluster_upstream（TC-06，多 key 轮换）

2 个 provider key（`upstream-key-1` / `upstream-key-2`），`MaxRetries = 1`，无会话亲和。

## 5. 限流策略配置

策略 JSON 由测试代码生成（`common.RateLimitPolicyData`），写入 `mod_ai_rate_limit/ai_rate_limit.data`：

| 用例 | 策略 ID | 规则 | 适用模型 | 绑定 |
|------|---------|------|----------|------|
| TC-01/02/03/04 | `rlp-sc19` | RPM：window=1min，max=1，burst=1，redis_key=`RL_RPM_rlp-sc19_0` | `[glm-5.2]` | `ak_rl` |
| TC-05 | `rlp-sc19-con` | MaxConcurrency=1 | `[glm-5.2]` | `ak_rl` |
| TC-06 | 无 | 无（验证上游 429 语义，不绑定策略） | — | — |

产品规则为 `default_t()` + `FINISH`（本地拒绝）；两个 token（`ak_rl` / `ak_up`）均无 allow/block 列表、使用 unlimited 配额方案（`CHECK_TOKEN` 通过即可）。

## 6. 路由规则

| 规则名 | Key | 条件 | targets | fallbacks |
|--------|-----|------|---------|-----------|
| rl-redirect | ak_rl | `req_host_in("redirect.example.org")` | `cluster_redirect` | 无 |
| rl-multi | ak_rl | `req_host_in("multi.example.org")` | `cluster_multi` | 无 |
| rl-fallback | ak_rl | `req_host_in("fallback.example.org")` | `cluster_main` | `cluster_backup` |
| rl-plain | ak_rl | `req_host_in("plain.example.org")` | `cluster_plain` | 无 |
| up-upstream | ak_up | `req_host_in("upstream.example.org")` | `cluster_upstream` | 无 |

`noroute.example.org` 在 host_rule 中可解析到 `ai_product`，但两个 apikey 路由表均无匹配规则 → 404「AI route not found」（TC-04 早期拒绝断言用）。
