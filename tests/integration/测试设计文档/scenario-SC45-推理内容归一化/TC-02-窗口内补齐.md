# TC-02 窗口内补齐

## 用例编号与名称

TC-02 窗口内补齐

## 所属场景

SC45 推理内容归一化

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.EnsureReasoningContent` 实现）

## 测试目的

验证核心行为与窗口边界：只有"最后一条 `user` 消息之后"的 assistant 消息被补 `reasoning_content: ""`，窗口之外的历史消息不动，且**除注入字段外请求体逐字节不变**。

## 运行模式

单组件模式：真实 `bfe` + 记录原始字节的 mock 上游。

## 前置条件

1. `cluster_ds` 的 `EnsureReasoningContent: ["openai"]`；
2. mock 上游记录请求体；
3. 请求体使用场景说明 §4.4 的样张：`messages[1]` 为历史 assistant（缺字段但**不应**被补），`messages[3]` 为窗口内 assistant（应被补）。

## 配置构造

```json
"AIConf": {
    "ModelProtocols": ["openai", "anthropic"],
    "EnsureReasoningContent": ["openai"],
    "Keys": [{"Name": "key-primary", "Key": "sk-upstream-secret", "Weight": 100}]
}
```

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `front.example.org` | `/v1/chat/completions` | `Bearer ak_front` | 场景说明 §4.4 样张 |

## 后端响应

同 TC-01（200 chat 响应）。

## 执行步骤

1. 启动 BFE，发送请求；
2. 取 mock 上游记录的请求体；
3. 做结构化断言（`messages[1]` 无字段、`messages[3]` 为空串）与字节断言（剔除注入片段后与原始请求体逐字节相等）。

## 预期结果

- 上游请求体满足：
  - `messages[1].reasoning_content` **不存在**（历史消息不动，上游不校验该段）；
  - `messages[3].reasoning_content == ""`；
  - `messages[4]`（tool 消息）不新增任何字段；
- 字节断言：`strings.ReplaceAll(got, ",\"reasoning_content\":\"\"", "") == 原始请求体`（注入片段恰好出现 1 次）；
- 字段顺序、数字格式、Unicode 转义均未变化（定点写入，非整体 re-marshal）；
- `ReasoningPatched` +1，`ReasoningSkip=0`、`ReasoningFail=0`；
- 上游返回 200，客户端 200。

## 清理

停止 `bfe` 进程与 mock 上游，删除临时目录。
