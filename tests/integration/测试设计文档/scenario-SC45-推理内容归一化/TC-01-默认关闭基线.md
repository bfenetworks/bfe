# TC-01 默认关闭基线

## 用例编号与名称

TC-01 默认关闭基线

## 所属场景

SC45 推理内容归一化

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.EnsureReasoningContent` 实现）

## 测试目的

验证字段缺省时的兼容性基线：不配置 `EnsureReasoningContent` 的集群，请求体**逐字节透传**到上游，`ReasoningPatched` 保持 0。这是存量集群"行为与旧版本完全一致"的回归锚点。

## 运行模式

单组件模式：真实 `bfe` + 记录原始字节的 mock 上游，无 Redis。

## 前置条件

1. `cluster_ds` 的 `AIConf`：**不配置** `EnsureReasoningContent`；
2. `ak_front` 已绑定 `apikey_ak_front`，命中 `cluster_ds`；
3. mock 上游返回 200 chat 响应，记录收到的请求体。

## 配置构造

```json
"AIConf": {
    "Provider": "mock-deepseek",
    "ModelProtocols": ["openai", "anthropic"],
    "Keys": [{"Name": "key-primary", "Key": "sk-upstream-secret", "Weight": 100}],
    "KeyPolicy": {"Strategy": "weighted_random", "MaxRetries": 0}
}
```

## BFE 请求

| 步骤 | Host | Path | Authorization | Body |
|------|------|------|---------------|------|
| 1 | `front.example.org` | `/v1/chat/completions` | `Bearer ak_front` | 场景说明 §4.4 的窗口内缺字段样张 |

## 后端响应

```json
{"id":"chatcmpl-1","object":"chat.completion","model":"deepseek-chat",
 "choices":[{"index":0,"message":{"role":"assistant","content":"ok"},"finish_reason":"stop"}],
 "usage":{"prompt_tokens":10,"completion_tokens":2,"total_tokens":12}}
```

## 执行步骤

1. 启动 BFE，发送请求；
2. 读取 mock 上游记录的请求体；
3. 读取 `proxy_state` 的 `ReasoningPatched` / `ReasoningSkip` / `ReasoningFail`。

## 预期结果

- 客户端收到 **200**；
- 上游收到的请求体与客户端发送的**逐字节一致**（`messages[3]` 仍缺 `reasoning_content`）；
- `ReasoningPatched=0`、`ReasoningSkip=0`、`ReasoningFail=0`、`ReasoningStill400=0`；
- 访问日志中本机制不产生任何字段（仅 `AiBasicInfo.ReasoningPatched` 为 false，不落日志）。

## 清理

停止 `bfe` 进程与 mock 上游，删除临时目录。
