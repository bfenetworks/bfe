# TC-13 指标面

## 用例编号与名称

TC-13 指标面

## 所属场景

SC45 推理内容归一化

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.EnsureReasoningContent` 实现）

## 测试目的

验证四个 `proxy_state` 指标在各自分支上正确点亮——它们是灰度判断与退出的依据，计数错位会让上线决策失真。本用例在一个实例上顺序跑多条臂，逐臂检查增量。

## 运行模式

单组件模式：真实 `bfe` + 记录原始字节的 mock 上游；经 monitor 端口读指标。

## 前置条件

1. `cluster_ds` 的 `EnsureReasoningContent: ["openai"]`；
2. 可复用本场景其他用例的请求样张（窗口内缺字段 / 已有值 / 压缩体 / 非法 JSON）；
3. monitor 端口可读（`common.ModuleMetric(monitorPort, "proxy_state", <name>)`）。

## 配置构造

同 TC-02。

## BFE 请求

| 臂 | Body | 预期指标变化 |
|----|------|--------------|
| A1 | 窗口内缺字段样张 | `ReasoningPatched` +1 |
| A2 | 同一 A1 再发一次（新请求） | `ReasoningPatched` +1（累计 2） |
| B1 | 已有非空 `reasoning_content` | 四个指标均不变 |
| C1 | `Content-Encoding: gzip` | `ReasoningSkip` +1 |
| C2 | 非法 JSON（截断的 body） | `ReasoningFail` +1 |

## 后端响应

除 D 臂外均 200；非法 JSON 臂的上游收到的仍是原字节（mock 返回 200，客户端 200）。若另设 D 臂（mock 返回 400）用于点亮 `ReasoningStill400`，见 TC-08。

## 执行步骤

1. 起 BFE，记录四个指标的初值；
2. 逐臂发送请求，每臂之后读一次指标；
3. 计算增量并与预期对照。

## 预期结果

| 指标 | 增量 |
|------|------|
| `ReasoningPatched` | A1 +1、A2 +1，其余 0 |
| `ReasoningSkip` | C1 +1，其余 0 |
| `ReasoningFail` | C2 +1，其余 0 |
| `ReasoningStill400` | 全部 0（该臂不含 400） |

所有臂客户端均收到 200，无 5xx。

## 清理

停止 `bfe` 进程与 mock 上游，删除临时目录。
