# TC-10 与上下文压缩共存

## 用例编号与名称

TC-10 与上下文压缩共存

## 所属场景

SC45 推理内容归一化

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.EnsureReasoningContent` 实现与 `mod_ai_context`）

## 测试目的

验证执行顺序约束：`mod_ai_context` 在 `HandleAfterAITargetModel` 回调内对请求体做**整体 re-marshal**，且其消息序列化会丢弃值为空的 `reasoning_content`。本机制的补丁必须晚于该回调，否则会被抹掉。本用例用"强制触发压缩"的规则把这条顺序钉死。

## 运行模式

单组件模式：真实 `bfe` + 记录原始字节的 mock 上游；启用 `mod_ai_context`。

## 前置条件

1. `cluster_ds` 的 `EnsureReasoningContent: ["openai"]`；
2. `mod_ai_context.conf` 启用模块，`context_rule.data` 配 `Mode: conservative`、`MaxContextTokens: 200`（远小于样张估算值，保证每次请求都触发压缩）；
3. 样张中窗口内 assistant 缺 `reasoning_content`，且历史里有可裁剪内容（长 tool 结果），使压缩确实改变 body。

## 配置构造

```json
"AIConf": {"EnsureReasoningContent": ["openai"], "Keys": [...], "ModelProtocols": ["openai"]}
```

`context_rule.data`：

```json
{
  "Config": {
    "saas_front": [{"Cond": "default_t()", "Mode": "conservative", "MaxContextTokens": 200}]
  },
  "Version": "20261103000000"
}
```

## BFE 请求

| 步骤 | 臂 | 机制开关 | 说明 |
|------|----|----------|------|
| 1 | A | 开启 | 压缩必触发 + 补丁生效 |
| 2 | B | 不配置 | 压缩必触发 + 无补丁（基线） |

## 后端响应

同 TC-01（200）。响应头应带 `x-ai-context-compression`（证明压缩确实发生）。

## 执行步骤

1. 起 BFE（启用 `mod_ai_context`），跑臂 A，取 mock 记录的请求体；
2. 断响应头 `x-ai-context-compression` 存在（压缩已生效）；
3. 重启换成臂 B 配置，跑臂 B，取 mock 记录的请求体。

## 预期结果

- 臂 A：响应头存在 `x-ai-context-compression`（压缩确实执行且 body 被重写）；mock 收到的 body 中，窗口内 assistant **带** `reasoning_content:""`——说明补丁在 re-marshal 之后执行、未被抹掉；`ReasoningPatched` +1；
- 臂 B：响应头同样存在（压缩发生），但窗口内 assistant 无 `reasoning_content`；
- 两臂客户端均 200。

## 清理

停止 `bfe` 进程与 mock 上游，删除临时目录。
