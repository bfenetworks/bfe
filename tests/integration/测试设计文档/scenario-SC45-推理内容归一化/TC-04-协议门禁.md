# TC-04 协议门禁

## 用例编号与名称

TC-04 协议门禁

## 所属场景

SC45 推理内容归一化

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.EnsureReasoningContent` 实现）

## 测试目的

验证开关的协议维度：`EnsureReasoningContent: ["openai"]` 时，同一集群上的 anthropic（`/v1/messages`）请求**不被注入**；把它改成 `["openai","anthropic"]` 后才进入 TC-05 的分支行为。避免"以为开了就全协议生效"的误解。

## 运行模式

单组件模式：真实 `bfe` + 记录原始字节的 mock 上游。

## 前置条件

1. `cluster_ds`：`ModelProtocols: ["openai","anthropic"]`、`ProtocolPaths: {"openai":"/v1","anthropic":"/anthropic"}`；
2. 臂 A：`EnsureReasoningContent: ["openai"]`；臂 B：`["openai","anthropic"]`（两臂各起一个 BFE 实例）；
3. anthropic 请求会被 `ProtocolPaths` 改写到 mock 的 `/anthropic/v1/messages`，mock 需按该路径路由；
4. **只发 `x-api-key`，不带 `Authorization`**：协议识别优先看 `Authorization`（`bfe_model_protocol/detect.go`），两个头同时存在会被判成 openai，从而走错协议分支——真实 anthropic 客户端（claude-cli 等）也只发 `x-api-key`。

## 配置构造

臂 A：

```json
"EnsureReasoningContent": ["openai"]
```

臂 B：

```json
"EnsureReasoningContent": ["openai", "anthropic"]
```

## BFE 请求

| 步骤 | 臂 | Host | Path | Headers | Body |
|------|----|------|------|---------|------|
| 1 | A | `front.example.org` | `/v1/messages` | `x-api-key: ak_front`、`anthropic-version: 2023-06-01` | `{"model":"deepseek-chat","max_tokens":64,"messages":[{"role":"user","content":"q"},{"role":"assistant","content":[{"type":"text","text":"a"}]}]}` |
| 2 | B | 同上 | 同上 | 同上 | 同上 |

## 后端响应

anthropic 形态 200：

```json
{"id":"msg_1","type":"message","role":"assistant","model":"deepseek-chat",
 "content":[{"type":"text","text":"ok"}],"stop_reason":"end_turn",
 "usage":{"input_tokens":10,"output_tokens":2}}
```

## 执行步骤

1. 起臂 A 的 BFE，发送 anthropic 请求，取 mock 记录的请求体；
2. 起臂 B 的 BFE，发送同一请求，取 mock 记录的请求体；
3. 对比两臂。

## 预期结果

- 臂 A：mock 收到的请求体与客户端发送的**逐字节一致**（`content` 数组未插入 thinking 块）；`ReasoningPatched` 不增加；
- 臂 B：请求体在 `messages[1].content` 头部出现 `{"type":"thinking","thinking":"","signature":""}`（详细断言见 TC-05）；
- 两臂客户端均 200。

## 清理

停止两个 `bfe` 进程与 mock 上游，删除临时目录。
