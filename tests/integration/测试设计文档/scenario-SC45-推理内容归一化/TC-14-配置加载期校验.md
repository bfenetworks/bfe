# TC-14 配置加载期校验

## 用例编号与名称

TC-14 配置加载期校验

## 所属场景

SC45 推理内容归一化

## 版本声明

- `bfe`：当前源码版本（含 `AIConf.EnsureReasoningContent` 实现与 `AIConfCheck` 校验）

## 测试目的

验证 `AIConfCheck` 的 fail-fast 语义：非法取值在**加载期**就被拒绝，不会带着"配了但什么都不做"的假开关上线。覆盖三条规则：`gemini` 不适用、协议未在 `ModelProtocols` 申报、取值未知；并验证 reload 失败时旧配置保留。

## 运行模式

单组件模式：真实 `bfe`（首启失败用例只检查启动结果）；reload 臂在同一实例上覆盖配置后调 `/reload`。

## 前置条件

1. 每次臂使用独立临时配置目录；
2. reload 臂先用合法配置启动（`EnsureReasoningContent: ["openai"]`），再改写 `cluster_conf.data` 后触发 reload；
3. mock 上游记录请求体。

## 配置构造（三个非法臂）

| 臂 | `ModelProtocols` | `EnsureReasoningContent` | 期望 |
|----|------------------|--------------------------|------|
| A | `["openai","gemini"]` | `["gemini"]` | 启动失败：`protocol "gemini" not supported` |
| B | `["openai"]` | `["anthropic"]` | 启动失败：`protocol "anthropic" not in ModelProtocols` |
| C | `["openai"]` | `["foo"]` | 启动失败：`protocol "foo" not supported` |
| D | `["openai"]` | `["openai","openai"]` | 启动失败：`duplicate protocol "openai"` |

reload 臂：运行中把 `cluster_conf.data` 改成臂 B 的非法组合。

## BFE 请求

| 步骤 | 臂 | 说明 |
|------|----|------|
| 1 | A–D | 不发送请求，仅观察进程启动结果与日志 |
| 2 | reload | reload 前后各发一次 TC-02 的样张请求 |

## 后端响应

reload 臂的 mock 返回 200。

## 执行步骤

1. 逐臂用非法配置启动 BFE，记录进程退出码与日志中的错误行；
2. reload 臂：合法配置启动 → 发请求 A（确认补丁生效）→ 覆盖为非法配置 → 调 `/reload` → 检查 reload 返回 → 再发一次请求 B。

## 预期结果

- 臂 A–D：BFE **启动失败**（进程退出码非 0），日志含上表对应错误信息（含字段名 `EnsureReasoningContent`）；
- reload 臂：`/reload/server_data_conf` 的返回体中带 `error`（该端点用 **HTTP 200 + `{"error":...}`** 表达失败，不是 HTTP 5xx），且错误信息含字段名 `EnsureReasoningContent`；
- reload 臂：**旧配置继续生效**——请求 B 的 body 仍带 `reasoning_content:""`，客户端 200；
- 全过程不出现"进程在跑但配置未生效"的静默状态。

## 清理

停止 `bfe` 进程，删除临时目录。
