# TC-33 额度不足放行模式下欠费持续累计

## 用例编号与名称

TC-33 额度不足放行模式下欠费持续累计（issue #1476）

## 所属场景

SC03 RMB 配额扣减

## 版本声明

- `bfe`：当前源码版本（含 issue #1476 修复）

## 测试目的

验证"额度不足时放行"（`PassNoQuota=true`）只跳过**鉴权期**余额检查：请求照常放行，但**收尾扣减仍按实际成本全额记账**，余额持续变负，累计消耗（`used = quota − remaining`）持续可见——修复前余额钉在 0、后续用量全部丢失。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. 嵌入式 Redis 已启动，并预置 `quota:plan_rmb = 10000`。
3. mock 后端 `cluster_rmb` 已启动，返回 usage 为 `prompt_tokens=100, completion_tokens=50` 的响应。
4. `ak_user_a` 绑定 RMB 配额计划 `plan_rmb`（`PassNoQuota=true`）。

## 配置构造

- `plan_rmb`：
  - `Unit`: `RMB`
  - `Quota`: `10000`
  - `RedisKey`: `quota:plan_rmb`
  - `PassNoQuota`: `true`

单次请求成本 = `20000` 定点单位；3 次合计 `60000`。

## BFE 请求

连续发送 3 次相同 POST 请求：

| 字段 | 值 |
|------|-----|
| Host | `rmb.example.org` |
| Path | `/v1/chat/completions` |
| Authorization | `Bearer ak_user_a` |
| Body | `{"model":"deepseek-chat"}` |

## 预期结果

- 3 次请求均返回 200，`cluster_rmb` 命中 3 次。
- Redis `quota:plan_rmb` = **−50000**（修复前为 0：第 1 次扣 10000 后钉 0，丢失 50000 用量）。
- `mod_ai_token_auth` 监控中 `QuotaOverage ≥ 3`。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录。
