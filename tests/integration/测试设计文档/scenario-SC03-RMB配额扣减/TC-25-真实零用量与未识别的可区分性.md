# TC-25 真实零用量与未识别的可区分性（issue #1414）

## 用例编号与名称

TC-25 usage 全 0（真实零用量）与"无 usage"（未识别）的可区分性（识别层 presence 判定 → `parsed` vs `unrecognized`）

## 所属场景

SC03 RMB 配额扣减

## 版本声明

- `bfe`：当前源码版本（含 issue #1414 修复；`ai_zero_cost_reason` 字段需 `bfe-access-pb >= v0.3.16`）
- 复用 TC-24 引入的公共设施改造：`TestEnv` 捕获 BFE monitor 端口 + `tokenAuthMetric()` / `waitForTokenAuthMetric()` 计数器读数辅助方法

## 测试目的

验证 issue #1414 把 usage 识别从**值判定**改为 **presence 判定**（按 usage 对象是否存在）之后，issue 断言 A-01 要求的"可区分性"成立：

1. 上游**显式返回全 0 usage 对象**的 2xx 请求属于**真实零用量**：识别为 final usage（`ai_usage_source=parsed`）、按真实 0 计费、**不再被 `EstimateToken` 估算**，且**不计入** `UsageUnrecognized`；
2. 上游**完全没有提供 usage** 且不可估算的 2xx 请求仍按既定口径零扣费，但计入 `UsageUnrecognized`（`ai_usage_source=unrecognized`）；
3. 两者在新收口信号上也不同：臂 1 的 `ai_zero_cost_reason=no_usage_tokens`（观测本身解释了零成本），臂 2 为 `unrecognized`（观测缺失）。字段级断言在 SC03 不可直接进行（未加载 `mod_access_pb3`），由单元测试与 SC05 覆盖，本 TC 在集成层以计数器与扣减金额为信号基准。

修复前（TC-24 的"已知限制"）：全 0 usage 与"无 usage"在识别层不可区分——`isguess` 为值判定（`UsedQuota > 0`），该类响应在 `EstimateToken=true`（出厂默认）下被按估算**超额计费**、`ai_usage_source=estimated`；显式关闭估算时则被误计入 `unrecognized`。本 TC 是该限制的回归载体。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis。

## 前置条件

1. 已编译 `bfe` 可执行文件（含 issue #1414 修复）。
2. 嵌入式 Redis 已启动，并预置 `quota:plan_rmb = 10000000000`。
3. SC03 `bfe.conf` 模板 `MonitorEnabled = true`；`TestEnv` 已捕获 monitor 端口。
4. `Server.EstimateToken` 取默认值 **true**（`bfe_config/bfe_conf/conf_basic.go` 程序默认）——臂 1 正是用来证明"估算开启时 presence 仍然优先"，臂 2 用不可估算形态（chunked + 非 SSE + 非 JSON）避开估算。
5. `ak_user_a` 绑定 RMB 配额计划 `plan_rmb`；`cluster_rmb` 价格表为 `defaultRMBAIConf`（`deepseek-chat`：`input 1e-6`、`output 2e-6`，定点 100/200）。

## 请求构造

同一 Key 依次发送 3 次 POST `http://rmb.example.org/v1/chat/completions`（`Authorization: Bearer ak_user_a`，body `{"model":"deepseek-chat"}`）：

| 臂 | 后端响应（均 HTTP 200） | 预期 |
|---|---|---|
| 臂 1 显式全 0 usage | 定长 JSON：`{"usage":{"prompt_tokens":0,"completion_tokens":0,"total_tokens":0}}` | 零扣费（**不是**估算值）；`UsageUnrecognized` **不增**；`BillingZeroCost` +1；`ai_usage_source=parsed`（字段断言见 SC05） |
| 臂 2 无 usage 且不可估算 | chunked（`NoContentLength`）+ `Content-Type: text/plain`，body `hello, no usage here` | 零扣费（issue #1410/#1414 均维持的既定口径）；`UsageUnrecognized` +1；`BillingZeroCost` +1 |
| 臂 3 正常计费对照 | 定长 JSON：`{"usage":{"prompt_tokens":100,"completion_tokens":50,"total_tokens":150}}` | 扣减 `100*100 + 50*200 = 20000`；`UsageUnrecognized` 与 `BillingZeroCost` 均**不增** |

臂 2 的形态选择理由与 TC-24 一致：定长或 chunked 的 JSON body 会被 `tokenReadResponseHandler` 整体解析（#1406 的 `isCompleteNonStreamBody`），无 usage 时走估算；只有"chunked + 非 SSE + 非 JSON"才既不整体解析、也不产生终止事件（`responseCompleted=false`），从而落入"未识别且不可估算"分支。

## 后端响应

mock 后端 `cluster_rmb` 按臂切换 body（复用 `MockBackend.Body` 赋值模式，同 TC-23/TC-24）；三次均返回 HTTP 200。

## 执行步骤

1. 按 SC03 公共流程启动嵌入式 Redis、mock 后端与 BFE（捕获 monitor 端口）。
2. 预置 `quota:plan_rmb = 10000000000`。
3. 臂 1（全 0 usage）：切换后端 body 为全 0 usage JSON → 发送请求 → 断言 200、后端命中 1 次。
4. 等待并断言计数器：`UsageUnrecognized == 0`、`BillingZeroCost == 1`、`UsageSource` 无法在集成层读取（见"预期结果"）。
5. 臂 2（无 usage）：切换 body 为 chunked `text/plain` → 发送请求 → 断言 200、后端命中 2 次；断言 `UsageUnrecognized == 1`、`BillingZeroCost == 2`。
6. 臂 3（正常计费对照）：切换 body 为正常 usage → 发送请求 → 断言 200、后端命中 3 次；断言 `UsageUnrecognized == 1`、`BillingZeroCost == 2`（均不增）。
7. 等待异步扣减（500ms）后断言 `quota:plan_rmb` 余额 = `10000000000 − 20000 = 99999980000`。**臂 1 的余额不变即为"未被估算计费"的等价断言**（修复前该臂会按 `EstimateToken` 估算扣费，余额会下降）。
8. 运行输出：臂 2 应出现 1 条 `usage unrecognized and not estimatable, billing skipped` Warn（臂 1 不应出现该 Warn）。与 TC-24 相同，测试框架将 BFE stdout 直挂测试进程、本场景无 `[log]` 段（不产生 exception.log），**Warn 不做文件断言**，由运行日志人工可见 + 单元测试覆盖代码路径。

## 预期结果

- 三次请求均返回 HTTP 200；`cluster_rmb` 共 3 次命中。
- `UsageUnrecognized`：臂 1 后 `0`（**核心断言**：显式全 0 usage 不再被当作未识别）、臂 2 后 `1`、臂 3 后仍 `1`。
- `BillingZeroCost`：臂 1 后 `1`、臂 2 后 `2`、臂 3 后仍 `2`（正常计费行不计数）。
- Redis 余额 `99999980000`：仅臂 3 扣减 20000；臂 1 零扣费证明"presence 优先于估算"（修复前臂 1 会被估算扣费）。
- 行级字段（`ai_usage_source` 为 `parsed` / `unrecognized`，`ai_zero_cost_reason` 为 `no_usage_tokens` / `unrecognized`）不在本场景断言：SC03 未加载 `mod_access_pb3`，由单元测试 `TestTokenRequestFinishHandler_AllZeroUsageIsParsed`、`TestReqAiInfoGenZeroCostReason` 与 SC05 TC-21 覆盖。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录。
