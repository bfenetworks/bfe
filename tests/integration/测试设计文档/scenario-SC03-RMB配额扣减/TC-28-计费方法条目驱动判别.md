# TC-28 计费方法条目驱动判别（issue #1420 边界）

## 用例编号与名称

TC-28 计费方法条目驱动判别（按张键存在性判别计费方法：混合条目按张优先、显式 0 价按张键不回落 token 公式、video_generation 对称回落）

## 所属场景

SC03 RMB 配额扣减

## 版本声明

- `bfe`：当前源码版本（含 issue #1420 修复）

## 测试目的

锁定 issue #1420 修复的**判别语义**与对称修复，三个臂分别守护：

1. **混合条目按张优先**：条目同时配置 `output_cost_per_image` 与 token 单价键时，按张计费（按次键是更显式的计费方法声明）；若误实现为"token 键存在即走 token 公式"，本臂金额将变为 0，可暴露优先级反转；
2. **显式 0 价按张键不回落**：`output_cost_per_image = 0`（键存在、值为 0）仍走按张公式计 0，**不**回落 token 公式——判别信号是键的存在性（`HasPrice`）而非值的大小；若误实现为 `GetPrice > 0` 判别，本臂将错误扣减 20000；
3. **video_generation 对称回落**：token 计价的生视频规则（无 `output_cost_per_video` 键）同 image_generation 一样回落 token 公式，修复同构 latent 缺陷。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. 嵌入式 Redis 已启动，并预置 `quota:plan_rmb = 10000000000`。
3. `cluster_rmb` 的 `ModelTable` 在默认条目之外新增三个条目（token 单价均为 `input_cost_per_token=1e-6`、`output_cost_per_token=2e-6`，即定点 100/200）：

| model | mode | 价格键 | 计费方法 |
|-------|------|--------|----------|
| `gpt-image-mixed` | image_generation | `output_cost_per_image=0.03` + token 单价键 | 按张优先 |
| `gpt-image-free` | image_generation | `output_cost_per_image=0`（键存在）+ token 单价键 | 按张（免费） |
| `kling-token` | video_generation | 仅 token 单价键 | 回落 token 公式 |

4. `ak_user_a` 绑定 RMB 配额计划 `plan_rmb`。

## BFE 请求

同一 Key 依次发送 3 次 POST（host 均为 `rmb.example.org`）：

| 臂 | Path | Body | 后端响应 body | 预期计费 |
|---|---|---|---|---|
| 按张优先臂 | `/v1/images/generations` | `{"model":"gpt-image-mixed","n":2}` | `{"usage":{"image_count":2}}` | 按张：`2 × 0.03 = 6000000`（token 键被按张优先忽略） |
| 显式零价臂 | `/v1/images/generations` | `{"model":"gpt-image-free"}` | `{"usage":{"prompt_tokens":100,"completion_tokens":50,"total_tokens":150}}` | 按张键存在（值 0）：`1 × 0 = 0`，不回落 token 公式，不扣减 |
| 生视频回落臂 | `/v1/video/generations` | `{"model":"kling-token"}` | `{"usage":{"prompt_tokens":100,"completion_tokens":50,"total_tokens":150}}` | 无 `output_cost_per_video` 键 → token 公式：`100×100 + 50×200 = 20000` |

## 预期结果

- 三次请求均返回 HTTP 200；`cluster_rmb` 共 3 次命中。
- 异步扣减完成后 `quota:plan_rmb` 余额 = `10000000000 − 6000000 − 0 − 20000 = 99993980000`。
- 三个臂合计金额唯一确定：任一臂判别语义被改坏（按张优先反转、值判别替代存在性判别、video 未做对称回落）都会使余额断言失败。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录。
