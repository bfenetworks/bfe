# TC-26 零计费收口信号（issue #1414）

## 用例编号与名称

TC-26 零计费收口信号：绑定 RMB 计划但计费为 0 的 2xx 请求可计数、可归因（`BillingZeroCost` + `ai_zero_cost_reason`）

## 所属场景

SC03 RMB 配额扣减

## 版本声明

- `bfe`：当前源码版本（含 issue #1414 修复；`ai_zero_cost_reason` 字段需 `bfe-access-pb >= v0.3.16`）
- 复用 TC-24 引入的公共设施改造（monitor 端口捕获 + 计数器读数辅助方法）

## 测试目的

issue #1410 只为"usage 未识别且不可估算"这一个计费旁路补了信号。本用例验证 issue #1414 的**结构性收口**：任何"2xx + 绑定 RMB 配额计划 + 计费结果为 0"的请求都在同一点被计数（`BillingZeroCost`）并能归因（`ai_zero_cost_reason`），其中：

1. **价格配置类零成本**（`model_table_missing`）：cluster 未配置 `AIConf.ModelTable` 时，`calcCostUnits` 早退为 0——修复前只有一行 Warn、没有计数器，对账完全看不见；
2. **价格缺失类零成本**（`price_miss`）：价格表中该 model 没有任何条目（chat 基准也不兜底）时按 0 计费——修复前该行同样无法被计数，且批量结算路径连 Warn 都没有；
3. **对照臂**：正常计费的 2xx 请求不计数、无零成本原因；
4. 三类零成本形态的**区分性**：零成本不等于"usage 未识别"——臂 1/臂 2 的 `ai_usage_source` 仍为 `parsed`（usage 已识别，只是价格为 0），`UsageUnrecognized` 不增。

**范围说明（诚实边界）**：本用例只覆盖 SC03 环境可稳定构造的两类零成本成因。另两类成因在**其他场景**覆盖，避免在 SC03 重复搭建：

- 客户端中断零扣费（`reason=aborted`，计数器 `AbortBillingSkipped`）→ SC12 TC-04；
- 批量契约释放未计费（`reason=batch_release` / 批量价缺失 `reason=price_miss`）→ SC28 TC-11；
- 缓存命中（`reason=cache_hit`，**有意不计入** `BillingZeroCost`，因其零成本属设计）→ 由单元测试 `TestTokenRequestFinishHandler_CacheHitIsMarkedButNotCounted` 覆盖。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程与嵌入式 Redis。

## 前置条件

1. 已编译 `bfe` 可执行文件（含 issue #1414 修复）。
2. 嵌入式 Redis 已启动，并预置 `quota:plan_rmb = 10000000000`。
3. SC03 `bfe.conf` 模板 `MonitorEnabled = true`；`TestEnv` 已捕获 monitor 端口。
4. `ak_user_a` 绑定 RMB 配额计划 `plan_rmb`。
5. 臂 1 使用 SC03 既有的 `cluster_no_table`（`route_rule.data`/`ai_route.data` 中已声明，TC-05 即用它验证"无 ModelTable 按 0 成本处理"）：该 cluster **不配置** `AIConf.ModelTable`。
6. 臂 2 复用 TC-23 的"无基线边界臂"构造：`cluster_rmb` 的价格表**只含 `deepseek-chat` 的 `chat` 条目**，请求 `/v1/chat/completions` 且 body 为 `{"model":"no-such-model"}`——价格表中没有该 model 的任何条目、mode=chat 又不回退，`LookupModelPrice` 返回 nil（`PriceLookupMiss` +1，issue #1408 既有行为）。
7. 臂 3 使用 `cluster_rmb` 的 `deepseek-chat`（`input 1e-6`、`output 2e-6`，定点 100/200）。

## 请求构造

三次 POST（均带 `Authorization: Bearer ak_user_a`，body 含正常 usage 形态），三臂的差异在 cluster / model 与后端响应：

| 臂 | 目标 | 后端响应（均 HTTP 200） | 预期 |
|---|---|---|---|
| 臂 1 `model_table_missing` | `cluster_no_table`，`deepseek-chat` | 定长 JSON `{"usage":{"prompt_tokens":100,"completion_tokens":50,"total_tokens":150}}` | 零扣费；`BillingZeroCost` +1；`ai_zero_cost_reason=model_table_missing`；`UsageUnrecognized` 不增；`ai_usage_source` 仍为 `parsed` |
| 臂 2 `price_miss` | `cluster_rmb`，`/v1/chat/completions`，`{"model":"no-such-model"}`（价格表中无该 model 任何条目） | 同上（正常 usage） | 零扣费；`BillingZeroCost` +1；`ai_zero_cost_reason=price_miss`；`PriceLookupMiss` +1（#1408 既有）；`UsageUnrecognized` 不增 |
| 臂 3 正常计费对照 | `cluster_rmb`，`deepseek-chat` | `{"usage":{"prompt_tokens":100,"completion_tokens":50,"total_tokens":150}}` | 扣减 `100*100 + 50*200 = 20000`；`BillingZeroCost` 不增 |

## 后端响应

mock 后端按臂切换（`cluster_no_table` / `cluster_rmb` 各自的后端地址由 SC03 公共设施分配，同 TC-05/TC-06 的 cluster 切换方式）。

## 执行步骤

1. 按 SC03 公共流程启动嵌入式 Redis、mock 后端与 BFE（捕获 monitor 端口）。
2. 预置 `quota:plan_rmb = 10000000000`。
3. 臂 1：向 `cluster_no_table` 发请求 → 断言 200 → 断言 `BillingZeroCost == 1`、`UsageUnrecognized == 0`。
4. 臂 2：向 `cluster_rmb` 发请求（无条目 model）→ 断言 200 → 断言 `BillingZeroCost == 2`、`PriceLookupMiss == 1`、`UsageUnrecognized == 0`。
5. 臂 3：向 `cluster_rmb` 发正常请求 → 断言 200 → 断言 `BillingZeroCost == 2`（不增）。
6. 等待异步扣减（500ms）后断言余额 = `10000000000 − 20000 = 99999980000`（臂 1/臂 2 均为既定口径的零扣费，本用例只断言其可计数与可归因，不主张其应计费）。
7. 运行输出：臂 1 应出现 `model table not found for cluster` Warn；臂 2 应出现 `model price not found for cluster ... model ... mode` Warn。与 TC-24 相同，**Warn 不做文件断言**（框架把 BFE stdout 直挂测试进程、本场景无 `[log]` 段），由运行日志人工可见 + 单元测试覆盖。

## 预期结果

- 三次请求均返回 HTTP 200。
- `BillingZeroCost`：臂 1 后 `1`、臂 2 后 `2`、臂 3 后仍 `2`。
- `UsageUnrecognized` 全程 `0`（**核心区分性断言**：价格/配置类零成本不是"usage 未识别"，两者不得混计）。
- `PriceLookupMiss` 在臂 2 后为 `1`（#1408 既有行为不回归）。
- Redis 余额 `99999980000`（仅臂 3 扣减）。
- `ai_zero_cost_reason` 的取值（`model_table_missing` / `price_miss`）与"正常计费行该字段缺席"不在本场景断言：SC03 未加载 `mod_access_pb3`，由单元测试 `TestTokenRequestFinishHandler_ZeroCostReasonPriceZero`（同路径的 price_zero 变体）、`TestTokenRequestFinishHandler_ZeroCostReasonModelTableMissing` 与 SC05 TC-21 覆盖。

## 清理

停止 `bfe` 进程、mock 后端与嵌入式 Redis，删除临时目录。
