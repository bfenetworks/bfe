# TC-08 缺省 0 零开销回归

## 目的

验证 `MaxConcurrencyPerKey` 缺省（等价 0 = 不限）时链路零改动：不读写任何 `conc:` 键，多会话并发行为与变更前完全一致（回归保护）。

## 前置条件

- `cluster_key_conc` 的 `AIConf` **不携带** `MaxConcurrencyPerKey` 字段（其余同 TC-01）；
- `[AIKeyAffinity]` 指向 miniredis；
- miniredis 为空。

## 请求构造

同 TC-01（`ak_conc_a`、`ak_conc_b`、`ak_conc_c`）。

## 执行步骤

1. 会话 A、B、C 并发各发 1 条请求；
2. 断言响应与 Redis 状态。

## 预期结果

- 三条请求全部 **200**（亲和绑定生效：各自绑定 Key，允许两把 Key 承载多个会话——无并发限制）；
- miniredis 中**不存在** `bfe:ai:key_affinity:conc:*` 键（零读写）；
- 绑定键正常写入（`bfe:ai:key_affinity:cluster_key_conc:kid-{a,b,c}` 存在）。

## 清理

测试结束时关闭 BFE、mock 后端与 miniredis。
