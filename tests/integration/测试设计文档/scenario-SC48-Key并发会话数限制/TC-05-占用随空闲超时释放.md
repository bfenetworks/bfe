# TC-05 占用随空闲超时释放

## 目的

验证占用成员的 score 过期后被 `ZREMRANGEBYSCORE` 回收、会话槽让出：空闲超时的会话不再占槽，新会话可占用该 Key。

## 前置条件

- 同 TC-01 集群配置；
- miniredis 为空。

**模拟方法**（场景说明 §2 已说明）：miniredis 脚本内 `redis.call('TIME')` 不随 `FastForward` 走（返回真实时钟），无法用 `FastForward` 推进脚本内时间；改为测试侧用 `ZADD key <过去毫秒时间戳> <member>` 把占用成员的 score 直接改写为过去时间，植入一个"已过期成员"，效果等价于该成员已经空闲超时。

## 请求构造

同 TC-01（`ak_conc_a`、`ak_conc_b`）。

## 执行步骤

1. 会话 A 发 1 条请求 → 200，记录绑定 Key（记为 `key-X`）；
2. 断言 `conc:cluster_key_conc:key-X` 成员为 `kid-a`；
3. 测试侧对 `conc:cluster_key_conc:key-X` 执行 `ZADD <key> 1 kid-a`（把 score 改为 1，即 1970 年，必已过期）；
4. 会话 B 发 1 条请求；
5. 断言 `conc:cluster_key_conc:key-X` 成员为 `kid-b`（旧成员被脚本回收、新会话入集）。

## 预期结果

- 步骤 4：200，B 绑定 `key-X`（A 的绑定键若仍在，亲和会先让 B 试 `key-Y`；本用例的验证核心是**acquire 脚本回收过期成员并放行**，故只需最终落到"脚本返回 1、ZSet 成员换代"；为消除亲和影响，步骤 3 同时删除 A 的绑定键 `bfe:ai:key_affinity:cluster_key_conc:kid-b` 更严谨——按此执行）；
- `key-X` 的 ZSet 成员最终为 `kid-b`；
- 无 429。

## 清理

测试结束时关闭 BFE、mock 后端与 miniredis。
