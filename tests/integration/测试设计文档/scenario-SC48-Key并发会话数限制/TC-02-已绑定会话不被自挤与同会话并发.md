# TC-02 已绑定会话不被自挤与同会话并发

## 目的

验证占用槽的会话**不会被自己 Key 的并发限制挤走**：同一会话的并发请求全部放行且始终命中自己绑定的 Key（acquire 脚本 ZSCORE 刷新分支）；并发不增加占用计数（ZSet 成员数恒为 1）。

## 前置条件

- 同 TC-01 集群配置；
- miniredis 为空。

## 请求构造

同 TC-01（`ak_conc_a`、`ak_conc_b`）。

## 执行步骤

1. 会话 A 发 1 条请求 → 200，记录绑定 Key（记为 `key-X`）；
2. 会话 A **并发**发 3 条请求（goroutine 同时发出）；
3. 会话 B 发 1 条请求 → 200，记录绑定 Key（应为另一把 `key-Y`）；
4. 读取两把 Key 的占用 ZSet 成员。

## 预期结果

- 步骤 2：3 条请求全部 200，且注入的 Provider Key 均为 `key-X`（`AuthHeaders()` 逐一断言）；
- 步骤 2 全程 `conc:cluster_key_conc:key-X` 的 ZSet 成员只有 `kid-a`（成员数恒 1，同会话并发只计 1）；
- 步骤 3：200，绑定 `key-Y`（≠ `key-X`）；`conc:...:key-Y` 成员为 `kid-b`；
- 无 429、无惩罚键产生。

## 清理

测试结束时关闭 BFE、mock 后端与 miniredis。
