# TC-01 槽满轮换与合成 429

## 目的

验证 `MaxConcurrencyPerKey=1` 且两把 Key 的会话槽都被占用时，新会话（第三会话）不使用任何 Key：返回网关合成 429（`NO_AVAILABLE_KEY`），`Retry-After` 取 `SessionAffinityTTL`（300），且**零新增上游交互**。

## 前置条件

- BFE 启动，`cluster_key_conc` 配 2 把 Key（`key-a`/`key-b`，Weight 50/50）、`MaxConcurrencyPerKey=1`、`SessionAffinity=true`、`SessionAffinityTTL=300`；
- miniredis 为空；
- 默认路由规则无 fallbacks。

## 请求构造

| 字段 | 值 |
|------|-----|
| Method | POST |
| Host | `key-conc.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_conc_a`（随后 `ak_conc_b`、`ak_conc_c`）、`Content-Type: application/json` |
| Body | `{"model":"gpt-4"}` |

后端对任意请求返回 200。

## 执行步骤

1. 会话 A（`ak_conc_a`）发 1 条请求 → 200，记录其绑定 Key（`AuthHeaders()`）；
2. 会话 B（`ak_conc_b`）发 1 条请求 → 200，记录其绑定 Key（应与 A 不同；若亲和随机到同一把，重试该步直到占满两把，最多 5 次）；
3. 记录此时后端 `Hits()` 计数（记为 H0）；
4. 断言 ZSet：`bfe:ai:key_affinity:conc:cluster_key_conc:key-a` 与 `:key-b` 各有 1 个成员（`kid-a`、`kid-b` 各居其一）；
5. 会话 C（`ak_conc_c`）发 1 条请求。

## 预期结果

- 步骤 1、2：200，A、B 分别绑定不同 Key；
- 步骤 5：**HTTP 429**，`error.code = NO_AVAILABLE_KEY`，`error.type = rate_limit_error`；
- `Retry-After: 300`，`error.details.retry_after_seconds = 300`；
- 响应带 `X-Bfe-Gw-Error: 1`；
- 后端 `Hits()` 等于 H0（第三会话零上游交互）；
- A、B 的占用 ZSet 成员不变；会话 C **无绑定键**（`bfe:ai:key_affinity:cluster_key_conc:kid-c` 不存在）。

## 清理

测试结束时关闭 BFE、mock 后端与 miniredis（`testEnv.Close()`）。
