# TC-03 失败解绑即时让槽

## 目的

验证失败轮换路径（401）会**即时 ZREM 会话槽**（不等 TTL）：会话 A 因绑定 Key 401 轮换到另一把 Key 后，原 Key 的占用槽立即释放，新会话 C 可马上占用原 Key。

## 前置条件

- 同 TC-01 集群配置；
- miniredis 为空；
- mock 后端支持按注入的 Provider Key 区分响应：对 `sk-key-a` 返回 401，其余返回 200。

## 请求构造

同 TC-01（`ak_conc_a`、`ak_conc_c`）。

## 执行步骤

1. 会话 A 发 1 条请求：首选 Key 加权随机；为使断言确定，重试（清空 Redis）直到 A 绑定 `key-a`（对 `sk-key-a` 返回 401 → 轮换 `key-b` 成功 200，单请求内完成）；
2. 断言：`conc:cluster_key_conc:key-a` 无成员（401 解绑即时 ZREM）；`key-b` 成员为 `kid-a`；绑定键 `...:cluster_key_conc:kid-a` = `key-b`；存在 `key-a` 的惩罚键（401 惩罚照旧写入，与本特性无关）；
3. 会话 C（`ak_conc_c`）发 1 条请求；
4. 断言 `conc:cluster_key_conc:key-a` 成员为 `kid-c`（即时获得刚释放的槽）；
5. 会话 A 再发 1 条请求。

## 预期结果

- 步骤 1：200（首试 `key-a` 401 → 轮换 `key-b` 成功），后端 Hits=2；
- 步骤 3：200，C 绑定 `key-a`（唯一空槽）；
- 步骤 5：**HTTP 429** `NO_AVAILABLE_KEY`（A 绑定的 `key-b` 被自己占用放行，但 C 已占 `key-a`——为验证"A 不被自挤"，此步亦可改为并发子用例：A 并发 2 条均 200 命中 `key-b`）；
- 全程无 5xx。

## 清理

测试结束时关闭 BFE、mock 后端与 miniredis。
