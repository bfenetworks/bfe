# TC-04 非法模式与非法条件启动失败

## 用例编号与名称

TC-04 非法模式与非法条件启动失败

## 所属场景

SC42 expr 条件引擎三模式

## 版本声明

- `bfe`：当前源码版本（含 `bfe_config/bfe_conf/conf_basic.go` 的
  `checkConditionEngineMode` 启动校验、`bfe_basic/condition/build.go` 的
  ExprOnly/ExprCompatible 编译失败不回退语义、`bfe_expr` 编译期类型检查）

## 测试目的

验证三类非法配置均 **fail-fast**（BFE 启动失败，而非带病运行）：

- (a) `ConditionEngineMode` 为非法值（如 `Bogus`）→ 配置加载阶段报错退出；
- (b) ExprOnly 模式下路由条件使用旧原语 → 旧原语名即未知函数，编译失败，路由表加载报错退出；
- (c) ExprOnly 模式下表达式类型错误（`ReqMethod()` 返回 string，`string && true` 不通过
  编译期类型检查）→ 编译失败，路由表加载报错退出。

(b)(c) 同时反向锁定 **不回退语义**：ExprOnly/ExprCompatible 编译失败绝不像 LegacyFirst
那样静默回退旧引擎。

三个子用例各启动一个 BFE 实例，均预期启动失败。

## 运行模式

单组件模式：仅启动真实 `bfe` 进程（三个子用例各一个实例，均预期启动失败）。

## 前置条件

1. 已编译 `bfe` 可执行文件。
2. mock 后端已启动：`cluster_expr_hit` / `cluster_expr_default`（子用例 (a)(b)(c) 的 BFE
   均未完成启动，不应收到任何请求）。

## 配置构造

| 子用例 | `bfe.conf` 改写 | `route_rule.data`（`expr_product`）条件 |
|--------|-----------------|------------------------------------------|
| (a) 非法模式值 | `ConditionEngineMode = Bogus` | `default_t()`（条件合法，失败点应在模式校验） |
| (b) ExprOnly + 旧原语 | `ConditionEngineMode = ExprOnly` | `req_path_prefix_in("/api", false)` |
| (c) ExprOnly + 类型错误 | `ConditionEngineMode = ExprOnly` | `ReqMethod() && true` |

## BFE 请求

无业务请求（三个子用例均预期 BFE 启动失败，启动探测超时/进程退出即判定）。

## 预期结果

- (a) BFE 启动失败，进程非零退出或启动探测超时；启动日志含 `ConditionEngineMode`
  相关错误（非法值与合法取值提示）；
- (b) BFE 启动失败；启动日志含路由规则条件原文与 unknown name / 编译错误
  （`req_path_prefix_in` 在 ExprOnly 下不可识别）；
- (c) BFE 启动失败；启动日志含类型检查错误（invalid operation string && bool 语义）；
- 三个子用例的 mock 后端请求计数均为 0。

## 清理

确认 BFE 进程已退出（未退出则杀掉），停止 mock 后端，删除临时目录。
